# AI 炒股投资项目方案：从"模仿 UP"到"学会方法论"的自动化投资分析系统

> **版本**：v2.3（2026-11-02，第五稿）
> **设计依据**：以原《投资学习项目框架》（已归档 `docs/archived/investment-learning-framework-v3.0/`）的**核心模块**为蓝本——该框架定义了一套经过思考验证的投资方法论（双路径、假设清单、信号跟踪、事前验尸、仓位规则、复盘校准），但它靠**人手工执行**。本项目的目标是：**把这套方法论的每个核心模块自动化成一个 AI 子系统**，机器按方法论跑流程、人只做最终决策。
> **免责声明**：系统一切产出仅供研究参考，**不构成任何投资建议**；不接入真实交易接口，不自动下单。

> **v2.1 变更说明**：v2.0 解决了"方法论自动化"，但知识底座仍锚定在单一 UP 主（B站博主青枫浦上Q）身上——`knowledge/claims/` 451 张观点卡、`framework/reasoning-patterns.yaml` 的推理模式、`sources/raw/财经/` 550 篇转写稿几乎全部源自其一人，且评测以 UP 为 ground truth。**UP 断更，则系统失准**。本稿核心变更：
> 1. 新增**引擎⓪ 方法论蒸馏**：把 UP 推理模式提纯为来源中立、经市场验证的方法论（第四节）；
> 2. 新增**产业链知识库**为底座中的底座——UP 思想的核心（涨价链推导）本质是跑在产业链客观结构上的推理，而产业链结构由公告/研报/财报/价格供给，**不依赖 UP 持续输出**（第五节）；
> 3. 新增**盲测对齐与毕业机制**：以市场走势为主判据验证 AI 独立结论，达标后毕业脱离（第十节）；
> 4. **prompt 层拆除 UP 实时锚定**，UP 内容降级为训练教材与事后对照标签（第十一节）；
> 5. 知识底座多源分桶 + 市场结果回写置信度（第十二节）。
>
> v2.0 的四大引擎骨架、输出契约、四条纪律铁律、"宁可没建议不给错建议"的降级原则，**全部保留**。
>
> **v2.2 变更说明**（影子首周实证后修订，详见第十六节）：影子双轨跑通 6 个交易日（2026-08-07~08-14），机制按设计兑现（契约 v2→v5 快速迭代、归因挖出数据缺/步骤缺、factcheck 抓到编造），同时暴露 1 个流程 bug 与若干判据缺陷。本稿不变动骨架，只做六处修订：① 毕业判据修正（阶段一致率降权，方向/标的超额升主判据，分环境段达标）；② 重跑-归因联动闭环（修 bug）；③ qing-agent 对比臂直接复用现有 `daily_review_summary.json`（46 天），不做 qing 盲跑；④ 研报管线定案（akshare 东财研报为主力公开源 + KPL 本地关键词初调 + 人工投递；KPL 无搜索端点、TDX 无资讯能力，已实测排除）；⑤ 分析层 skill 化路线（skill = 方法论 + 查询脚本 + 输出契约，影子/盲测继续用确定性整包）；⑥ M1/M2/M3 遗留事项按"立即可做 / 等数据 / 等毕业"重排。

## 一、问题诊断：为什么 v2.0 会"UP 断更即失准"

| # | 缺陷 | 证据 |
|---|---|---|
| 1 | **单点依赖**：知识底座几乎全部源自 UP 一人 | 451 张 claims 逐字摘自其 B 站内容；`reasoning-patterns.yaml` 每条模式的 source_raw 均为 UP；研报仅 2 篇 |
| 2 | **评测错配**：只评"像不像 UP"，不评"对不对" | `scripts/evaluate_agent_vs_up.py` 以 UP 为 ground truth；claims 的 confidence 由 LLM 按语言强度设定，无市场背书；evals 自述"不追求预测涨跌" |
| 3 | **推理风格固化**：prompt 要求模仿 UP 思考 | `market_analyst.txt`："推理模式…这是你思考的方式，不是可选工具""你应该模仿这个逻辑框架"；`direction_signals`/`up_sentiment` 实时锚定 UP 情绪；冲突裁决"UP 优先" |
| 4 | **产业分析没底座化**：UP 思想的核心反而是仓库里最散的资产 | 产业链研究散落在 `docs/标的深度研究/` 的一次性快照里（写完不更新），没结构化、没和推理引擎挂钩、没有事件驱动维护；`sector-diffusion-framework.md` 的 BOM 拆解没有可调用的产业链数据支撑 |

**关键洞察**：UP 炒股思想的核心是**产业链推导**——涨价链（AI需求爆发 → 产能向高端倾斜 → 高壁垒供给刚性 → 全品类涨价轮动）是从产业链结构推出来的，不是盘感。而产业链结构（环节分层、价值量分布、壁垒、格局、传导路径）是**客观、缓变、可从公开数据独立维护的知识**——这恰恰是"脱离 UP"最硬的底座：UP 断不断更，长鑫的扩产招标、雅克科技的前驱体份额、CMP 设备的国产唯一性都在那里。把底座从"UP 说了什么"换成"产业链客观上是什么样"，方法层的推理才有独立运行的地基。

## 二、认识论基础：UP 内容三层拆解

UP 的内容不是铁板一块，三层价值命运完全不同：

| 层 | 例子 | 性质 | v2.1 处置 |
|---|---|---|---|
| **观点层** | "明天看好燃气轮机" | 会过期，不是知识 | 只作对照标签，不入知识底座 |
| **方法层** | 涨价链五步拆解、BOM 扩散筛选、冰点/炸板率情绪判断 | 可蒸馏的启发式 | 提纯为来源中立方法论，**必须经市场验证才可信**（引擎⓪） |
| **信息层** | 渠道调研、产业链人脉消息、盘面嗅觉 | AI 物理上没有此渠道 | 用公开数据（板块资金、价格、公告、研报、招标）近似替代；替代不了的**诚实标注能力边界** |

**"彻底脱离"的诚实定义**：方法论可复制的结论类型（产业链推导、信号识别、情绪阶段判断、标的分层）达到可验证的命中率；信息优势型结论（依赖非公开渠道的判断）不承诺复制，产出中显式标注"此结论类型存在信息层差距"。系统不假装复制 UP 的信息优势。

## 三、设计思想与总体架构

**设计思想**：方法论不变，执行者换人——且方法论本身也要先经市场验证才配被执行。v2.0 的"人 + 检查清单 → AI 引擎 + 同一张检查清单"不变；v2.1 增加一条：**检查清单里的每条推理模式必须带 validation 区块（历史命中率/适用环境/已知失效场景），未通过验证的模式不得进入 prompt**。

```
                        ┌─────────────────────────────────────┐
                        │  调度层：盘前 / 盘中7时点 / 收盘      │
                        └───────────────┬─────────────────────┘
                                        ▼
┌──────────┐   ┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ 双路径引擎 │→ │ ① 产业逻辑引擎     │→ │ ② 信号与情绪引擎   │→ │ ③ 执行与复盘引擎   │
│ (路径分流) │   │ (路径A研究自动化)  │   │ (跟踪+验尸自动化)  │   │ (计划+纪律+校准)   │
└──────────┘   └──────────────────┘   └──────────────────┘   └────────┬─────────┘
       │ 每个标的/建议             │ 假设清单                │ 信号触发        │ 建议报告
       │ 先定路径                 │ (数值置信度)             │ +验尸结果       │ +交易日志
       ▼                        ▼                        ▼              ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ 引擎⓪ 方法论蒸馏：推理模式提纯(来源中立) + 历史回测 + validation 区块        │
├──────────────────────────────────────────────────────────────────────────┤
│ 知识底座（三层）：                                                          │
│  · 产业链知识库（底座中的底座：环节/价值量/壁垒/格局/传导链/标的映射）        │
│  · 方法论库（蒸馏后、带验证记录的推理模式 + UP术语词典）                     │
│  · 观点对照库（claims 分桶：up教材/agent自产/research/announcement/data）   │
│ 数据底座：东财→新浪→缓存降级链 · K线SQLite缓存 · akshare财报 · 市场情绪      │
```

关键事实（沿用 v2.0）：四大引擎所需的底层能力在本仓库均已存在并每日跑通——Qing-Agent 的 9 节点 LangGraph 工作流已有知识检索、市场分析、个股分析、魔鬼代言人、引用校验、复核节点；监控规则引擎已在做信号触发与去重。本项目是把它们按四大模块重组为统一系统，只新建编排层与各模块缺失的薄功能。

## 四、引擎⓪：方法论蒸馏引擎（新增，最高优先级）

**目标**：把 UP 的推理方法从"UP 个人表达"中分离出来，变成来源中立、数据驱动、可验证、可证伪的方法论资产。

### 4.1 推理模式提纯（改写 `framework/reasoning-patterns.yaml`）

现有 10 个通用框架（116 个单 raw 模式聚合而来）每条含 `UP_logic` 字段，逐条改写为来源中立结构：

```yaml
- pattern_id: bom-diffusion          # 例：BOM拆解扩散
  trigger:                           # 触发条件：客观数据特征，不再引用"UP说"
    - 主线核心资产进入高位轮动（核心标的涨幅/换手达阈值）
    - 下一代系统级产品 BOM 可拆解
  data_requirements:                 # 每步所需数据及获取通道
    - 环节价值量 ← 研报/产业链知识库
    - 供给壁垒与涨价能力 ← 公告/认证状态/涨价函
    - 位置（相对已涨核心） ← K线缓存
    - 订单/客户验证 ← 公告/财报/互动平台
  steps: [拆BOM → 比价值量增幅 → 筛供给壁垒 → 比位置 → 要订单验证 → 标的四层分层]
  falsification: [核心环节破位且资金离开主线, 订单验证连续落空]
  validation:                        # 市场验证记录，未填不得进 prompt
    historical_hit_rate: null        # 历史回测命中率
    applicable_regime: null          # 适用市场环境
    known_failures: []               # 已知失效场景
```

### 4.2 历史回测（补上缺失的 backtest 基建）

- 用 K 线 SQLite 缓存 + 550 篇 raw（作当时信息环境的语料）+ 451 张 claims 回放验证 10 个框架：在历史交易日只喂当天可得数据，跑推理模式，对照后续市场走势计命中率，填入 validation 区块；
- `docs/tasks/buy-signal-implementation.md` 引用的 `scripts/backtest_buy_signals.py` **并不存在**——回测基建是 M0 的新建项，不是复用项，如实估算工作量。

### 4.3 UP 概念体系解耦为术语词典

冰点、炸板率、缩容炒作、高低切等概念保留为**术语词典**（每个词给出客观数据定义，如"炸板率 = 当日炸板家数/触及涨停家数"），与方法论骨架解耦——概念是描述市场的语言，谁都能用；方法论是推理步骤，必须验证。

## 五、产业链知识库：底座中的底座（新增专节）

**定位**：UP 的涨价链推导本质是跑在产业链客观结构上的查询。把这个结构建成独立维护的知识库，AI 就能脱离 UP 自己做产业推导——这是本方案"脱离 UP"最核心的资产建设。

### 5.1 Schema（以仓库已有深度研究为模板）

`docs/标的深度研究/方向一：长鑫存储产业链全景梳理` 的结构已验证有效，固化为标准 schema。每条产业链一个条目，存放于 `knowledge/industry-chains/<chain-id>/`：

- **`chain.yaml`（机读）**：
  - `thesis`：一句话传导链（如"长鑫IPO融资扩产 → 资本开支扩大 → 设备/材料采购增加 → 封测配套需求提升"）；
  - `segments[]`：环节分层，每环节含 `name / value_share（价值量） / barrier（壁垒） / landscape（格局） / growth（增速） / status（当前状态：扩产中/涨价中/认证突破…）`；
  - `mappings[]`：标的映射，含 `code / name / segment / relation（与链主关系） / cert_status（认证/供货状态） / order_evidence（订单证据+来源+日期） / elasticity（核心受益/弹性/概念，及理由）`；
  - `last_verified`：各字段最近核实日期（产业链知识缓变但会过期，必须有保鲜期）。
- **`research.md`（人读）**：沿用现有深度报告格式（分赛道详表 + 投资要点 + 核心/弹性总结）。

### 5.2 数据源：客观信息供给，不由 UP 供给

| 数据 | 通道 |
|---|---|
| 公告/招标/扩产/参股关系 | 事件管线（`qing-event-pipeline`）、交易所公告采集 |
| 财报/营收/关联采购额 | akshare 财报 cron（`fetch_financial_reports_cron.py`） |
| 研报（环节价值量/壁垒/格局判断） | **研报管线扩容——当前全仓库仅 2 篇，是必须补的短板** |
| 价格/涨价函/现货价 | 监控规则引擎 + 事件管线 |
| 认证/供货状态 | 公告、互动平台问答、招股书 |

UP 对产业链的解读（如"存储是下一阶段弹性所在"）降级为**该库的一个推理模式的输出样例**，用来对照，不用来供给事实。

### 5.3 事件驱动维护（治"一次性快照"病）

当前 `docs/标的深度研究/` 的文档写完就不再更新。v2.1 改为事件管线驱动：

- 触发事件：涨价函、招标公告、扩产公告、业绩预告、认证突破、链主 IPO/再融资进展；
- 动作：更新 `chain.yaml` 对应环节 `status` 与标的 `order_evidence`/`cert_status`，刷新 `last_verified`；传导链状态变化（如"设备采购启动"）→ 自动触发对下游环节的重推导，产出进入引擎②的信号跟踪表；
- `last_verified` 超阈值的字段在报告中自动标注"待核实"，防止拿过期产业链知识当事实。

### 5.4 与推理引擎的关系

方法论库里所有产业链类模式（BOM 扩散、涨价传导五步、标的分层）的 `data_requirements` 直接指向本库——**模式提供推理步骤，知识库提供事实**，二者分离后各自可独立验证、独立更新。引擎① 的产业链拆解产出也回写本库，越用越厚。

### 5.5 数据获取与维护分工：AI 自动做什么，人做什么

| 字段类型 | 例子 | 获取方式 | 自动化程度 |
|---|---|---|---|
| 事实层 | 公告、招标、参股关系、财报、关联采购额、价格 | 事件管线 + 财报 cron + 行情降级链（仓库已有通道） | **AI 全自动** |
| 现货价/涨价函 | 存储现货价、封装涨价函 | 公开价格网站（生意社等）+ 公告/新闻采集 | AI 自动为主，部分源需人工确认 |
| 分析层 | 环节价值量、壁垒、格局、增速判断 | AI 从公开研报/券商摘要/招股书抽取，标注来源 | **AI 初稿 + 人工抽检**（研报管线扩容后自动比例提高） |
| 认证/订单核实 | "已供货"状态、订单证据 | AI 从公告/互动平台问答（互动易/e互动）抽取，附来源链接 | AI 抽取 + 关键字段人工确认 |
| 信息层 | 渠道调研、产业链人脉消息 | **AI 物理上没有此渠道** | 不参与；或用户手动填入，标注"人工信息源" |

- **冷启动**：存量 3 篇深度研究（已经人工验证）直接迁移为首批 `chain.yaml`；新增产业链走"AI 初稿 → 人工确认关键字段 → 入库"，跑顺后逐步提高自动比例；
- 用户手动填入的信息（如自有产业渠道）作为 `manual` 来源进 `mappings`，与 AI 抽取字段区分标注，同样受保鲜期管理。

## 六、双路径引擎：每笔建议先定路径

原框架铁律："同一标的必须事先选定路径 A 或路径 B，不能中途切换理由。"自动化设计：

- **路径判定**：每个进入观察池的标的带 `path` 字段（A/B），写入 `config/stock_monitor/watchlist.yaml`；AI 生成建议时必须声明路径，报告模板按路径分栏；
- **路径 A 建议**：只能引用基本面证据（订单、价格、产能、财报、产业链验证——v2.1 起优先取自产业链知识库）；失效条件必须对应假设证伪；
- **路径 B 建议**：只能引用情绪/趋势证据（成交额占比、换手率、舆论、估值分位）；失效条件必须是趋势破坏（止损价）；
- **混用检测（自动校验节点）**：复用 Qing-Agent 的 reviewer 节点加一条校验规则——若路径 A 建议里出现"情绪还在所以持有"类表述，或路径 B 建议里出现"基本面好所以长持"，判违规、退回重写。这对应原框架复盘表里的"路径纪律"一栏，从人工自查变成机器强制。

## 七、引擎①②③（骨架与纪律不变，接口按 v2.1 调整）

### 7.1 引擎①：产业逻辑引擎（模块一自动化）

**目标**：输入一个产业主题或标的，自动产出产业链拆解 + 结构化假设清单。

**产业链拆解**：
- 拆解脚手架从"UP 的推理链"换成**蒸馏后带 validation 的方法论模式**（第四节），事实取自产业链知识库（第五节）；`docs/标的深度研究/` 存量报告作为输出范例并迁移入库；
- 输出：上中下游分层、各环节价值分配/壁垒/格局、核心事件的"直接受益/间接受益/情绪映射/受损"四类标的映射，产出回写产业链知识库（5.4）。

**信息分级（自动标注）**：
- 按原框架三级标准给每条输入信息自动打级：一级（公告/财报/交易所）、二级（研报/协会）、三级（社媒/传闻）；
- 硬约束（原框架规则不变）：**任何假设至少 1 条一级 + 1 条二级信息支撑**，否则不进入假设清单。数据源降级链（东财→新浪→缓存→报错）保证一级信息的诚实性：没数据就报"数据缺失"，禁止 AI 编造；
- 现状短板：全仓库研报仅 2 篇，二级信息供给不足，该约束在知识层落空——研报管线扩容（M3）是前置任务。

**假设清单（自动生成，对接 claim 卡）**：
- 输出格式沿用原框架字段：**假设内容 / 判断依据 / 验证信号 / 信息等级 / 数值置信度(%) / 基准率 / 兑现时间窗 / 证伪后处理**；
- 置信度不是拍脑袋：AI 必须先在 `knowledge/cases/` 案例库检索历史类似案例（基准率），再给出数值；
- 直接写成 `knowledge/claims/` 的 claim 卡格式（statement/evidence/confidence/status/supersedes 天然同构），进入 Neo4j 观点演化图——**假设从此可检索、可追溯、可证伪**。

### 7.2 引擎②：信号与情绪引擎（模块二自动化）

**目标**：假设清单里的每条验证信号变成机器盯的指标；路径 B 的四指标自动计算；事前验尸自动执行。

**路径 A：基本面信号跟踪**：
- 把假设清单的验证信号（招标公告、价格库存、业绩预告、政策事件、产业链互证）映射到现有采集通道：监控规则引擎（`monitor/rules/`）盯价格/区间类信号，财报 cron（`fetch_financial_reports_cron.py`）盯业绩信号，事件管线（`qing-event-pipeline`）盯公告/政策类信号；v2.1 新增信号源：产业链知识库的事件驱动更新（5.3）；
- 信号触发 → 自动更新对应 claim 的状态与置信度（支持→上调、反对→下调）；**置信度跌破 40% 自动判假设失效**，按"证伪后处理"字段执行并通知——原框架"纠偏判断流程"的自动版。

**路径 B：情绪四指标（自动计算）**：
- 板块成交额占比、龙头股换手率、舆论密度、相对估值分位，全部由现有数据源计算（东财行情 + 板块数据 + 情绪采集 `market_sentiment`）；冰点、炸板率等术语按术语词典的客观定义（4.3）计算；
- 判定"升温/过热/退潮/冰点"时调用 `methodology/market-cycle.md` 与 `framework/market-cycle-framework.md` 的状态定义，避免 AI 自由发挥；量能真假用 `framework/volume-quality-assessment.md` 的三步法交叉验证。

**事前验尸（自动化 Devil's Advocate）**：
- Qing-Agent 已有 devils_advocate 节点，把原框架 pre-mortem 流程固化为输出契约：对每笔建议**必须输出"假设 6 个月后失败的 3 个具体死因"**，且每个死因回推一个"现在可观察的先行指标"并入路径 A 跟踪表；
- 原框架的 5 个反证问题（是否已 price-in、是否只听利好、空仓还会买吗等）作为该节点固定检查清单注入 prompt。

### 7.3 引擎③：执行与复盘引擎（模块三自动化）

**目标**：交易计划自动生成、仓位纪律机器强制、日志与复盘全自动、校准按季自动跑。

**交易前路径匹配检查（自动门禁）**：
- 原框架五问表变成建议报告强制字段：买入理由 / 持有周期 / 证伪信号 / 退出条件 / 最大亏损，缺一不出报告；
- "答案介于两条路径之间 → 不做"——reviewer 节点判不定路径时直接输出"回避"。

**仓位规则引擎（纪律硬编码）**：
- 原框架公式不变，机器强制换算：**仓位% = 单笔风险上限% ÷ 止损幅度%**，再套三层上限（个股 ≤10%、单主题 ≤20%、路径 B 合计 ≤30%）取最小值，实际风险重算确认 ≤2%；
- 每条建议在报告里必须同时出现**仓位/止损/单笔风险三个数值**，缺一被校验节点打回；
- 组合熔断：月回撤 ≥10% 自动触发"强制减半"建议——从人的自觉变成系统规则（持仓数据来自 `positions.yaml`，本地私有、不进 git）。

**交易日志与复盘（自动记录、过程/结果分离）**：
- 日志：每笔建议落盘即留档（标的/路径/三数值/对应假设/市场周期位置/数据时间戳），无需人记；
- 复盘：收盘后自动跑（现有 daily-review 通道），按原框架原则**过程评分与结果评分分离**——过程分评"当时信息下流程是否合格"，防止用结果反推决策质量（resulting 偏误）；
- 错误自动分类六型（逻辑/数据/执行/心理/路径/**运气**），"过程合格但亏损"自动归"运气"，防止 AI 因一次坏运气乱改方法论。

**季度校准（自动统计）**：
- 按季度统计所有已到时间窗的假设——"AI 说 70% 的事实际兑现几成"，按置信度分桶输出命中率偏差表；偏差超 10 个百分点 → 自动给下季度 AI 输出的置信度打 9 折（prompt 层注入校准系数）；
- v2.1 升级：从"校准 AI 置信度"扩展为"分桶校准各信息源"（up/agent/research/announcement/data 各桶分别统计，见第十二节）。

## 九、输出契约（v2.0 不变，新增一条）

- 每条建议五要素：标的+方向 / 触发条件 / 失效条件 / 依据与证据分级（证据 vs 推断）/ 数据时间戳；

## 十、市场验证与持续可靠性机制（v2.3 重构）

**目标**：青枫浦上Q停止新增输入后，Qing-Agent 以既有多专家架构独立运行；每天用市场结果检验其真实输出，以持续证据表达可靠性，而不是等待一次毕业后再开始独立运行。

**多专家边界**：退出的是 qing 的新增实时输入，不是全部专家。gator 的采集、patterns、确定性规则快照和冲突卡继续参与分析；每日留痕必须同时保存各专家视角与最终合成判断，学派归属和平权分歧规则不变。

### 10.1 历史回放测试集

选 N 个历史交易日（覆盖上涨/震荡/下跌、主线清晰/混沌等不同环境），只喂当天可得的客观数据（K线、板块资金、公告、当时已有的产业链知识库快照），AI 独立输出市场阶段/方向/标的判断。**被测日期之后的专家观点不得进入 prompt。** 历史回放只提供基线，不替代每日新增样本验证。

### 10.2 市场结算与历史基线

- **主判据：vs 市场后续走势**——最终合成判断中的方向与标的在约定期限内相对沪深300的表现、假设是否被证伪、失效条件是否执行；过程合规与结果表现分开记录。
- **专家分项须有独立输出**——只有专家视角明确给出方向/标的和期限时才单独计分，不用最终结果倒算专家命中率。
- **阶段一致率只作参考**——机械真值与模型读取同源指数数据，不单独作为预测力证据。
- **青枫浦上Q只作历史基线**——既有 qing 结论和命中率用于教材筛选与历史对照；没有新增 qing 动态不影响每日验证，也不再要求双方当日差异对照。

### 10.3 Qing-Agent 每日验证期

每日流程：Qing-Agent 盘前/盘中/收盘分轨冻结各专家视角和最终合成判断（含生成时间、数据时点、判断期限、school 与证据引用）→ 到期后市场结算 → 错因归因。收盘后的当日解释不得冒充事前预测，已冻结判断不得用后见结果覆盖。归因分四型：

| 归因类型 | 含义 | 处置 |
|---|---|---|
| 数据缺 | 推理所需数据没有采集通道 | 补数据通道 |
| 步骤缺 | 方法论缺环节 | 回写引擎⓪ 补模式 |
| 概念误用 | 术语/框架用错场景或学派归属混淆 | 修订术语词典/prompt |
| 信息差 | 当前公开数据通道无法覆盖所需信息 | 标注能力边界，不强求 |

shadow 可继续作为历史或实验对照臂，但每日可靠性验证的对象是 Qing-Agent 本身。市场结算不自动裁决 standing 学派冲突。完整留痕与异常口径见 `docs/superpowers/specs/2026-11-02-m4-independent-operation-design.md`。

### 10.4 滚动可靠性观察（不再作为 M4 启动门槛）

- 每日检查留痕完整性、事实与学派归属错误、数据缺失和结算状态；
- 每周汇总滚动 4 周/8 周的方向与标的 5 日超额、假设证伪率、样本数及分环境分布；最终合成与可独立结算的专家视角分开报告；
- 原阶段一致率 70%、方向超额 60%、路径 A 假设证伪率不高于历史基准 +10pct 等阈值保留为观察与告警参考；
- 样本不足输出 `insufficient_data`，429、缺失和未到期不得计为命中；
- **M4 自 2026-11-02 启动，是否继续独立运行不再由旧式 `graduated` 决定；可靠性是否提升由后续每日样本回答。**

## 十二、知识底座重构：多源 + AI 自产 + 市场回写

- **claims 按 source 分桶**：`up`（教材，只用于训练与对照）/ `agent`（AI 自产）/ `research`（研报）/ `announcement`（公告）/ `data`（量价数据回写）；各桶权重**由该类历史命中率决定**，不再按"语言强度"设置信度；

### 16.1 修订一：毕业判据修正——阶段一致率降权，超额收益升主判据

**问题（实证）**：首周阶段判定 6/6 全对，但证据效力弱——① 本周真值全是"震荡"，单类别周，永远猜震荡也是满分；② 阶段真值是机械规则（`blindtest/truth.py`：r20/pos20/vol_trend），模型数据包里的指数 K 线与真值同源，`stage_hit` 本质是"模型与规则读同一份数的一致性"，有循环论证成分，不能当预测力证据。原第十节毕业标准把"阶段一致率 ≥70%"列为首条，会被震荡市刷高。

**方案**：
- 毕业判决主判据改为**无循环的两条**：方向 5 日超额命中率 ≥60%（维持原标准）、标的 5 日超额命中率 ≥55%（对齐 M1 基线 56.6% 设门槛）；
- 阶段一致率降级为**参考项**，报告中必须标注"与机械真值的一致性检查，非预测力证据"；
- 主判据加**分环境段约束**：按真值标签分段统计，每段（主升/震荡/调整/恐慌）样本 <10 该段不计入；窗口内环境单一（如纯震荡）→ 维持 `insufficient_data`，不毕业。此约束写进 `shadow/graduation.py` 聚合逻辑；
- 原判据"路径 A 假设证伪率"维持 pending-definition（待 M3 分桶，见 16.6）。

**验收**：`graduation_check.py` 输出含分环境段明细与单环境警示；毕业/未毕业判决只由超额两条决定。
