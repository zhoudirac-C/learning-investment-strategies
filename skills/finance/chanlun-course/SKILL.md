## 核心框架（先看这个）

1. **两级别分工**：日线级别定**仓位性质**（反弹仓 vs 反转仓），60min 级别定**入场时机**。日线无底背驰 → 这波上涨只是次级别（60/90min）反弹，不是日线反转——这是最容易被误判的一条。
   - **30min 是用户实际用的更细入场/中枢级别（2026-08-27 确认）**：用户要求"最新 60分图和 30分图"同时给。30min 中枢/买点比 60min 更敏感，用于定位更精确的回踩/突破点。同一标的 60m 位置（如"中枢内"）与 30m（如"中枢上方"）可能不同——以 60m 作主判断（结构定性）、30m 辅助定精细入场点，两级别都画（`chan_analysis.py --30m/--60m` + `chan_plot.py`）。
2. **三类买点唯一**（claim-20070109-001-a 买卖点完备性定理）：一买=趋势背驰点，二买=一买后回调不创新低，三买=突破中枢后回踩不回中枢。**中枢内没有该级别买卖点，只有低级别买卖点**（claim-20070523-001-a）。
3. **背驰必造买卖点**（claim-20070118-001-b）：背驰后回跌至少回到原中枢；背驰有级别问题——1min 背驰绝大多数不会制造周线大顶。
4. **大级别二买 = 次级别一买**（claim-20061205-001-a 买点定律）：日线二买要找 60/90min 的一买确认。
5. **验证纪律**：不给无条件买卖指令；每标给出 防守线（最近底背驰低点）/ 反转确认位（前高突破回踩不破）/ 目标位（前高）/ 失效条件（破防守线）。

## 输出惯例（用户偏好：precision）

- **防守线** = 最近底背驰低点（如 2026-08-14：科创50 1690.67 / 上证 3903.70）：不破则 60min 一买成立，破则一买失败、回调加深
- **反转确认位** = 前高（如 8/13 顶）放量突破并回踩不破 → 中枢上移/三买雏形，升级为反转仓
- **仓位性质标签**：反弹仓（60min 级别，到前高减半兑现）vs 反转仓（日线级别，回踩可加）——UP claim-20260731-019 口径："止跌仓位与反转仓位差别不在买点，而在反弹之后是加还是减"
- **中阴/待定标签（L88/89 中阴阶段，2026-08-29 沉淀）**：走势类型死亡后、新走势类型确立前的**模糊期**（前一走势的背驰/盘整背驰宣告其死，到新走势确立之间），一律标记 `中阴/待定`，不强行套反弹仓或反转仓。判定要点：
  1. **必先出现大一级别中枢**（课89 原理：中阴阶段的震荡必然围绕某级别的中枢进行，出现大级别中枢是 100% 准确的底部/顶部依据）——未出现前定性保持"待定"
  2. **健康性检查**：健康的更大级别中枢震荡**至少落在前走势最后一个中枢范围内**；一旦回到第二甚至更后中枢 → 中阴状态不健康，降级处理
  3. 操作含义：中阴阶段**不新增仓位**，等大级别中枢出现后再定性（反弹仓/反转仓）
- **失效条件**：破防守线 → 停止买入并止损；破更大级别前低（如 8/3 底）→ 反弹彻底终结，退出等新结构
- 所有价格给具体数值区间（用户要求"回踩73-76区间"式精度，不给"等回踩"）
- **T+1 兑现纪律（用户 8/17 纠正过）**：ETF/股票当天买入次日才能卖——"反弹到前高减半兑现"一律指**次日**减半，绝不写"当天冲高减半"；当天买入的仓位=锁仓，破防守线最早次日开盘止损 → 买入价距防守线必须留 ≥1.5% 缓冲，当天只挂回踩价不追现价。**老仓（前日买入）是唯一当天可兑现的仓位**：反弹脉冲日（如设备 ETF 单日 +4%）逢高卖老仓是当天兑现窗口

## 与 UP / investment-structure-recognition 交叉验证

- 缠论"日线未反转" ≈ UP"反弹能否转反转未确认"——两框架同结论时可信度高
- 案例（2026-08）：科创50 日线无底背驰（8/3 底 1549.74 只是 60/90min 结构）→ 缠论判定反弹仓；UP 8/16 同样犹豫"反弹转反转关键"。两框架互证
- 背驰分**盘整背驰**（中枢内出现，级别低，反弹幅度理论上限=中枢区间）vs **趋势背驰**（中枢外，标准一买）——报告必须标注背驰类型，防止把盘整背驰当反转信号
- **背驰前提字段（输出契约强制，2026-08-29）**：报告输出背驰类型时**必须同时输出前提结论**（`premise` 字段，G3 校验显式化）——trend_div → "前提满足：存在同级别同向不重叠前中枢"；consolidation_div → "前提不满足：无同级别前中枢（仅盘整背驰）"。实现：`src/chan_engine/core/backchi.py:classify_backchi_type`（G3）+ `report/skill_adapter.py:_premise_note`，CLI 渲染 `└ {级别} 背驰前提: ...`。目的：强制检查"没有趋势没有背驰"，盘整背驰不会被误当反转信号
- **小转大判定流程（L44 小背驰-大转折定理，2026-08-29 沉淀）**：当小级别（30m/60m）出现顶/底背驰时，**不直接升级为大级别转折判断**，按两步走：
  1. **必要条件检查**：看该级别走势**最后一个次级别中枢是否出现第三类买卖点**——小级别顶背驰 + 最后次级别中枢出三卖 = 大级别向下的候选（底背驰反之）；**最后次级别中枢未出三类买卖点 = 正常震荡，小级别背驰不传导**
  2. **充分条件缺失**：小级别背驰后能在最后次级别中枢内正常震荡的，**不构成大级别转折**——冲顶赶底阶段尤其警惕（常是主力借小级别背驰洗盘）
  - 输出处置：chan_analysis.py 打印"小转大候选"时，报告必须人工核对第 1 步的三类买卖点是否出现，**不能直接把小级别背驰报成大级别转折信号**（G10 引擎未自动落地，须人工确认）

- **概念追问逐层展开**：用户会连环追问 EMA→MACD面积→笔区间→次级别——按递归链条逐层讲（价格→EMA→DIF→DEA→柱→笔区间切片面积→背驰），并点明 P2均线面积与P4 MACD柱面积同构（快慢线差值的|·|累加），数值不可互换但方向一致

## Pitfalls（都踩过）

1. **python urllib 拉腾讯K线被限流**（UA 不完整 → `data:[]`）：用 subprocess curl + 完整 Windows UA，或 curl 预拉到 `/tmp/klines/{code}.json` 再读文件（批量拉取推荐后者）
2. **数据没更新**：日K接口盘前/早盘拉到的还是上一交易日数据（腾讯实时时间戳 `[30]` 判断）；分析报告必须标数据基准日
3. **字段错位**：qt.gtimg.cn 88 字段索引从 0 起；GBK 必须 `decode("gbk")`，UTF-8 解码直接崩
4. **缠论术语严格性**：按 claims 口径说话——"回调"≠"下跌趋势"，"盘整背驰"≠"一买"（一买只属于趋势背驰），中枢内无该级别买卖点
5. **背驰面积用 MACD 柱面积（|hist|），不是 DIF 面积**；指数与 ETF 的背驰确认常差 0.5-1 天 → 分批建仓：指数信号管大盘、ETF 自身信号管个股
6. **突破反弹目标 ≠ 追入信号**：标的突破反弹目标（前高）后冲高回落是常态（159381 于 8/17 开盘冲 1.245 破目标 1.237 后回落 2.1%，重演 8/13 顶背驰剧本）——突破目标位的标的当天不介入，等回踩目标位上方或次日结构确认；反弹仓纪律是"到目标减半"，不是"破目标买入"
7. **盘中判断必须实时拉数**：竞价结束(9:25-9:30)拉一次对照防守线定挂单 → 开盘后每 20-30 分钟再拉（qt.gtimg.cn 88 字段：现价/最高/最低/量额/时间戳[30]校验基准日）。关键信号：①是否破防守线（撤单）②是否冲高回落（接近中枢上沿/反弹目标时=上方压力验证，改挂回踩价）③量能估算（半日成交×2 vs UP 情形A 2.5万亿，达标才升级第二批）。用户会反复要求"再拉取一下"，结论必须基于最新时点数据，先拉数后下结论
8. **分批挂单两档结构**：现价档 40% + 回踩档 60%（防踏空+防追高）；若盘中已冲高回落（T+1 下当天不能纠错），收紧为只挂回踩档——"宁可少买不可买错，错过比套牢便宜"
9. **挂单价必须当天重算缠论，且逐项标注来源归属**（用户会质询"这些挂仓点是依据缠论分析得出的吗"——沿用昨日锚点=不合格，实测 8/18 被抓出）：
   - 流程：给挂单前先拉**当天**日K+60min（60min 含盘中实时 bar，新浪接口会带上今日进行中的 bar）重跑 chan_analysis.py，再出价；昨日结构已演化（一买→反弹笔进行中，防守线/中枢已上移），直接复用昨日防守线/目标位是错的
   - 输出带归属表：每档挂单标注「缠论锚=哪个中枢/背驰/买卖点；UP锚=哪个 claim；盘口锚=实时涨跌」；**非缠论依据的指令要明说**（如"卖设备=UP 排序+换仓效率，缠论上反弹笔未走完"），不冒充缠论结论
   - **中枢纪律**：中枢下沿=硬防线（破=一买失败，全部撤退），中枢上沿=加仓门槛（放量站上=三买成立）——两者中间的位置既不是防守也不是买点，不能拿来做挂单依据。实测 8/18：给 515980 防守 1.100 偏浅，重算后硬防线=60min 中枢下沿 1.060（8/14 一买低点），1.100 仅降级为"减半观察位"
10. **60min 顶背驰标的的追买挂单降级**：价格创新高但 MACD 柱面积缩小（a2<a1×0.9）= 顶背驰，追买挂单应改为「深回调至中枢中下部 或 放量突破顶背驰高点破坏结构」二选一，二者不满足就放弃。实测 8/18：159819 8/17 高点 1.903 对 8/13 高点 1.891 顶背驰（面积 0.11→0.07），原挂单 1.875-1.882 撤掉，改等 1.84-1.85 或突破 1.903；159381 无顶背驰（双级别中枢上方）保持回踩单 1.245-1.250
11. **项目有现成结构函数，别总手写全套**（用户 8/18 提醒"现成的函数，TDX 可以拉取"）：`src/investment_engine/structure.py::detect_structure(klines, window=5, timeframe='60min')` 现成实现顶/底背离（价新高+DIF 未同步）+ 金叉/死叉确认，timeframe 传 '60min' 返回理论天数；与手写 chan_analysis.py 交叉验证。**但 detect_structure 的 top.state='formed' 有历史结构陷阱**：它是「最近两个 top pivot 背离+死叉」的**最后一次确认**，pivot 需前后 window(5) 根确认——8/17 新高后 8/18 才 1-2 根 bar，新背离无法识别；且返回的 formed 常是上一轮（8/13 顶在 8/13-14 死叉）的历史确认。**报告前必须 dump 最后两个 top pivot 的价格/DIF/死叉时间**（`_find_pivots` + `compute_macd` 直查），区分三态：历史已 formed / 当前钝化中（divergence 未死叉）/ 无背离（DIF 同步新高）。实测 8/18：4 只 ETF 报 formed 全是 8/13 历史，真正"正在钝化"的是上证（8/13 顶背离未死叉）——把历史 formed 报成今天信号是误导
12. **用户偏好 TDX 拉K线（8/18 明确"可以用tdx的接口"）**：`TdxMarket().get_kline(code, 'daily'/'60min', count=...)` 直连稳定，60min 含完整 datetime；chan_analysis.py 内置腾讯日线 URL 有 bug（`day,,{n}` 少一个逗号，正确应为 `day,,,{n}`）→ 对个股直接跑报 `'list' object has no attribute 'keys'`。绕过：手动 curl 正确 URL 存 `/tmp/klines/{code}.json`（日线需包装成腾讯格式 `{"data":{code:{"qfqday":[[date,open,close,high,low,vol]...]}}}`，60min 用新浪格式 `[{"day":..,"open":..,"close":..,"high":..,"low":..,"volume":..}]`）再跑脚本；或 TDX 拉取后转上述缓存格式

13. **个股板块归属必须核实，不能凭名称/直觉归类（用户 8/19 纠正）**：把顺钠股份(000533)当"科技"分析后用户纠正"顺钠是电力不是科技"。教训：①个股归类先查 F10 主营/东财行业，名称含"智能/科技/电子"≠科技板块（顺钠是干式变压器/成套开关设备，属电网设备）②板块归属错了方向判断全错——UP 对科技 vs 防御/高股息的处理完全不同（科技=5成仓等回调承接，电网=高股息防御过渡性题材）③持仓分析前对每只标的标板块归属，不确定就查（东财 suggest 返回名称，或腾讯 f[1]）；用户纠正过的板块归属记住（顺钠 000533=电力设备，不是科技）

14. **尾盘/收盘前操作分析模式（用户"快收盘了帮我分析"场景，8/19 实测）**：14:50-15:00 用户要求尾盘操作分析时，**只拉腾讯实时行情即可，不必重跑缠论脚本**（盘口价=最新，防守线/中枢沿用当日早间 TDX 跑过的结果）；输出格式：**可执行卖出（老仓，T+1 兑现窗口）+ 明日盯防（触发线+动作）+ 持有**三档清单。要点：①明确 T+1——今天买入的锁仓不能卖，尾盘能卖的只有老仓 ②触发线给具体价位（如"0.907 破位止损"）③尾盘拉升触及兑现位（如 588170 +2.5% @1.104 到 1.10 目标）是负成本仓最后的兑现窗口，不纠结等更高 ④"涨的兑现、弱的持有、破位的走"是尾盘版核心逻辑 ⑤收盘后把尾盘清单整理成次日盯防表（防守线不变，明日触发）

**批量持仓缠论分析的标准做法（2026-08-18 验证，10 只一次跑完）**：TDX 批量拉取 → 转缓存格式 → 逐只跑脚本 → 腾讯实时交叉验证。可运行骨架：

```python
import json
from qing_investment.tdx_market.market import TdxMarket
m = TdxMarket()
codes = {'sh588170': '科创半导体ETF华夏', ..., 'sz000533': '顺钠股份'}  # 全部持仓
for code, name in codes.items():
    daily = m.get_kline(code, 'daily', count=300)
    h60   = m.get_kline(code, '60min', count=240)
    tencent_fmt = {'data': {code: {'qfqday': [[r['date'], str(r['open']), str(r['close']),
                  str(r['high']), str(r['low']), str(r['volume'] or 0)] for r in daily]}}}
    json.dump(tencent_fmt, open(f'/tmp/klines/{code}.json','w'))
    sina_fmt = [{'day': r['datetime'] or r['date'], 'open': str(r['open']), 'close': str(r['close']),
                 'high': str(r['high']), 'low': str(r['low']), 'volume': str(r['volume'] or 0)} for r in h60]
    json.dump(sina_fmt, open(f'/tmp/klines/{code}_60m.json','w'))
# 然后逐只：python chan_analysis.py {code}  /  python chan_analysis.py --60m {code}
# 数据新鲜度验证：TDX 60m 最后 bar 收盘 vs qt.gtimg.cn 现价（同分钟级时点应一致）
```

## 批量扫描持仓工作流（2026-08-26 实战验证）

1. 日K预拉：curl 循环写 `/tmp/klines/{code}.json`（间隔 ≥1.6s）；60min 用 sina 接口写 `{code}_60m.json`
2. 逐只 `python3 chan_analysis.py $c` / `--60m $c`，输出 grep 关键行（`最新|位置|最近6笔|背驰|买点`）
3. **坑①**：`/tmp/chan_results.json` 每次运行被覆盖，顶层是 **list 不是 dict**——`.get()` 会 AttributeError
4. **坑②**：9只批量循环输出会被截断——先跑全量看结构，再对被截断标的用 `grep -E "^背驰|^买点" -A2` 补拉
5. 结论必须日线+60min 双级别对照给：60min 常比日线早出新鲜买点（如 8/25 二买），且能区分同类 ETF 强弱（中枢上方>中枢内>中枢下方）
