## 本轮变化

- 窗口扩到 20 个交易日（2026-08-03 ~ 08-28，T+5 全部到期）
- 两臂 pack 均新增 `direction_pool` 块（45 条精选方向，仅 id+打码 name）——
  一轮归因发现池 id 在 pack 中不可见是 v16 方向回归的主因
- v17 = v16 骨架（推理链）+ 引用义务清单化 + 方向硬门槛逐条独立
- 校验层新增 `first_violations` 记录（首版违规可见，归因不再靠猜）

## 归因

1. **方向池归位成功**：direction_pool 进 pack 后两臂均 100% 选池 id
   （v15 从 6/13 → 23/23）。数据通道是主控——prompt 里背 id 表（v15 旧做法）
   只是数据缺失的代偿。此块对生产同为增益，保留。
2. **重试率回归未修复，且主犯不是引用类规则**：规则15 占 v17 首版违规的 74%。
   机制：v15 用规则15+规则20 两处重复强调「守住/跌破当前台阶」，v17 压缩成
   一条 bullet——**压缩删掉的是冗余，而 LLM 对约束的服从度部分来自冗余**。
   另：v17 模型频繁写「25000亿」但不带「确认位」关键词，差一步触发豁免。
3. **同簇限选语义化也变弱**（规则27 首版 6 次 vs 0）：v15 的 C1-C7 显式分簇表
   同时承担着"教模型哪些方向同簇"的职能，语义规则替代不了枚举。
   正确修法仍在数据层：direction_pool 每条带 cluster 字段，prompt 只写
   「同簇最多选1条（簇见 direction_pool.cluster）」。
4. 标的选择是 v17 的亮点（+14pp）：池锚定后标的从池内股票产生，质量更高。

## 裁决

按预登记标准（重试率不明显升高），**v17 仍未通过，生产默认维持 v15**。
但本轮把问题收敛到了两条可修的规则上：

- v18 处方：① 规则15 恢复双处强调 + 在 JSON 契约的 scenarios/watch_next
  字段描述里内联「（量能阈值用相对口径）」（在生成现场拦截）；② direction_pool
  块带 cluster 字段（代码 `_DIRECTION_CLUSTERS` 已有单点数据），prompt 引用之。
- 成本参考：v15 ≈ 28 次调用，v17 ≈ 38 次，重试率平价前压缩版无成本优势。
