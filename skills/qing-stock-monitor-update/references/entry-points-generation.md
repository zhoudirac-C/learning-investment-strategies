# Entry Points 生成规范

> 基于技术分析 + 博主观点 + 市场环境，为 watchlist 中的标的生成具体的介入区间、仓位、触发条件和失效条件。
>
> 这是 strategy_pack.yaml 中最关键的配置，直接影响实际交易决策。

---

## 生成流程

```
Step 1: 获取实时行情 + 历史K线
  └─ 运行 scripts/scan_all_stocks.py 或单独获取
  └─ 记录：现价、今日高低、MA5/10/20、近期高低点、量比

Step 2: 读取博主观点
  └─ 扫描最近 3 天 claims
  └─ 检查博主是否明确提及该标的
  └─ 记录：看好/规避/未提及

Step 3: 技术分析
  └─ 均线系统：多头/空头/缠绕
  └─ 回撤幅度：从近期高点回撤 %
  └─ 量价关系：放量/缩量/正常
  └─ K线形态：长下影/反包/大阳线/大阴线/十字星
  └─ 支撑压力：近期20日高低点

Step 4: 生成介入区间
  └─ 基于技术位置计算合理介入点
  └─ 不是"拍脑袋"，必须有数据支撑

Step 5: 交叉验证
  └─ 与博主观点是否矛盾
  └─ 与 claims 一致性校验

Step 6: 写入 strategy_pack
  └─ entry_points 列表追加
  └─ sector_groups 同步更新
```

## 介入区间计算方法

### 方法1：基于均线（趋势票）

**适用**：均线多头排列，趋势向上的票

```
介入区间 = [MA5 × 0.97, MA5 × 1.00]
或
介入区间 = [MA10 × 0.98, MA10 × 1.01]
```

**示例**：
- 兆易创新：MA5=481, MA10=479 → 介入区间 [470, 480]
- 逻辑：回踩MA5/MA10附近是趋势票的合理买点

### 方法2：基于近期低点（震荡票）

**适用**：均线缠绕，区间震荡的票

```
介入区间 = [近期20日低点 × 0.98, 近期20日低点 × 1.02]
或
介入区间 = [前期平台低点, 前期平台低点 × 1.03]
```

**示例**：
- 浪潮信息：近期低点63.1 → 介入区间 [63, 65]
- 逻辑：接近支撑位时风险收益比最好

### 方法3：基于回撤百分比（高位票）

**适用**：已大涨，需要等充分调整的票

```
介入区间 = [近期高点 × (1 - 回撤率), 近期高点 × (1 - 回撤率 + 0.02)]

回撤率参考：
- 单日大涨 +5~8%：等回撤 5-7%
- 单日大涨 +8~15%：等回撤 8-12%
- 连续大涨 +20%+：等回撤 15-20%
```

**示例**：
- 裕太微：近期高点241，单日+11% → 等回撤10-15% → 介入区间 [205, 215]
- 逻辑：大涨后不追高，等充分调整

### 方法4：基于分时低点（日内回踩）

**适用**：当天有明确分时低点，且低点有支撑的票

```
介入区间 = [今日最低 × 0.99, 今日最低 × 1.03]
```

**示例**：
- 兆易创新：今日最低477 → 介入区间 [475, 480]
- 逻辑：日内低点是短期支撑，回踩至此可试探

## 仓位配置原则

| 条件 | 仓位 |
|------|------|
| 博主明确看好 + 技术信号强 + 主板 | 1.5-2成 |
| 博主明确看好 + 技术信号中等 + 主板 | 1成 |
| 博主未提及 + 技术信号强 + 主板 | 0.5-1成 |
| 博主明确看好 + 技术信号强 + 非主板 | 0.5成（标注不可交易）|
| 高弹性/高风险票（如裕太微） | 0.5成 |
| 防御性板块（煤炭、电力） | 0.5-1成 |

**总仓位控制**：
- 空仓状态：首次建仓总仓位不超过 6成
- 已有持仓：新增仓位不超过 3成
- 满仓状态：只做T，不开新仓

## 触发条件 vs 失效条件

| 类型 | 示例 | 说明 |
|------|------|------|
| **触发条件** | "回踩MA5企稳" "放量突破前高" "板块联动确认" | 满足条件才买入 |
| **失效条件** | "跌破XX且30分钟不能收回" "板块龙头大跌" "放量跌破支撑位" | 满足条件则放弃买入 |

**触发条件必须具体**：
- ❌ "等企稳" → 太模糊
- ✅ "回踩470-480区间，分时不再创新低，放量收回均线" → 具体可执行

**失效条件必须量化**：
- ❌ "趋势走坏" → 太模糊
- ✅ "跌破453且30分钟不能收回" → 具体可执行

## 与博主观点矛盾的处理

| 场景 | 处理 |
|------|------|
| 技术信号强 + 博主明确看好 | 正常配置介入区间 |
| 技术信号强 + 博主明确不介入 | ❌ 配置为"只观察不介入"，position_ratio=0 |
| 技术信号弱 + 博主明确看好 | ⏳ 配置介入区间但标注"等更充分调整" |
| 技术信号弱 + 博主明确不介入 | ❌ 配置为"只观察不介入" |

**示例**：
- MLCC（风华高科/火炬电子）：技术评分+4/+2，但博主明确"现在追涨是韭菜" → 配置为"只观察不介入"

## 无具体价格时的处理

当数据源降级或无法获取实时价格时：

1. **诚实说明**："数据源降级，无法获取实时价格"
2. **提供计算规则**："基于当日收盘价，回踩5-7%介入"
3. **绝不编造虚假价格**
4. **备用方案**：使用腾讯财经 API（curl）获取价格

**示例配置**：
```yaml
- code: sh600160
  name: 巨化股份
  entry_zone: 等分歧回踩（基于当日收盘价，回踩5-7%介入）
  position_ratio: 1成
  trigger: 化工涨价逻辑持续，制冷剂+PFA双催化
  invalidation: 板块龙头大跌或涨价逻辑证伪
  note: 5月31日复盘后未再提具体价格，需盘中确认回踩点位。数据源降级时参考腾讯财经API
```

## 常见错误

1. **给已大涨的票配低位区间**：如裕太微+15%后配"等充分调整"，但区间还是按原价算
2. **给博主明确不介入的票配买入区间**：如MLCC已提前提示，还配介入区间
3. **区间太宽**：如"50-70区间"，20%的区间没有意义
4. **区间太窄**：如"55.0-55.2区间"，很难触及
5. **没有失效条件**：只写"买入"不写"什么情况下不买"
6. **仓位与风险不匹配**：高风险票配2成，低风险票配0.5成
