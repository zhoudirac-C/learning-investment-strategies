# Design Philosophy Correction (2026-06-08)

> 来源：用户对 config+cron 架构 review v1.0 的反馈纠正
> 关联文档：`docs/config-cron-architecture-review.md` v2.1

## 核心纠正

**v1.0 方向错误**：方案倾向于让系统更量化、更规则化（减少 cron 节点、增加量化轮询）。

**用户纠正**：
1. "想让大模型像UP那样，像一个成熟的交易者一样，根据每天的盘面分析，有个操作的思想，而不是死死的量化数据"
2. "现在定时任务基本都是提醒我减仓，但是很少提醒我买入和加仓，特别的保守"
3. "目前的设计是在一些关键时间点，让AI做判断" — 这是正确的设计理念

## 正确的设计方向

| 方向 | ❌ 错误（v1.0） | ✅ 正确（v2.0+） |
|------|----------------|-----------------|
| Cron 节点 | 减少到3个 + 量化轮询 | 保留节点数，每个差异化 prompt |
| 核心目标 | 量化规则增强 | LLM 思维方式重塑——从风控机器人到交易者 |
| 观察池 | 删减/生命周期 | 热度排序，不删票 |
| 持仓操作 | reduce_zone + risk_zone 为主 | 增加 buy_zone / add_zone / 机会模式扫描 |
| LLM 角色 | 风控巡检员 | 职业交易员（赔率思维 + 7大机会模式） |

## 三项关键原则

1. **机会发现 > 风控巡检**：系统默认模式是主动扫描买入机会，风控是安全网
2. **AI 判断是核心，不是负担**：不减少 AI 做判断的时间点，而是让每个节点的 prompt 有差异化焦点
3. **Claims 必须注入盘中决策**：607条 claims 不是装饰品，每次 LLM 触发时必须检索匹配的 claims

## 实施时需注意

- 修改任何 cron 任务 prompt 时，确保嵌入交易者人格 + 赔率框架 + 反保守自检
- 不要用 "保持谨慎" "控制风险" 等措辞主导 prompt——这会强化 LLM 的保守倾向
- 每次修改后自测：同样的市场数据，新 prompt 是否输出了至少一条买入/加仓建议？
