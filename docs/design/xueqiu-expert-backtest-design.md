# 雪球大牛回测筛选系统设计

日期：2026-09-23
状态：待评审
关联：`~/.hermes/skills/xueqiu-cube-tracking/SKILL.md`（登录态搭建 + 端点实测手册，2026-09-23 全部验证通过）

## 1. 背景与问题

目标：用过去 2 年板块真实走势做锚点，找出在板块启动**之前**就公开预判对的人，两年验证下来筛选出"眼力强、行情敏锐"的可跟踪大佬（①类分析型大牛；②类高收益模拟仓为次要参考）。

调研证伪了三条"从板块反查历史帖"的路径（2026-09-23 逐项实测）：

1. **雪球站内搜索无时间筛选器**：`/k?q=<kw>` 页面无时间维度过滤（DOM 实测 filters=[]），无法按"2025-06~2025-08"窗口拉帖。
2. **个股讨论区只能回溯 ~3 个月**：`/statuses/search.json?symbol=SH603986&page=N` 实测 page=100 → 2026-09-11，page=200+ → 空；`before/since/until/start/end/max_id` 时间参数全部被忽略（永远返回最新 10 条）。
3. **搜索引擎对用户帖索引覆盖率 = 0**：`site:xueqiu.com 存储芯片 2025年6月` / `site:xueqiu.com 创新药 2025年3月` 两次实测，结果全部为 stockmc.xueqiu.com 的 PDF 公告，无一条用户讨论帖。

**结论：唯一可行路径 = "从作者正向翻历史"**。先发现候选人，再用时间线 API 翻每人 2 年帖子做命中判定。用户时间线 API 已验证可拉到 2023-11（超过 2 年要求）。

## 2. 设计原则

- **顺序不可反**：候选人发现 → 时间线回测 → 命中判定。不能"从板块反查帖子"（已被证伪）。
- **规则层零 LLM**：板块启动判定、时间窗口过滤、评分全部纯函数可单测；LLM 只在"帖子内容看多/看空"解析时调用，且只处理窗口内候选帖（控成本）。
- **复用不重建**：登录态复用 chromium profile（cookie 持久化）；候选池复用已采集的 100 个组合主理人；最终跟踪名单的输出格式对齐现有 claim 体系。
- **诚实标注覆盖率天花板**：只能发现"当前仍活跃且曾预判对"的人；已删号/停更者系统性不可达，报告必须显式声明。

## 4. 链路设计

### 4.1 板块启动事件库（纯函数）

对东财行业板块（t:2）+ 概念板块（t:3）全量日 K，过去 2 年（2024-09 ~ 2026-09）：

```
启动事件判定（可配置阈值）：
  ① 板块指数收盘突破 60 日均线（当日 close > MA60 且前一日 ≤ MA60）
  ② 之后 20 个交易日内最大涨幅 > 10%
满足 ①② → 记录事件：
  { sector, launch_date, ma60_break_date, max_gain_20d, top10_stocks_20d }
```

落盘：`data/xueqiu/sector_launches.json`。
验收口径：抽样 10 个市场公认行情（2025-03 创新药、2025-07 存储、2025-09 CPO 等），事件库应命中 ≥8/10，否则调阈值。

### 4.2 候选人发现（3 渠道）

| 渠道 | 方法 | 产出特征 |
|---|---|---|
| A. 当前活跃作者（主渠道） | 对 4.1 的每个板块做站内搜索 → 讨论 tab → 提取作者；过滤媒体号（7X24快讯类）/研报搬运号/原创帖 <10 的号 | 当前仍活跃、与板块相关 |
| B. 公开大 V 清单 | 雪球年度影响力用户/十大新锐等历年公开名单（web_search 获取） | 已有社区知名度 |
| C. 组合主理人 | 已采集 100 个高收益组合的 owner_id，查其是否有原创帖（部分只调仓不发言） | 收益型、可能有分析帖 |

产出：`data/xueqiu/candidates.json` — `{uid, screen_name, source: A|B|C, related_sectors, followers_count}`。

### 4.3 时间线回测（批量）

对每个候选人翻 `/statuses/original/timeline.json` 至 2024-09（或 total 耗尽）：

- 每帖提取：`created_at / title / description / target(URL)`
- 效率：每人 10-60s（浏览器导航限速），100 人 ≈ 17-100 分钟，可分批
- 产出：`data/xueqiu/posts/{uid}.json`
- 完整正文只对在命中窗口内的候选帖二次拉取（`xueqiu.com/<uid>/<status_id>`），快照存 `sources/raw/xueqiu/`

### 4.4 命中判定与评分

**窗口过滤（纯函数）**：帖日期 ∈ [启动日−21天, 启动日−3天] 且帖子与该板块相关 → 候选帖。

**内容判定（LLM，仅候选帖）**：看多该板块/个股 vs 中性提及 vs 看空。抽样 20 条人工复核，误差率 >15% 时收紧 prompt。

**命中三档**：
- **强命中**：提前 7~21 天 + 看多 + 板块 20 日涨 > 15%
- **中命中**：提前 3~21 天 + 看多 + 板块 20 日涨 5~15%
- **未命中**：方向错或板块未涨

**评分（纯函数）**：

```
眼力分   = 强命中×3 + 中命中×1
持续力   = 命中跨越的不同板块数（多板块命中 > 单板块反复）
密度     = 命中数 / 总原创帖数
综合分   = 眼力×0.5 + 持续力×0.3 + 密度×0.2
```

产出：`data/xueqiu/expert_ranking.json` TOP 20，每人附命中明细（日期-板块-提前天数-板块涨幅-原帖 URL，可追溯）。

## 5. 存储设计

```

```

## 6. 实施阶段

| Phase | 内容 | 预计耗时 | 验收标准 |
|---|---|---|---|
| P1 | 板块启动事件库 | 0.5 天 | 抽样 10 个公认行情命中 ≥8/10 |
| P2 | 候选人发现（100-300 人） | 1-2 天 | candidates.json，三渠道来源标注，过滤规则生效 |
| P3 | 时间线回测 | 2-3 天 | posts/ 拉取成功率 ≥95%，最早帖 ≤2024-10 |
| P4 | LLM 命中判定 | 1-2 天 | verdicts/ 全覆盖；抽样 20 条人工复核误差 ≤15% |
| P5 | 评分 + TOP 20 输出 | 0.5 天 | expert_ranking.json + 每人命中明细报告 |

总计 5-8 天，可分批执行。每个 Phase 产出落盘后可中断续跑（索引文件驱动）。

## 7. 风险与不确定性

1. **覆盖率天花板**：2 年前预判对但已删号/停更者系统性不可达——输出报告必须显式声明"名单 = 当前仍活跃且曾预判对的人"。
2. **LLM 判定误差**：看多 vs 中性提及存在边界模糊（如"值得关注"），抽样人工复核兜底。
3. **WAF 频率风险**：时间线 API 需浏览器导航，批量跑时限速分天，避免触发封号。
4. **板块事件口径**：突破 MA60 + 20 日 >10% 是建议初值，需用公认行情校准后锁定。
5. **单向验证偏差**：体系只验证"看多命中"，不惩罚"看空踏空"——评分读法需注意。
