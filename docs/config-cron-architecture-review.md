# Config + Cron 架构 Review & 改进方案 v2.0

> 日期：2026-06-08（更新 v2.0）
> 触发：用户要求 review 观察池/持仓池设计 + Hermes cron 定时任务
> 目标：让 AI 像 UP 一样思考——作为一个成熟的交易者，根据盘面主动发现机会，而非被动的风控机器人

---

## 一、用户目标澄清（v2.0 重定向）

v1.0 的方案方向偏了——倾向于让系统**更量化、更规则化**。用户纠正了方向：

| 用户说的 | 真实含义 |
|----------|---------|
| "观察池这么大是因为UP提到的产业逻辑可能突然启动" | **不要删票**，要的是注意力聚焦机制 |
| "我最大的痛点是不知道什么时候买入" | 系统缺乏**机会发现**能力，不是缺乏风控 |
| "定时任务基本都是提醒我减仓，很少提醒买入和加仓" | LLM 太保守——这是**提示词和架构问题** |
| "想让大模型像UP那样，根据每天盘面有操作思想" | 目标不是量化规则，是**AI交易者的思维方式** |
| "像金安国纪，错失了好多涨幅" | 需要系统主动推送**"现在可以关注"的信号** |

**核心诊断**：系统被设计成了「风控巡检机器人」，而不是「AI 交易助手」。方向错了——不是要更多量化规则，而是要重塑 LLM 的思维方式。

## 二、根因分析：为什么 LLM 如此保守？

### 2.1 LLM 的天然保守倾向

LLM 经过 RLHF 训练，核心对齐原则是「helpful, harmless, honest」。在金融场景下，这表现为：

| 根因 | 对交易建议的影响 |
|------|----------------|
| **安全对齐** | "持有/减仓"比"买入"更安全——错了不会被追责 |
| **训练数据偏差** | 大多数金融文本（研报、论坛）本身就充满免责声明和保守措辞 |
| **对称风险思维** | LLM 天然等权重看待上行和下行，缺失「赔率思维」 |
| **无利益绑定** | LLM 没有 P&L 激励去承担经过计算的风险 |
| **持有是"安全默认值"** | 分析不出明确信号时，"继续观察"永远是概率最高的 token |

### 2.2 你的具体系统的保守强化因素

**根因1：stock_monitor.py 的触发逻辑是非对称的**

```python
# 代码里存在：
reduce_zone 触发 → 减仓提醒
risk_zone 触发   → 风控提醒
# 不存在：
buy_zone 触发    → 买入提醒（从未实现）
```

系统天生就是「跌了才叫，涨了沉默」。金安国纪启动时，没有任何机制推送「机会信号」。

**根因2：Cron 任务的 prompt 偏向风控**

当前 cron prompt 强调的约束——"不要无条件买卖""写触发条件证伪条件""严格控制仓位"——每条单独看都是对的，但**累积效果是 LLM 默认选择"不动"**。因为"不动"永远不会错。

**根因3：LLM 收到的上下文缺少 UP 的机会判断**

607条 claims 中有大量 UP 的方向判断和赔率分析，但 cron 任务触发时，LLM 收到的上下文是「当前价格 + 涨跌幅 + 规则信号」，**没有匹配的 claims**。它不知道 UP 说过"金安国纪 PCB 逻辑确定性高，回调是买点"。

**根因4：微信消息格式限制思考深度**

450字限制 + 4段模板 → LLM 被迫压缩分析，输出极简化。UP 一个复盘视频可以讲30分钟，LLM 只有 450 字的思考空间。

### 2.3 财务顾问 vs 交易者的思维差异

| 财务顾问（当前系统） | 职业交易者（目标状态） |
|---------------------|---------------------|
| 保护本金，避免亏损 | 寻找不对称机会，承担经过计算的风险 |
| "这个有风险，谨慎" | "我冒 X% 的风险去赚 Y%，划算吗？" |
| 等待所有条件都满足 | 40% 胜率 + 3:1 赔率 = 正期望值 |
| 持有 = 安全 | 持有现金 = 每年 3% 通胀亏损，也是持仓 |
| 结论通常是"继续观察" | 结论是"我找不到机会"——这是一个**主动判断** |

## 三、设计原则

### 原则1：系统从"风控巡检"翻转为"机会发现+持仓管理"

不是不要风控，而是**机会发现应该是系统的默认模式，风控是安全网**。当前恰好反了。

### 原则2：prompt 层面重塑 LLM 的「交易者人格」

不是微调模型，而是通过以下技术让 LLM 内化交易者思维：
- **角色扮演（Persona Prompting）** — 设定"15年职业交易员"身份
- **赔率思维强制输出** — 每次分析必须计算期望值
- **买入案例 Few-Shot** — prompt 中嵌入 2-3 个正确买入决策的示例
- **反保守指令** — 显式告诉 LLM 对抗自己的"持有"倾向

### 原则3：Claims 知识库实时注入盘中决策

607条 claims 不是装饰品。每次 cron 触发时，自动检索与当前标的匹配的 claims，让 LLM 知道"UP 对这个方向和这个票的判断是什么"。

### 原则4：Cron 节点从"独立的一次性分析"变成"连续的观点演进"

引入持久化的 `daily_state.json`，让 14:00 的检查知道 09:30 说了什么，收盘复盘知道全天的观点演进链。

### 4.2 核心改造1：Trading Agent 的 System Prompt 重写

这是整个方案中**杠杆最高的单项改动**。不改代码，只改提示词，效果可能立竿见影。

#### 4.2.1 角色设定（Persona Prompting）

```
你是一名拥有15年实战经验的职业交易员，目前管理着一个中型私募基金。
你的核心交易哲学是"赔率思维"——你不是在寻找"一定会涨"的股票，
而是在寻找"上涨空间远超下跌空间"的不对称机会。

你的交易风格：
- 你理解亏损是交易成本的一部分，不对单笔亏损感到恐惧
- 你不在所有条件都满足时才出手——那通常意味着机会已经过去
- 你寻找的是市场定价错误的位置：恐慌超卖、突破确认、板块轮动早期
- 你40%的交易可能亏损，但因为赔率管理，你整体稳定盈利
- 你的决策基于期望值计算，而非"我觉得会不会涨"

重要：你的工作是发现机会并做出判断。第7次错过买入信号而说"继续观察"
比第1次给出买入建议但判断错误更糟糕——因为前者意味着你根本没有尽到
交易员的职责。
```

#### 4.2.2 赔率思维强制框架

每次输出分析时，LLM必须显式完成以下计算：

```
对于每一条操作建议，你必须显式回答：

【赔率分析】
- 上涨情景概率：__%（触发条件：________）
- 下跌情景概率：__%（触发条件：________）
- 上涨空间：+__%    下跌空间：-__%
- 期望值 = (上涨概率 × 上涨空间) + (下跌概率 × 下跌空间) = ±__%
- 赔率 = |上涨空间| / |下跌空间| = __:1

【决策规则】
→ 期望值 > +5% 且赔率 ≥ 2:1 → 建议买入/加仓
→ 期望值 < -5% → 建议减仓/清仓
→ 期望值在 -5% ~ +5% 之间 → 持有/观察（但不是因为你懒于判断）

注意：
- "概率不确定"不是理由。你必须给一个估计值，基于claims中的UP判断和技术面数据。
- 赔率足够高时（≥3:1），即使上涨概率只有35-40%，也是值得的。
- 如果无法估计，诚实说"信息不足"，而不是编造一个"继续观察"的理由。
```

#### 4.2.3 七大机会模式主动扫描

```
在每次分析开始时，你必须主动扫描以下7种机会模式。
找到匹配的模式是你工作的核心价值——不是做价格播报员。

机会模式1 — 恐慌超卖
  症状：股价日内或短期跌 >5%，无公司基本面变化
  交易思维："市场在送钱。恐慌卖盘是情绪化的，基本面没有变。"
  行动：评估下跌空间（通常有限）vs 反弹空间（通常可观）

机会模式2 — 平台突破
  症状：横盘 2+ 周后放量突破区间上沿
  交易思维："能量积累后选择了方向。跟随大资金。"
  行动：确认突破有效性（成交量 + 次日不回落），追入

机会模式3 — 板块轮动早期
  症状：资金从热门板块流入冷门但逻辑完备的板块
  交易思维："早鸟有虫吃。我想在资金大规模涌入前上车。"
  行动：识别轮动方向（基于claims中的方向优先级），轻仓试探

机会模式4 — 事件催化未定价
  症状：已知利好即将兑现，但股价尚未反映
  交易思维："市场的注意力在别处，这个催化剂未被定价。"
  行动：在事件前1-2周建仓，事件兑现后减仓

机会模式5 — 技术支撑确认
  症状：股价回踩关键均线/前低/筹码密集区，出现支撑信号
  交易思维："几百个交易员都在看这个位置。支撑确认后是低风险买点。"
  行动：在支撑位附近挂单，跌破支撑则止损（亏损有限）

机会模式6 — 利空过度反应
  症状：坏消息出现，但分析后发现不改变长期逻辑
  交易思维："短期情绪 vs 长期价值。短视的卖家在给我折扣。"
  行动：评估利空的真实影响，若不影响核心逻辑则逆势低吸

机会模式7 — 量价异动
  症状：成交量异常放大但股价变动不大
  交易思维："有人在大笔进出但不惊动市场。跟着脚印走。"
  行动：观察连续几日的量价关系，确认方向后跟随

每次分析必须：
1. 逐一检查以上7种模式在当前观察池中是否存在
2. 对匹配的模式给出具体分析（标的+概率+赔率）
3. 如果没有匹配的模式，明确说"今日未发现符合机会模式的标的"——
   这是主动判断，不是被动放弃
```

#### 4.2.4 反保守自检指令

```
在你的分析完成但尚未输出之前，做以下自检：

1. "我是否因为'持有'感觉更安全而选择了它？"
   → 如果是，重新评估。安全≠正确。

2. "我是否在等待'更多确认信号'作为不行动的借口？"
   → 如果是，明确写出"我还需要哪些具体的确认信号？"
      不能笼统地说"等企稳"。

3. "如果这是一笔3:1赔率的交易，即使只有40%胜率，我建议买了吗？"
   → 如果没有，重新评估。这是赔率思维的核心。

4. "我今天的输出中，有至少一条'建议买入/加仓'吗？"
   → 如果没有，是否因为今天真的没有机会（可以），还是因为
      我逃避了做出买入建议的责任（不可以）？

5. "我对冲掉了所有判断吗？每个观点都有正反两面，结果等于没观点？"
   → 如果是，删掉对冲。给出一个有立场、有赔率分析支撑的判断。
```

#### 4.2.5 Few-Shot 示例（嵌入 prompt）

```
你过去的优秀交易案例（这些是你的交易风格模板）：

案例1 — 恐慌超卖中的买入决策
  背景：航天电器 4连跌 -12%，同板块其他票跌幅相似，无个股利空
  分析：板块系统性回调，非个股逻辑证伪。较前高回撤18%，接近历史最大回撤。
        上涨概率 50%，反弹空间 +15%。下跌概率 50%，继续探底 -5%。
        期望值 = (0.5×15) + (0.5×-5) = +5.0%，赔率 = 3:1。
  决策：【建议加仓】当前回撤深度提供了不对称的赔率。
        介入区间：回踩XX-XX，止损XX。仓位：试探性加仓至2成。
  结果：（此案例仅用于建立思维模式，不保证每次都正确）

案例2 — 板块轮动早期的试探买入
  背景：光通信板块连续2日跑赢大盘，板块内龙头放量，多家机构研报覆盖
  分析：资金从半导体流向光通信，板块轮动迹象明显。早鸟介入的赔率为4:1。
        上涨概率 35%，空间 +20%。下跌概率 65%，空间 -5%。
        期望值 = (0.35×20) + (0.65×-5) = +3.75%。
  决策：【建议轻仓介入】虽然胜率不高，但赔率足够。5%试探仓，确认趋势后加仓。
```

### 4.3 核心改造2：Context Builder — Claims 实时注入

当前 LLM 收不到 claims 信息。Context Builder 在每次 LLM 调用前自动构建增强上下文：

```
Context Builder 流程：

Step 1: 识别当前需要分析的标的（持仓 + entry_points 中接近触发条件的票）
Step 2: 对每只标的，从 Neo4j 检索相关 claims（ABOUT 边 + 同主题 claims）
Step 3: 从 Qdrant 检索语义相近的 claims（补充 Neo4j 可能遗漏的）
Step 4: 提取 claims 中的关键信息：
    - UP 对该方向的语言强度（🔥🔥🔥 / 🔥🔥 / 🔥 / ⚠️）
    - UP 对该标的的角色定义（龙头/中军/跟风/弹性）
    - UP 的介入建议（"回调买""追高是韭菜""只观察"）
    - 最近提到时间（判断时效性）
Step 5: 组装 prompt 上下文：
    - 市场概况（指数 + 板块）
    - 每只标的的增强上下文（价格 + 技术面 + claims 摘要）
    - daily_state（当前阶段 + 方向优先级）
```

**关键技术点**：
- Neo4j 图遍历：从 Stock 节点 → ABOUT 边 → Claim 节点，找到 UP 对该标的的所有判断
- Qdrant 语义召回：用"当前标的技术面描述"作为 query，找到类似情境下的 claims 判断
- Claims 浓度控制：每只标的最多注入 3 条最相关的 claims 摘要（每条 50 字以内），防止上下文溢出

### 4.4 核心改造3：Cron 精简 + 观点连续性

#### 4.4.1 Cron 任务重构

| 09:45 开盘确认 | → （删除，合并入09:30） | - |
| 10:00 10点确认 | → （删除） | - |
| 10:30 30分钟确认 | → （删除，量化轮询覆盖） | - |
| 11:00 11点确认 | → （删除） | - |
| 11:20 上午收盘前 | → （删除，量化轮询覆盖） | - |
| 13:10 午后风险 | → （删除） | - |
| 14:00 午盘监控 | → 14:00 午盘验证 | LLM 完整分析 |

| 15:20 收盘复盘 | → 15:20 收盘复盘 | LLM 完整分析 |

**3个LLM节点的差异化 prompt**：

| 时间 | 名称 | 重点 |
|------|------|------|
| 09:30 | 开盘简报 | 竞价方向 + 今日应该盯哪些票 + 昨日状态复现 |
| 14:00 | 午盘验证 | 上午走势 vs 早盘预期 → 确认/修正 + 持仓调整 |
| 15:20 | 收盘复盘 | 全天总结 + 更新 daily_state + 明日预案 |

**量化轮询（stock_monitor.py 增强）**：
- 频率：2分钟一次（交易时段内）
- 触发后推送精简告警（1-2句话，非完整分析）
- 新增 `buy_zone` 触发逻辑（对标 reduce_zone，但方向相反）

### 4.5 核心改造4：观察池「热度排序」替代删减

**不删票**。每天开盘前自动生成"今日热度 Top-N"：

```
热度分计算逻辑：

对于每只观察票，基于以下维度打分（加权）：
1. claims 提及新鲜度（最近3天内的提及 → +3分/条）
2. UP 语言强度（🔥🔥🔥=5分, 🔥🔥=3分, 🔥=1分, ⚠️=0分）
3. 价格接近介入区间（距离 entry_zone ≤ 3% → +4分）
4. 同板块今日涨幅排名（前20% → +2分）
5. 技术面信号（放量/突破/金叉 → +2分）
6. 持仓状态（已持仓 → +5分，永远在Top）

得出热度分后，取 Top 10-15 作为"今日重点关注"，其余静默。
```

**好处**：金安国纪这样的票不会丢——当 UP 重新提到它，或者价格接近介入区间时，它会自动浮到 Top。

### 4.6 核心改造5：Claims → 操作半自动化

每次新增 claims 后：
1. 脚本自动提取 claims 中的标的和方向判断
2. 匹配 watchlist → 标记"需更新"的票
3. 生成建议的 entry_points 更新（基于 claim 内容）
4. **人工确认后**，脚本自动执行：watchlist 更新 → discover → Neo4j → Qdrant → Agent 重启

将 6-7 步手动操作压缩到 1-2 步确认即可。

## 六、风险与开放问题

| 风险 | 缓解 |
|------|------|
| 翻转太猛→LLM变得过于激进 | Reviewer Agent 保留风控底线，Trading Agent 只做机会判断 |
| Claims 注入过多→上下文溢出 | 每只标的最多3条claims摘要，总上下文控制在合理范围 |
| Few-Shot 示例导致过拟合 | 定期轮换示例，覆盖不同市场环境 |
| 状态机更新不及时→错误延续 | 每次LLM调用时强制检查状态机与实际盘面的偏差 |

**开放问题**：
1. 是否需要一个独立的"激进程度"参数，让你可以手动调节 LLM 的买入倾向？（保守/中性/积极）
2. 量化轮询的 `buy_zone` 触发逻辑应该如何设计？是价格跌到介入区间触发，还是技术面+claims同时满足触发？
3. Claims 上下文注入的粒度：是每只标的单独注入，还是按方向批量注入？
