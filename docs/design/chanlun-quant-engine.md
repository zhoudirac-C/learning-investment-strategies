# 缠论量化引擎 — 技术方案（设计文档）

> 版本: v1.0 | 日期: 2026-07-18 | 作者: Kimi + 337 条缠论定理级 claims
>
> 目标：以 `knowledge/claims/` 中 337 条缠论 108 课定理级 claims 为**验收标准**，构建口径严谨、可复现的缠论结构分析引擎（分型→笔→线段→中枢→买卖点→级别递归）。
>
> 路线（经调研确认）：**混合路线** —— fork chan.py 作单级别形态学+增量引擎底座，用 claims 编译成的测试门逐条校准，级别递归层自建。纯复用（两库均不过验收）与纯自建（丢掉已踩平的工程细节）均被否决。

---

## 一、背景与决策依据

### 1.1 调研结论摘要（2026-07-18，三路并行调研）

| 候选 | 覆盖度 | 口径可信度 | 工程底座 | 结论 |
|------|--------|-----------|----------|------|
| czsc (waditu) | 仅分型/笔/笔中枢；**无线段、无走势类型、无严格买卖点** | 笔规则编译死在 Rust（min_bi_len=6），无新老笔开关 | 增量更新+Rust 性能+信号事件体系 | 只作**对照实现**，不作底座 |
| chan.py (Vespa314) | 五要素全覆盖，口径高度可配，线段有子类扩展点 | **作者明示未读完原著、不向原文靠拢，零测试** | is_sure/虚笔虚段/逐帧增量一致性，业内最诚实的未来信息防护 | **作底座 fork**，按 claims 校准 |
| 社区证据 | 实现间分歧结构性存在（新笔/旧笔、77 课区间歧义、特征序列缺口）；可复现正收益证据为零 | — | — | 口径验收标准只能来自我们自己的 claims |

### 1.2 核心矛盾

没有任何两个缠论实现能在边界 case 上自动一致（社区共识+两库源码实证）。因此**口径标准必须先于实现**——337 条 claims 是我们独有的、逐字对齐原文的规格源，把它编译成可执行测试，是整个方案的地基。

### 1.3 收益预期（诚实声明）

本引擎的交付物是**口径严谨的结构分析能力**，不是盈利机器。公开渠道无任何"纯缠论买卖点信号+完整成本假设"的可复现正收益记录（广发 2012/中信建投 2016 两份券商金工结果中性）。策略侧定位为：缠论结构特征/过滤器，嵌入更大策略体系。

## 二、目标与非目标

### 2.1 目标

1. **校准测试门（M1，决策门）**：claims → 可执行测试用例 → czsc/chan.py 对表 → 《口径偏差清单》
2. **单级别形态学引擎（M2）**：fork chan.py，按偏差清单校准笔/线段/中枢/买卖点，全部测试门 PASS
3. **级别递归层（M3）**：按原文递归观（课 35/84：f1/f2）自建，两库均无此物
4. **is_sure 语义全程保持**：所有未确认元素（虚笔/虚段/虚中枢）带确认标记，下游可严格区分

### 2.2 非目标（本期不做）

- 策略回测与盈利验证（M4 以后单独立项）
- 实盘接入、实时行情流
- 画图/GUI（chan.py 自带的保留即可，不投入）
- 期货/外盘适配（先 A 股日线级别，T+1 语义在数据层预留）

## 四、校准测试门设计（M1 核心）

### 4.1 用例三来源

**A. claims 直译 synthetic 用例（主力，20-30 条）**
手工构造 K 线序列（开高低收数组），精确命中某条 claim 的定义边界：

| 用例族 | 覆盖 claims | 边界点 |
|--------|------------|--------|
| 包含合并 | 课62/65（`claim-20070630-001-b` 等） | 方向判定、顺序处理、连续包含 |
| 分型 | 课62/81/82 | 三根关系、右确认延迟、共用K线 |
| 笔 | 课77/91（`claim-20070905-001-b`） | **77课"区间"歧义**、间隔K线数、新笔成笔旧笔废止 |
| 线段 | 课64/67/71/78 | **特征序列缺口两情况**、一笔不破坏、古怪线段 |
| 中枢 | 课17/18/35 | 区间公式 max/min、三连续重叠、升级（9段） |
| 买卖点 | 课20/21/53/86 | 一/二/三类位置几何、二三类重合、级别定理 |
| 背驰 | 课24/27/44 | MACD 面积比较、区间套、小转大必要条件 |

**B. 课文金标样本（3-5 条）**
108 课中缠中说禅本人做过的图上分析（如 2007-02 前后 5 分钟中枢、课 35/36 的 2915/2760-2858 例），取对应时段真实数据跑分解，与课文结论对照。数据缺口（2007 分钟线难获取）时降级为日线实例+synthetic 替代。

**C. 真实数据互 diff（探索性）**
A 股指数/个股近年日线、30 分钟线各取若干段，两实现互相对 diff，分歧点人工仲裁后沉淀为新用例。

### 4.2 用例格式（rules.yaml + cases/*.yaml）

```yaml
- case_id: BI-001
  claim_refs: [claim-20070905-001-b]   # 笔的划分规则与唯一性
  rule: 相邻顶底分型且顶分型区间高于底分型区间 → 成笔
  bars: [[o,h,l,c], ...]                # synthetic K线
  expect:
    fx: [{idx: 2, type: top}, {idx: 5, type: bottom}]
    bi: [{start: 2, end: 5, dir: down, sure: true}]
```

每条用例可追溯到 claim id；FAIL 即定位到具体定理。

### 4.3 判定与产出

- harness 归一化两实现输出（分型表/笔表/线段表/中枢表/买卖点表）后逐字段 diff
- 产出**校准矩阵**：case_id × 实现 × PASS/FAIL/diff 详情
- 汇总为《口径偏差清单》：每条偏差记录【规则源 claim、两实现行为、仲裁结论（以原文为准）、改造点】——这份清单就是 M2 的工作订单

## 五、Fork 改造策略（M2）

### 5.1 Vendor 而非 submodule

chan.py 需改源码（笔规则无插件接口），submodule 不利于补丁管理。vendor 进 `third_party/chanpy/`：

- 保留 `LICENSE`（MIT）与版权声明
- `PATCHES.md` 逐条记录：文件、函数、原行为、改后行为、对应 claim id、对应校准用例
- 上游同步策略：低优先（作者年 27 commits），需要时人工三方合并

### 5.2 预估改造点（按调研，待 M1 偏差清单确认）

| 层 | 改造方式 | 说明 |
|----|----------|------|
| 分型 | 大概率不改 | 定义无争议 |
| 笔 | **改源码**（Bi.py/BiList.py） | 按 claims 钉死 77 课区间口径等 |
| 线段 | **子类扩展**（CSegListComm） | 特征序列两情况对齐课 67/71 |
| 中枢 | 配置+必要时改 | zs_algo 选最接近口径后校准 |
| 买卖点 | 自写 BSPointList 子类 | 复用其上游输出 |
| 增量/is_sure | **不改，核心资产** | 这是我们 fork 它的首要原因 |

### 5.3 零测试风险的对冲

chan.py 无测试。fork 后**先**在其自带配置上跑通校准门冒烟（确认 harness 集成正确），**再**开始改规则——每改一处，校准门必须全程绿（Red-Green-Refactor）。

## 六、级别递归层设计（M3，两库都没有）

### 6.1 原文口径

- 课 35：最低级别中枢由连续三笔同价交易定义（实务中以线段为最小构建单元，课 83），三个连续次级别走势类型重叠形成高级别中枢，逐级上推
- 课 84：f1(a0)=a1（启始规则可配），f2(an)=an+1（高级别生长规则不变）
- 级别与时间无关（课 84）——**不做"30 分钟图≈30 分钟级别"的偷换**

### 6.2 LevelTree 设计

```
ticks/bars → 分型 → 笔 → 线段(L0 走势类型)
  → 3×L0 重叠 → L1 中枢 → L1 走势类型
  → 3×L1 重叠 → L2 中枢 → L2 走势类型 → …
```

- 每层对象：中枢区间、进入/离开段、三类买卖点、完成/未完成（is_sure 透传）
- 增量生长：新 bar 只触发最低层重算，变化向上层传播（层间失效传播与 chan.py 层内 is_sure 机制同构）
- 与两库"多周期并列"模型本质差异：高级别**只能**由低级别递归合成，不直接读高级别图

### 6.3 与多周期数据的关系

多周期图仍可作为**模本**（课 33：图是显微镜）辅助显示与人工校验，但不参与递归定义。

- **synthetic bars**：纯数组构造，零依赖，校准门主力
