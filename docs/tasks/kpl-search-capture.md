## 背景：为什么需要这次抓包

v2.2 §16.4 调查结论（云端实测/核查）：

- 已封装的 KPL 端点里**没有任何搜索类接口**——资讯只有"按日时间流列表 → 逐篇全文"
  （`IndexPlate.GetIndexList` / `ForumsMsgJX.GetInfo`）；
- 最像研报的付费专栏条目全文 `errcode=1130` 无权限，只有标题/摘要；
- TDX 纯行情协议，无资讯/研报能力，已排除；
- 但**用户在 KPL App 内确认可以搜索**（资讯/文章/产业相关文章）——说明搜索接口存在，
  只是历次抓包未覆盖该操作路径。

本次任务：在本地抓取 **App 搜索功能** 的接口，记录后推送，云端继续接入。

## 抓取目标（按优先级）

1. **搜索接口**（核心）：在 App 内执行关键词搜索（建议试："产业链"、一个板块名如"PCB"、
   一个个股名/代码），捕获：
   - 请求：`c=&a=`、子域、全部参数（关键词参数名、分页参数、类型筛选参数）；
   - 响应：结果列表结构（字段名级别）、结果条目类型（资讯/文章/专栏/帖子如何区分）、
     命中条目的 ID 能否直接用 `ForumsMsgJX.GetInfo` 拉全文；
   - 搜索结果的 tab/分类（如"资讯/文章/研报"分页）各自的参数差异。
2. **文章详情链路**：从搜索结果点进文章详情的请求——确认是否复用现有 GetInfo，
   还是有独立详情接口；付费专栏条目在搜索链路下全文行为是否仍为 1130。
3. **顺带验证**（路过就做，不专门追）：
   - `TCop` 题材关键词流（列表响应附带，清单已记录未接入）；
   - `c=ForumsMsgJX&a=GetBkFuPan`（板块复盘，JS 里发现未实测）；
   - 搜索"产业链"这类产业文章在 App 内的入口形态（有无专栏/专题页及其接口）。

## 操作环境（已配置好，直接复用）

抓包拓扑与注意事项见 `docs/design/kpl-api-inventory.md` 两节：

- **Reqable VPN 模式**（首选）：SSL 代理规则集 `kpl-api-only`（仅拦截
  `app*.longhuvip.com`，其余透传）。注意开抓包时板块/题材详情页不可用（直连通道证书固定），
  抓完停掉 Reqable 再正常用 App；
- **USB + adb 拓扑**（公司网拦截场景备用）：完整命令在清单文末；
- 导出 HAR；抓包文件存 `temp/kpl_capture/`（已 gitignore，含 token，勿提交勿外泄）。

操作顺序建议：

1. 启抓包 → App 内随便浏览两下确认 API 流量可见（看到 `apparticle` 等域名明文）；
2. 执行搜索操作（上述 3 组关键词，每组翻一次页看分页参数）；
3. 从搜索结果点 2-3 篇文章（普通+付费各一）；
4. 停抓包，导出 HAR 到 `temp/kpl_capture/kpl-search-<date>.har`。

## 记录格式（追加到 kpl-api-inventory.md 新一节）

每个新接口按清单既有格式记录：

```
c=<控制器>&a=<动作>   子域: <subdomain>   参数: <关键参数及取值>
```

- 响应关键字段（字段名级别，贴 1 条实样 JSON 片段）；
- 标注：是否 H5 通道可解密 / 是否走直连通道（如搜索也走直连通道，如实记"不可得"并收尾，
  不要硬刚证书固定）；
- token 状态：本次抓包时 token 是否仍有效（记录上次抓包时间→本次的存活跨度）。

## 完成后交接回云端的 checklist

接口记录提交推送后，在云端（本仓库）继续：

## 纪律与边界（不变）

- 频率等同正常用户：每类调用每天一次，篇间 ≥0.5s；私有 API 有封号风险，仅限个人研究；
- `temp/kpl_capture/` 永不提交；`.env` 的 kpl 三件套不进 git；
- 若搜索走直连通道（证书固定）→ 记"不可得"收尾，转向 akshare 东财研报为主力源（§16.4 三层方案不变）。
