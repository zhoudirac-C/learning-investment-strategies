# 修订多指数周期分歧时的锚定规则

## 分析

AI在cycle_state中同时记录了创业板指90min底部（bottom_date=2026-09-17，rebound_day=5，理论窗口6-8天）与科创50（rebound_day=36）、上证（rebound_day=38）的超窗状态，却以「操作定位以超窗指数（科创50/上证）为高位兑现主锚」为理由，实质选择单一超窗指数锚定空头方向，而输出阶段时仅写「调整」，未将创业板指仍在窗口内的事实转化为“震荡”可能。这正是审计项所指「选取对预设结论最有利的单一指数锚定」，应归入概念误用。同时，AI的场景树只有「退潮延续·主动降速（基准）」和「退潮一日修复」两项，缺少“震荡”中间态；其invalidation仅设置“放量破位→升级调整”和“放量续板→改判修复”，未设置“指数未破位、成交额守住21000、涨停跌停均不极端→归为震荡”的分支，导致框架被迫在“调整/修复”二选一，且基准偏空，最终与事后真值“震荡”不符。数据缺口方面，当日已知缺口无，intraday_amount缺失只是AI自述风险，非本次判错主因；也不存在非公开渠道信息依赖。

## 处置建议

在cycle_state中若存在bottom_date/rebound_day分歧，禁止以单一超窗指数作为操作主锚；正确做法是给出区间（如“创业板指窗口内第5天，科创50/上证超窗”）或取中位，并显式标注“分歧状态”对阶段判断置信度的影响，降低空头或多头单边权重。
