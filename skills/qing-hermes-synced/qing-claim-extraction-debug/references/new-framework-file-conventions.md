# 新建 Framework 文件规范

> 来源：2026-07-29 方法论复盘→4个框架入库（2新建+2扩展）
> 用途：当 review 产出独立主题的 framework（不能归类到现有文件）时参考

## 新建 vs 扩展的判断

| 情况 | 操作 |
|------|------|
| 新规则可归类到 `trading-rules.md`（交易纪律/模式识别） | **扩展**：末尾追加新 section |
| 新规则可归类到 `sector-diffusion-framework.md`（板块/选股） | **扩展**：末尾追加 |
| 新规则可归类到 `market-cycle-framework.md`（周期判断） | **扩展**：末尾追加 |
| 新规则是**独立主题**（量能判断/宏观证伪等） | **新建**：独立文件 |

## 新建文件模板

```markdown
# 简短标题

> **定位**：操作工具层（轨道A），[谁加载？什么场景？]
> **来源**：[claim ID] 或 methodology-review 报告
> **关联 Claims**：claim-xxxxx, claim-yyyyy

---

## 核心原则

> **一句话核心判断（加粗引用格式）**

---

## 一、第一个核心章节

### Step 1: 判断维度

| 列1 | 列2 | 含义 |
|------|------|------|

---

## 格式约定

1. **定位行**：标注轨道A(Agent加载)或轨道B(参考)

2. **善用表格**：对比、误判、条件判断用表格

3. **善用引用块**：核心原则用 `>` 块突出

4. **善用ASCII流程图**：
   ```
   状态A → 条件1 → 状态B
          ↓ 条件2 → 状态C
   ```

5. **联动章节**：每个 framework 必须包含"与其它框架的联动"

6. **误判章节**：用具体话术而非抽象描述

7. **底部水印**：`*写入日期：YYYY-MM-DD | 来源：xxx*`

## 扩展现有文件的步骤

1. 先读目标文件尾部确认插入点
2. 新 section 用 `---` 分隔
3. 使用一致的标题层级
4. 更新目录索引（如有）
5. 添加关联 Claims 链接
6. 同步更新 `framework/README.md`（索引+更新记录）

## 更新 checklist

- [ ] `framework/README.md` 索引添加新文件
- [ ] `framework/README.md` 更新记录
- [ ] 如扩展 `trading-rules.md`，更新目录表
- [ ] git add + commit（message 以 `framework:` 开头）
- [ ] 通知用户新增了什么以及位置
