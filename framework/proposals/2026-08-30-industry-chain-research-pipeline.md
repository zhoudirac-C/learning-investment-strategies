# 产业链深度分析调研管线 — 立项文档

> 日期：2026-08-30
> 性质：基础设施立项（选股层核心能力建设）
> 触发：UP 方向池依赖风险——续费到期后失去 UP 方向判断
> 目标：用**券商产业链深度研报**为核心数据源，LLM 提取产业链逻辑，替代 UP 的方向判断能力
> **数据源验证（2026-08-30 交叉验证通过）**：UP CCL 方向的每一个数据点（FR8 160→200+、M6+缺货、
> 订单排至2027、VR200单柜+233%、建滔五轮提价、球硅/PPO涨价）均能在东财研报 API 的
> 公开券商深度研报中找到原文——UP 读的就是这些研报，不是私有信息

## 一、问题重新定义

### 1.1 上一版的问题

初版方案把"市场数据源"（资金流/龙虎榜/情绪/KPL）当成产业链数据源。
**这些不是产业链数据——它们是交易数据。** 产业链分析的核心是：

| 产业链分析需要什么 | 交易数据能给吗 |
|---|---|
| 产业链上下游传导关系（谁供谁） | ❌ 资金流不知道 |
| 各环节价值占比/壁垒/格局 | ❌ 龙虎榜不知道 |
| 供需缺口/产能约束/扩产节奏 | ❌ 涨停数不知道 |
| 技术升级路径/替代进度 | ❌ 炸板率不知道 |
| 价格传导链（铜箔→CCL→PCB→服务器） | ❌ 北向资金不知道 |

### 1.2 UP 的产业链分析到底怎么做（调研结论）

看 UP 的 26 个方向主题（watchlist.yaml）和 68 篇研报类原始文档（sources/raw/财经/研报：*.md），
UP 的产业链分析有清晰模式：

**信息源**：
- UP 读的是**券商深度研报**（不是日度简评，是 20-65 页的产业链专题）
- 典型代表：《AI PCB Rubin 产业链深度报告》《AIDC 与 AI 算力产业链深度研究》《国产算力产业链与 Token 经济学》
- UP 标注来源为"研报整理"，即**转发/解读**券商研报，不是自己调研

**UP 的分析框架**（从 watchlist.yaml 的 chain_relation/market_checks 拆解）：

```
产业链深度研报（券商写的 65 页 PDF）
  → UP 提取产业链传导链（上游→中游→下游，每环价值占比）
  → UP 识别核心卡脖子环节（谁有定价权、谁缺产能）
  → UP 映射到 A 股标的（按 chain 位置 + 竞争格局选龙头）
  → UP 设定验证指标（价格是否持续上涨、产能是否扩张、订单是否落地）
  → UP 判断持续性（产业趋势 vs 事件催化 vs 主题炒作）
```

**UP 的价值不在信息垄断，在于：**
1. 从 227 篇/日的研报中筛出 6 篇产业链深度研报（**筛选**）
2. 从 65 页 PDF 中提取产业链传导链（**提取**）
3. 把传导链映射到 A 股标的（**标的映射**）
4. 给出操作判断（**判断**）

**这四步 LLM 都能做。**

## 二、核心数据源验证（2026-08-30 实测）

### 2.1 东财研报 API —— 产业链深度研报

**API**：`reportapi.eastmoney.com/report/list`
- `qType=1`（行业研报）——近 3 天 50 条，其中产业链深度型 **6 条**（标题含"产业链/深度/全景/拆解/供应链"）
- `qType=0`（个股研报）——近 3 天 100 条，深度型 **3 条**
- 每条有 `infoCode` → PDF 直链 `https://pdf.dfcfw.com/pdf/H3_<infoCode>_1.pdf`

**实测验证（2026-08-30）**：

| 研报 | 机构 | 页数 | 内容 |
|------|------|------|------|
| 超节点方案重塑AI算力产业趋势 | 东吴证券 | **65页** | 超节点架构+NVLink/UALink+散热/供电+标的映射（工业富联/华勤/浪潮/紫光） |
| 光模块行业深度报告 | 爱建证券 | 27页 | 光模块价值链重构 |
| 计算机"一周解码"：Rubin周期 | 中银证券 | 10页 | Rubin 驱动全产业链 |
| 2026年全球智能手机洞察 | 头豹研究院 | 17页 | 存储芯片涨价 |

**PDF 可下载、可用 PyMuPDF 提取文本**（65 页 7.6MB PDF 实测提取成功）。

**每日产业链深度研报量**：约 6/50 行业研报 = **12%**，每日约 2-3 篇可用的深度研报。

### 3.2 与 UP 分析的对标

| UP 做的 | 管线替代方案 | 差距 |
|---------|------------|------|
| 筛研报：从 227 篇筛 6 篇深度 | Step 1 规则筛选 + Step 3 LLM 判断 | LLM 可能漏掉标题不含关键词的深度研报 |
| 读 PDF 提取产业链逻辑 | Step 2 PDF 提取 + Step 3 LLM 分析 | LLM 对图表数据提取可能不如人 |
| 映射 A 股标的 | Step 3 LLM 标的映射 | LLM 可能给错代码，需 A 股代码校验 |
| 判断持续性/操作性 | Step 3 LLM 判断 + reasoning-patterns | 需要回测校准 |
| 串逻辑链（跨研报） | Step 4 综合分析 | LLM 长上下文能力足够 |

### 3.3 reasoning-patterns.yaml 的匹配

LLM 提取时按关键词匹配 UP 的推理模式：

| 模式 | 触发关键词 | LLM 分析侧重 |
|------|-----------|------------|
| upstream_cycle | 涨价/供需/缺口/扩产/满产 | 供需缺口→涨价持续性→周期位置 |
| tech_diffusion | 渗透率/代际升级/BOM拆解 | 技术路径→替代时间线→价值量跃迁 |
| event_drive | 中标/签约/政策/停牌 | 事件催化→标的映射→兑现时点 |
| rotation | 高低切/轮动/分歧承接 | 板块轮动→资金流向→切换信号 |
| bottom_grinding | 磨底/缩量/冰点/反弹 | 底部结构→反弹窗口→仓位管理 |

## 五、实施计划

### Phase 1：产业链研报筛选 + LLM 提取 MVP（3-5 天）

**目标**：给定一天研报数据，LLM 能提取出产业链逻辑

**交付物**：
- `scripts/chain_analysis.py` 主入口
- Step 1 候选筛选（纯规则，不需要 LLM）
- Step 2 PDF 下载 + 文本提取
- Step 3 LLM 产业链提取（单篇研报）
- 输出示例：`infra/data/chain_analysis/step3_chains_<date>.json`

**验收**：
- 对 8/27 的东吴证券超节点深度报告（65页 PDF），LLM 能提取出：
  - 产业链传导链（上游→中游→下游）
  - 至少 5 个 A 股标的映射
  - 验证指标和失效条件
- 与 UP 同主题方向（watchlist.yaml 中的 PCB/CCL 方向）对比，标的重合度 > 50%

### Phase 2：跨研报综合 + 标的池（1 周）

**目标**：每日自动输出产业链简报 + 动态 watchlist

**交付物**：
- Step 4 跨研报综合
- dynamic_watchlist.yaml 输出
- factor_rank.py --source dynamic 对接
- 每日产业链简报（Markdown）

**验收**：
- 连续 3 天运行，每日产出 3-5 条产业链主线
- dynamic_watchlist 含 20-40 只标的
- 与 UP 当日方向池重合度 > 40%

### Phase 3：公告扫描 + 持续校准（1-2 周）

**目标**：补全公告事件源，持续校准

**交付物**：
- 公告事件扫描（LLM 筛选"提价/扩产/签单"类）
- 与研报提取合并
- UP 续费期内每日对比校准
- Prompt 调优

## 七、风险与限制

1. **研报滞后**：券商深度研报通常滞后 1-2 周——趋势已走了一段才出研报
   → 缓解：同时看公告事件（更及时）
2. **LLM 图表提取弱**：PDF 中大量信息在图表里，文本提取可能丢失
   → 缓解：优先提取文本段，图表标题作为线索
3. **标的映射错误**：LLM 可能给错代码或张冠李戴
   → 缓解：A 股代码格式校验 + factor_rank 验证
4. **深度研报量不稳定**：有些天可能没有产业链深度研报
   → 缓解：连续 3 天无深度研报时，降级为"行业研报简评"模式

## 八、不做的事

- ❌ 不做实时新闻爬取（信息噪音太大，等研报沉淀更可靠）
- ❌ 不做社交媒体舆情（与产业链分析无关）
- ❌ 不替代 chan_engine（买卖点判断仍由 M7 引擎负责）
- ❌ 不做基本面财务分析（产业链逻辑 ≠ 公司财报分析）
- ❌ 不挂 cron 自动跑（LLM 密集任务，手动/事件驱动触发）
