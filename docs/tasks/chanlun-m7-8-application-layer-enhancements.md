# M7-8 应用层增强：量能验证 + 市场状态识别 + 因子排序

> 设计依据：`framework/proposals/2026-08-30-methodology-three-layer-upgrade.md`（完整立项文档）
> 前置：M7-1~M7-7 全部完成（chan_engine 多周期引擎已稳定运行）
> 性质：**应用层增量**，不改 chan_engine 内核，只在双引擎脚本（`qing_position_dual_analysis.py`）层面扩展
> 日期：2026-08-30

---

## 一、定位与动机

M7-1~M7-7 解决"缠论引擎怎么算"的问题（数据层/对齐/理论补全/递归/skill接入/线段/递归统一）。
M7-8 解决"算出来之后怎么用"的问题——在引擎输出（latest.json m7_report）之上叠加三个应用层模块：

```
┌─────────────────────────────────────┐
│  M7-8-3 因子排序（选股层）           │  ← 方向池内标的评分排序
├─────────────────────────────────────┤
│  M7-8-2 市场状态识别（状态分类器）    │  ← A/B/C 三状态前置判断
├─────────────────────────────────────┤
│  M7-5 chan_analysis.py（引擎输出层） │  ← 已有，不改动
├─────────────────────────────────────┤
│  M7-1~M7-4/M7-6 引擎核心            │  ← 已有，不改动
├─────────────────────────────────────┤
│  M7-8-1 量能验证（引擎输出后处理层）  │  ← 三级量能确认
└─────────────────────────────────────┘
```

**为什么不改内核**：chan_engine 的输出（state_plan/backchi/defense_lines 等）已足够稳定，
应用层的量能/状态/排序都是对引擎输出的**消费**，不是对引擎算法的修改。
改内核需要过 claims 校准门；改应用层只需要回测验证。

## 二、三个子模块

### M7-8-1 量能验证（P0）

**目的**：缠论背驰（MACD 面积递减）是滞后指标，需要更前置的量能确认。

**实现**：`qing_position_dual_analysis.py` 新增 `compute_volume_profile(code, state_plan)`

**三级确认**：

| 级别 | 字段 | 逻辑 | 数据源 |
|------|------|------|--------|
| 中枢离开 | `leave_volume_ratio` + `leave_label` | vol/MA5_vol ≥1.2=放量(真突破) ≤0.8=缩量(无确认) | chan_bars.db 日线 vol |
| 回试确认 | `retest_volume_ratio` + `retest_label` | 近3日均量/MA5_vol ≤0.8=缩量回试(有效) ≥1.2=放量回试(谨慎) | chan_bars.db 日线 vol |
| 背驰量能 | `backchi_volume_trend` | 近5日后半段 vs 前半段，递减=配合背驰 | chan_bars.db 日线 vol |
| 辅助 | `vol_60m_ratio` | 60m 最新量/MA5(60m) | chan_bars.db 60m vol |

**回测结论（2026-08-30，282 个事件）**：

| 规则 | 准确率 | 基线 | 判定 |
|------|--------|------|------|
| 放量≥1.2→真突破 | **79%** | 73% | ✅ 成立 |
| 放量≥1.5→真突破 | **85%** | 73% | ✅ 强确认档 |
| 放量≥1.5→真破位(向下) | **100%** | 64% | ✅ 放量杀跌=立即风控 |
| 缩量≤0.8→假突破 | **31%** | — | ❌ **证伪，改为"无确认中性"** |

**关键修正**：缩量离开≠假突破（方向反了），真实语义=无资金确认（中性观望）。
缩量阴跌反而增强破位有效性（无承接，惯性延续）。

**配置同步**：`strategy_pack.yaml` → `stock_volume_checks` 7 条规则 + `combo_rules` 3 条组合。

### M7-8-2 市场状态识别（P1）

**目的**：缠论在极端单边市中枢来不及形成（中枢失效），需要一个前置状态分类器
决定当前是否该用缠论分析。

**实现**：`qing_position_dual_analysis.py` 新增 `compute_market_state(code, boll_rows)`

**双确认架构（v3，回测准确率 94%）**：

```
判定优先级（高→低）：
1. 个股事件：当日涨跌幅|>7%（涨跌停附近）→ B
2. 市场B + 标的极端：指数跌<-1.5% AND 标的ATR分位≥90%/跌<-5%/振幅>10% → B
3. 市场B：指数暴跌 → 全局防守 → B
4. C：band_pct 近60日分位≤10% → 收敛变盘临近
5. A：默认
```

**关键设计决策**：
- "极端单边市"是市场级现象，不是标的级现象——单标的 ATR 分位无法捕捉系统性暴跌
  （ETF 篮子分散波动，标的 ATR 分位可能仅 2-50%）
- 妖股豁免（001258 立新 ATR 分位常年 85-100%）：用"当日跌幅<-5%"和"振幅>10%"
  替代 ATR 分位做标的极端判据

**三轮迭代**：

| 版本 | 判据 | 准确率 | 问题 |
|------|------|--------|------|
| v1 | ATR 绝对阈值(3%/5%) | — | ETF 基线 3.4-4.8% 使阈值失效 |
| v2 | ATR 历史分位(≥90%) | 64% | 单标的判不出系统性暴跌 |
| v3 | 市场级+标的级双确认 | **94%** | ✅ 达标 |

### M7-8-3 因子排序（P2）

**目的**：缠论解决"什么时候买/卖"，不解决"买什么"。方向池内标的缺横向比较。

**实现**：`scripts/factor_rank.py`

**三维评分**：

| 维度 | 权重 | 因子 | 数据源 |
|------|------|------|--------|
| 动量 | 40% | 20日涨幅 rank + 60日涨幅 rank | 日线 K 线 |
| 波动率 | 30% | ATR14/close rank + band_pct rank | 日线 K 线 + 布林 |
| 缠论结构 | 30% | 中枢位置评分 + 买卖点类型评分 + 背驰类型评分 | chan_engine analyze_code |

**首次运行结果（2026-08-30，方向池 70 只，Top 5）**：

| 排名 | 代码 | 名称 | 方向 | 20日% | 总分 | 缠论结构 |
|------|------|------|------|-------|------|----------|
| 1 | 512400.SH | 有色金属ETF | 持仓ETF | +10.6 | **81.3** | 60m/30m全中枢上方 |
| 2 | 517520.SH | 黄金股ETF | 持仓ETF | +20.9 | 78.4 | 60m/30m全中枢上方 |
| 3 | 600378.SH | 昊华科技 | WF6涨价 | +33.8 | 78.0 | 日线中枢上方 |
| 4 | 601699.SH | 潞安环能 | 煤炭涨价 | +13.2 | 76.4 | 日线中枢上方 |
| 5 | 603938.SH | 三孚股份 | WF6涨价 | +30.2 | 72.9 | 60m/30m全中枢上方 |

**已知限制**：
- 缠论分钟线缺失（仅持仓 10 只有分钟线，其余仅日线粗粒度）
- 大单净流入缺失（东财接口不稳定，降级为纯价格动量）
- 权重 40/30/30 为初始值，未回测校准
- 5 只数据不足（次新/停牌）

## 四、数据流

```
chan_bars.db（日线+分钟线）
  ├── chan_engine analyze_code → m7_report（state_plan/backchi/defense_lines/...）
  ├── compute_volume_profile → volume_profile（leave/retest/backchi 量能三级确认）
  ├── compute_market_state → market_state（A/B/C + metrics）
  └── boll7 calc_boll7 → boll_day（七轨+ band_pct + signals）

factor_rank.py 独立入口：
  watchlist.yaml → 75 只标的 → 三因子评分 → 排序输出
```
