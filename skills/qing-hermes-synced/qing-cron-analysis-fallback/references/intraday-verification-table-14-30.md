## 关键步骤

1. **取当日 claims**：`mcp__neo4j__get_recent_claims(days=1)`，重点找 `claim_type=operation` 的
   "验证变量"类 claims（如 claim-20260804-020 五个盘中验证变量）+ 情形A/情形B claims。
2. **逐项实测**：每个变量配 1-3 个代表标的的实时 quote + 量能/宽度数据，注明采样时间戳。
3. **判定情形**：多数变量 ✅ → 情形A（正反馈落地）；变量 3 量能不升反降 → 情形B。
4. **操作提示以条件句写**：不是"买/卖"，而是"若明日量能≥2万亿+涨停维持 → 回踩观察；若 <1.9万亿+首板下滑 → 情形B，做T为主"。

## 结论书写顺序（本次验证有效）

## 坑位补充

- 科创50 裸代码 `get_quote("000688")` mis-resolve（价格 29 而非 1612）→ 用 fetcher 带 `1.000688`。
- daily_state.json 含控制字符 → `json.loads(raw, strict=False)`，read_file 工具会 JSONDecodeError。
- 指数间细微涨幅差异（+3.84% vs +4.05%）多为采样时点差，报告声明时间戳即可。
- **TDX fetcher 低价 ETF 价格 ×10**（2026-08-14 实测）：588780/588170/159516 等 1 元级 ETF 返回 10.09/10.19/7.39（实际 1.009/1.017/0.740），涨幅正确仅绝对价错 → 算持仓盈亏前必须腾讯 gtimg 复核（详见 SKILL.md 坑 6）。指数与高价股不受影响。
- **claims 全文 yaml 解析**：当日文件结构是 `claims:\n- id: claim-...`（**字段带 `- ` 前缀**），按 `re.split(r'(?m)^- id:\s*', txt)` 切块再取 `subject:/statement:/interpretation:`；用 `(?m)^(?=id:)` 会匹配不到（行首是 `- id:` 不是 `id:`）。核心验证变量常藏在 `interpretation:` 里，必须读全文不能只看 Neo4j 摘要。
- **昨日量能基准**：`daily_review_summary.json` 是**按日期为 key 的 dict**（`rev['2026-08-13']`），`market` 字段含 stage_detail（涨停/炸板率）+ key_levels，是昨日基准的权威本地来源；UP claims 量能描述（如 claim-005）作交叉验证。
