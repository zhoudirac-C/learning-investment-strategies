## 0. 背景与动机

### 问题定义

缠论的几何分解方法（笔→线段→中枢→背驰）在"价格结构+多级别分析"赛道仍是最完整体系，
但实战假设面临三个变化：

1. **量化交易普及** → 分钟级别笔结构噪音增大，假突破增多
2. **信息传播加速** → 中枢形成时间变短，情绪周期被压缩
3. **市场互联互通** → 外盘隔夜走势可瞬间改变 A 股开盘结构

结论：**缠论框架不过时，但单靠缠论不够**。需要在缠论的上方、下方、侧面各补一层。

### 与现有体系的关系

当前双引擎 = 缠论（结构择时）+ 七轨布林（状态过滤）。三层升级是在此基础上的扩展：

```
┌─────────────────────────────────────────────────┐
│  第三层：选股补充 — 因子模型/资金流向 rank        │  ← 新增
├─────────────────────────────────────────────────┤
│  第一层：市场状态识别 — 缠论之上的状态分类器      │  ← 新增（布林带已覆盖部分）
├─────────────────────────────────────────────────┤
│        缠论核心：中枢 + 级别 + 背驰               │  ← 现有
├─────────────────────────────────────────────────┤
│  第二层：订单流验证 — 缠论之下的量能/订单流确认    │  ← 新增（量能判断已覆盖部分）
└─────────────────────────────────────────────────┘
```

## 1. 第一层：市场状态识别器（缠论之上）

### 1.1 要解决的问题

缠论默认"中枢总会形成"——但在以下场景中中枢来不及形成或已被外力打破：

| 场景 | 缠论表现 | 根因 |
|------|----------|------|
| 极端单边市（连续涨停/千股跌停） | 无中枢可分析，笔延伸不停 | 供需极端失衡，无平衡区间 |
| 跳空缺口大（隔夜外盘冲击） | 日线笔被跳空直接打断 | 信息在一夜之间 price-in |
| 流动性极低标的 | 笔被少数大单扭曲 | 参与者不足以形成有效中枢 |

### 1.2 设计方案

**状态分类器 = 三状态自动判定**

```
状态 A：正常趋势市
  → 缠论有效，正常运行双引擎
  → 判定条件：日线 ATR/收盘价 < 3%（波动率正常区间）

状态 B：极端单边市
  → 缠论失效，切换到布林轨道+量能极值模式
  → 判定条件：日线 ATR/收盘价 > 5%，或连续 3 日单方向幅度 > 累计 8%
  → 操作模式：不判中枢，只用布林轨道位置（接近顶轨=减仓区/接近底轨=观望区）
              + 量能极值（天量=出货信号/地量=底部信号）

状态 C：震荡收敛市
  → 缠论中枢内无买卖点，需要判定变盘方向
  → 判定条件：布林 band_pct < 20%（或近 60bar 第 10 百分位以下）
  → 操作模式：等方向选择，放量突破中枢上沿+布林中轨上方才跟；
              缩量在中枢内不动
```

### 1.3 与现有体系的衔接

- **布林带已覆盖状态 B 和 C 的部分功能**：`band_pct` 收敛信号 + 二轨失守信号已在双引擎中运行
- **缺的是状态 A↔B↔C 的自动切换逻辑**：当前是人工判断"今天是极端行情还是正常行情"，需要改为规则化
- **实施路径**：
  1. 在 `qing_position_dual_analysis.py` 中增加 `market_state` 字段（A/B/C + 判定依据）
  2. 根据 state 切换报告模板：A=正常双引擎 / B=布林轨道模式 / C=收敛变盘模式
  3. 在 positions.yaml 的 `today_plan` 中增加状态标签

### 1.4 验收标准

- [x] `latest.json` 新增 `market_state` 字段，值为 A/B/C + 判定依据文本
- [x] 状态 B 时报告不引用缠论中枢（因为中枢无效），只给布林轨道+量能
- [x] 状态 C 时报告增加"变盘方向"提示（放量突破方向 = 跟踪方向）
- [x] 回测 2026-08 月数据，状态分类与人工复盘一致率 > 80%（实际 **94%**，35 个测试点）

### 1.5 回测结论与架构修正（2026-08-30）

**三轮迭代**：

| 版本 | 判据 | 准确率 | 问题 |
|------|------|--------|------|
| v1 | ATR绝对阈值(3%/5%) + 3日单边8% | — | ETF基线3.4-4.8%使阈值失效；001258妖股ATR常年>5%误判 |
| v2 | ATR历史分位(近60日≥90%) + 3日单边8% + 当日跌<-3%/振幅>8% | 64% | 8/12-13非暴跌日（误标）；大盘暴跌时个股/ETF标的级判不出 |
| v3 | **市场级(上证)+标的级双确认** | **94%** | ✅ 达标 |

**v3 判定逻辑（最终版）**：

```
优先级（高→低）：
1. 个股事件：当日涨跌幅|>7%（涨跌停附近）→ B
2. 市场B + 标的极端：指数当日<-1.5% 或 3日单边>5%
   AND 标的 ATR分位≥90% / 当日跌<-5% / 振幅>10% → B
3. 市场B（无标的极端）：指数暴跌 → 全局防守 → B
4. C：band_pct 近60日分位 ≤ 10% → 收敛变盘临近
5. A：默认
```

**关键设计决策**：
- "极端单边市"是市场级现象，不是标的级现象。单标的 ATR 分位无法捕捉系统性暴跌
  （如 8/19 上证 -2.4% 时，多数 ETF 的 ATR 分位仅 2-50%，因 ETF 篮子分散了波动）
- 001258 立新（妖股）ATR 分位常年 85-100%，属于"常态高波动"→ 用"当日跌幅<-5%"和"振幅>10%"
  替代 ATR 分位作为标的极端判据（妖股的 ATR 分位高不=市场异常）
- 标的极端阈值比原设计更严（-5% vs -3%，振幅>10% vs >8%）→ 减少误判

**8/19 暴跌日回测**（唯一验证窗口）：
- 上证 -2.40% → 市场级 B 触发 ✅
- 大部分 ETF 当日 -1~-3% → 标的级未达极端阈值（不判个股B）但市场级已 B → 全局防守 ✅
- 立新 8/19 当日 -12.6%（涨跌停附近）→ 个股事件触发 B ✅

## 2. 第二层：订单流/量能验证（缠论之下）

### 2.1 要解决的问题

缠论的背驰（MACD 面积递减）是**滞后指标**——等 MACD 确认时价格已走了一段。
更前置的信号是：**中枢离开时的量能特征**。

当前体系已有 `volume_checks`（strategy_pack.yaml）和布林量能信号，
但未系统化到"中枢离开 = 量能阈值判定"层面。

### 2.2 设计方案

**量能验证 = 三级确认机制**

```
级别 1：中枢离开确认（最核心）
  → 价格离开中枢上沿/下沿时，量能必须 > 5日均量 × 1.2
  → 放量离开 = 真突破（可信，可跟）
  → 缩量离开 = 假突破（不可信，等回试）
  → 实施：在 chan_engine 的 state_plan 中增加 volume_confirm 字段

级别 2：回试量能确认
  → 价格回试中枢上沿（三买位）时，量能应萎缩（缩量回试 = 卖压不足）
  → 缩量回试不破 = 有效三买（可信，可加）
  → 放量回试 = 有承接但抛压也大（谨慎，等二次确认）
  → 实施：回试日的 volume vs 前一日 volume 比值

级别 3：背驰量能确认
  → MACD 面积递减（背驰）+ 量能同步递减 = 强背驰（高可信度反转）
  → MACD 面积递减 + 量能不递减 = 弱背驰（可能还有一冲）
  → 实施：在 backchi 判定中增加 volume_trend 字段
```

### 2.3 数据可行性

| 数据源 | 可得性 | 颗粒度 |
|--------|--------|--------|
| 成交量（VOL） | ✅ 已有，腾讯/东财 API | 日级别 + 分钟级别 |
| 成交额（AMOUNT） | ✅ 已有 | 日级别 + 分钟级别 |
| 换手率 | ✅ 已有 | 日级别 |
| Level2 盘口订单流 | ❌ 无数据源 | 需购买通达信Level2或第三方 |
| 大单/特大单净流入 | ⚠ 东财 datacenter 有接口 | 日级别（分钟级别不稳定） |

**结论**：级别 1-3 的量能确认用日级别/分钟级别成交量即可实现，
不需要 Level2 数据。订单流级别（盘口）暂不纳入（数据门槛高+成本高）。

### 2.4 与现有体系的衔接

- `strategy_pack.yaml` 的 `volume_checks` 已有量能规则，但偏定性（"放量"/"缩量"）
- 需要量化为阈值：放量 = `vol > MA5_vol × 1.2`，缩量 = `vol < MA5_vol × 0.8`
- 在 `chan_engine` 的 `analyze_code` 返回中增加 `volume_profile` 字段
- 在双引擎报告解读时增加"量能确认"维度（当前只有缠论结构 + 布林位置）

### 2.5 验收标准

- [x] `latest.json` 每只持仓新增 `volume_profile` 字段：`leave_volume_ratio`（中枢离开日量比）、`retest_volume_ratio`（回试日量比）、`backchi_volume_trend`（背驰时量能趋势）
- [x] 双引擎报告中增加量能确认行：真突破/假突破/缩量回试/放量回试
- [x] `strategy_pack.yaml` 的 volume_checks 从定性升级为定量阈值
- [x] 回测验证（2026-08-30 执行，方法=20日箱体突破代理中枢离开+3日后真假判定，标的=10只持仓全年日线）

### 2.6 回测结论与阈值修正（2026-08-30）

**方法**：20日箱体突破作为"中枢离开"代理事件（缠论中枢≈价格密集区），
收盘破箱体=离开事件，3日后仍在箱体外=真突破/回落=假突破。
样本：10 只持仓 2026 全年日线，282 个事件（↑196 / ↓86）。

**结果**：

| 规则 | 窗口 | n | 准确率 | 基线 | 判定 |
|------|------|---|--------|------|------|
| 放量≥1.2→真突破 | 全年 | 103 | **79%** | 73% | ✅ +6pct 判别力成立 |
| 放量≥1.5→真突破 | 全年 | 33 | **85%** | 73% | ✅ 阈值越高越可靠 |
| 放量≥1.5→真破位 | 全年(向下) | 6 | **100%** | 64% | ✅ 放量杀跌=真破位极可靠 |
| 缩量≤0.8→假突破 | 全年 | 16 | **31%** | — | ❌ **方向反了，规则作废** |
| 放量≥1.2 | 8月单月 | 3 | 67% | 18% | ⚠ 样本太少 |
| 放量≥1.2 | 6-8月 | 36 | 72% | 63% | ✅ |

**关键发现——缩量规则的语义修正**：

原假设"缩量离开=假突破风险"被证伪（准确率仅31%，即 69% 的缩量跌破 3 日后仍有效）。
真实语义：**缩量=无资金确认（中性）**，不是反指——
- 向上缩量突破：真突破率 62% vs 基线 77% → 确实减弱，但仍是多数成立，只是"不确认"而非"反转"
- 向下缩量破位：真破位率 75% vs 基线 64% → 反而增强（缩量阴跌=无承接，惯性延续）

**方向不对称性**：向下破位对量能更敏感（放量≥1.5 时真破位率 100%），
向上突破即使放量也只到 80%——因为 A 股下跌动量天然强于上涨动量。

**修正后的规则（已同步 strategy_pack.yaml）**：

| 规则 | 修正前 | 修正后 |
|------|--------|--------|
| 放量≥1.2 离开 | 真突破可跟 | **真突破可跟**（79% 验证通过，保持） |
| 放量≥1.5 离开 | （无） | **强确认**（85%/100%，新增强化档） |
| 缩量≤0.8 离开 | 假突破风险 | **无资金确认（中性观望），不作反向信号** |
| 缩量回试≤0.8 | 回试有效可加仓 | 缩量回试=卖压不足（保留，但需配合方向） |
| 放量杀跌≥1.5 | （无） | **真破位极可靠 → 立即执行风控不等反弹** |

**对 512400 有色的复盘校验**：08-28 leave=0.71（缩量离开）按修正规则=中性观望，
不再输出"假突破风险"误导信号；但其日线 trend_div + 背驰量能递减的卖出组合仍成立
（背驰量能是独立规则，不受本次修正影响）。

## 3. 第三层：选股层因子补充（缠论侧面）

### 3.1 要解决的问题

缠论解决"什么时候买/卖"，不解决"买什么"。

当前选股路径：UP 方向池 → ETF/个股映射 → 缠论择时。
缺的是**统计层面的因子筛选**——方向池内的标的之间没有横向比较。

### 3.2 设计方案

**因子补充 = 三维评分体系（非替代选股，是方向池内排序工具）**

```
维度 1：动量因子
  → 20日/60日涨幅 rank
  → 资金净流入（大单净额）5日/10日 rank
  → 用途：方向池内哪个标的动能最强

维度 2：波动率因子
  → ATR/收盘价（波动率）rank
  → 布林 band_pct rank
  → 用途：哪个标的处于收敛变盘临界（低 band_pct + 低 ATR = 变盘临近）

维度 3：缠论结构因子
  → 中枢位置（上方/内/下方）评分
  → 最近买卖点类型（一买/二买/三买）评分
  → 背驰类型（trend_div > consolidation_div）评分
  → 用途：哪个标的的缠论结构最有利
```

**综合评分 = 动量(40%) + 波动率(30%) + 缠论结构(30%)**

→ 输出：方向池内标的排序 + 推荐优先关注 Top 3

### 3.3 数据可行性

| 因子 | 数据源 | 可得性 |
|------|--------|--------|
| 20日/60日涨幅 | 腾讯行情 K 线 | ✅ 已有 |
| 大单净流入 | 东财 datacenter | ⚠ 日级别，分钟不稳定 |
| ATR | K 线计算 | ✅ 已有 |
| band_pct | 双引擎已计算 | ✅ 已有 |
| 缠论结构评分 | chan_engine 已有 | ✅ 已有 |

**结论**：全部因子数据已有或可从现有数据计算，不需要新数据源。

### 3.4 与现有体系的衔接

- **不替代 UP 方向池**：方向选择仍以 UP 方法论 + 独立判断为主
- **在方向池内增加排序**：同一方向下多个标的时，用因子评分排序优先关注
- **实施路径**：
  1. 新增 `scripts/factor_rank.py`：输入方向池标的列表 → 输出三维评分 + 综合排名
  2. 在收盘复盘中增加"因子排序"模块
  3. 不挂 cron（遵循用户偏好：批量 LLM 任务不自动跑），手动/事件驱动触发

### 3.5 验收标准

- [x] `scripts/factor_rank.py` 可运行，输入 watchlist.yaml 标的 → 输出评分表（70/75 只成功，5 只数据不足）
- [x] 评分表包含三维度分数 + 综合分 + 排名

## 4. 实施路线图

### 优先级排序

| 顺序 | 层 | 理由 | 预估工作量 |
|------|----|------|------------|
| **P0** | 第二层（量能验证） | 数据已有，改动最小，对当前持仓判断价值最高 | 2-3 天 |
| **P1** | 第一层（状态识别） | 布林带已覆盖部分，需要补的是自动切换逻辑 | 3-5 天 |
| **P2** | 第三层（因子评分） | 选股层面价值大但非紧迫，且依赖前两层稳定 | 5-7 天 |

### 依赖关系

```
第二层（量能验证）── 独立，无依赖
第一层（状态识别）── 依赖第二层的量能数据（状态 B 用量能极值）
第三层（因子评分）── 依赖第一层+第二层的输出（缠论结构+量能+波动率）
```

→ 先做第二层，再做第一层，最后做第三层。

### 不做的事（明确边界）

- ❌ 不引入 Level2 盘口数据（成本高+门槛高）
- ❌ 不引入机器学习预测模型（过拟合风险 > 收益）
- ❌ 不替代缠论核心（中枢+级别+背驰仍是择时主干）
- ❌ 不替代 UP 方向池（因子评分是排序工具，不是选股替代）
- ❌ 不挂 cron 自动跑因子评分（遵循用户偏好：手动/事件驱动触发）

## 5. 风险与不确定性

| 风险 | 影响 | 缓解 |
|------|------|------|
| 量能阈值 1.2x/0.8x 是拍脑袋值 | 级别 1 误判 | 用 2026-06~08 数据回测校准 |
| 状态分类器 ATR 阈值 3%/5% 是拍脑袋值 | 状态误判 | 同上，回测校准 |
| 因子权重 40/30/30 是拍脑袋值 | 排序不准 | 先用等权(33/33/33)跑一轮，看结果再调 |
| 东财大单净流入接口不稳定 | 因子维度 1 数据缺失 | 降级为只用量能+缠论结构二维评分 |
