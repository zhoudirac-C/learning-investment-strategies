# 个股深度分析 — 竞价+盘前数据层 + Prompt 差异化设计文档

> 版本: 2026-06-11 v1.0
> 触发: 用户要求看盘定时任务对持仓个股做竞价组合+分时形态级别分析
> 目标: 每个时间节点的 LLM 输出，从"风控巡检+简短备注"升级为"持仓重点股深度分析+大盘/观察池精简"

## 1. 数据采集层

### 1.1 昨日特征摘要 (_yesterday_summary)

**数据源优先级**：
1. `15:20 收盘复盘 cron` 写入的结构化 `config/stock_monitor/daily_review_summary.json`（最完整）
2. `config/stock_monitor/state.json` 的 `last_quote_snapshot`（收盘行情快照，无分时分析字段）
3. K 线缓存 SQLite 的第 N 日数据 + 腾讯财经 API 兜底（最不完整，仅 OHLC）

**设计原则**：收盘复盘 cron 调用 Qing-Agent 分析后，由 `stock_monitor.py` 从复盘输出和行情快照中自动提取并写入 summary 文件。次日的 poll / agent cron 直接读取 summary，不再重新采集。若 summary 不存在（如复盘 cron 失败），fallback 到 state.json + API。

**字段清单**（18 个，分 4 类）：

#### A. 基础行情（7 项，所有来源都可提供）

| 字段 | 键名 | 示例 | 来源 |
|------|------|------|------|
| 昨收 | `close` | 134.81 | 所有来源 |
| 今开 | `open` | 126.22 | 所有来源 |
| 最高 | `high` | 134.81 | 所有来源 |
| 最低 | `low` | 124.00 | 所有来源 |
| 涨跌幅 | `change_pct` | 10.00 | 所有来源 |
| 成交量 | `volume` | 576461 | 所有来源 |
| 成交额 | `amount` | 75.05亿 | state.json + API |

#### B. 板/封板特征（4 项，仅 summary 可完整提供）

| 字段 | 键名 | 示例 | 含义 |
|------|------|------|------|
| 是否涨停 | `is_limit_up` | true | 收盘是否为涨停 |
| 连续涨停天数 | `consecutive_limit_ups` | 2 | 含今天的累计连续板数 |
| 烂板标记 | `weak_board` | true | 盘中是否开板后回封 |

### 1.2 竞价快照 (_auction_snapshot)

**采集时间**：09:25:05（集合竞价结果生成的瞬间）
**数据源**：腾讯财经 API (竞价阶段可用) 或 东方财富 竞价 API

| 字段 | 键名 | 示例 | 含义 |
|------|------|------|------|
| 竞价价格 | `auction_price` | 130.50 | 集合竞价撮合价格 |
| 竞价涨跌幅 | `auction_change_pct` | -3.2 | 相较昨收的涨跌% |
| 竞价成交量 | `auction_volume` | 21000 | 竞价阶段成交量(手) |
| 竞价量占比 | `auction_volume_ratio` | 0.35 | 竞价量/近5日竞价量均值 |
| 竞价末5分钟趋势 | `last5min_trend` | "pull_up" | last 5 min 价格方向(pull_up/stabilize/push_down) |
| 竞价买卖盘差 | `auction_order_delta` | "+300万" | 买盘-卖盘金额差 |

### 1.3 数据流

```
15:20 收盘复盘 cron (LLM)
    │  输出：复盘分析文本 + 结构化复盘数据
    ▼
stock_monitor._build_yesterday_summary()
    │  从 state.json 的 last_quote_snapshot 提取基础行情
    │  从 daily_state.json 提取市场阶段、方向判断
    │  从策略包提取 entry_zone 状态
    ▼
config/stock_monitor/daily_review_summary.json  ← 持久化

次日 06:30: K线预拉取 cron
    │  补充 MA5/MA10 等均线计算
    ▼
次日 09:26 竞价记录 cron
    │  读取 summary + 拉竞价数据
    ▼
JSON 上下文 → LLM 分析
```

## 2. Prompt 差异化

### 2.1 篇幅分配

**之前**（总计 ~450 字）：

```
盘面/大盘: ~100字 (22%)
持仓池: ~200字 (44%)
观察池: ~100字 (22%)
脚注: ~50字 (11%)
```

**改成**（总计 ~600 字）：

```
【盘面】: ~50字 (8%)   ← 大幅精简
【重点分析】: ~300字 (50%) ← 新增，个股深度
【其他持仓】: ~60字 (10%)  ← 精简
【观察池】: ~40字 (7%)    ← 精简
【脚注】: ~50字 (8%)
缓冲：~100字 (17%)
```

### 2.2 各时间节点 Prompt 特异化

#### 09:26 竞价后（竞价数据）

```
【角色】你现在看到的是集合竞价数据（09:25 撮合结果）。
前15分钟的量能和价格运动尚未出现。

【Focus】
- 竞价价格相对于昨收的位置（高开/低开）
- 竞价成交量是否异常放大
- 竞价最后5分钟的价格方向（拉升/稳定/打压）
- 持仓股中哪些竞价异常最突出

【输出】
📊 大盘竞价定性（15字）
📊 持仓重点分析（1-2只竞价最异常的标的，每只60-80字，
   说清竞价特征 + 开盘后验证条件）
📋 观察池信号（15字）

【禁止】不要给"持有/减仓"结论，此刻还没开始交易。
```

#### 09:45 开盘15分钟（竞价+前15分钟验证）

```
【角色】你现在看到的是竞价+开盘前15分钟数据。
可以用前面定好的框架：竞价特征 + 前15分钟是否验证。

【框架】（重点个股自动套用）
| 竞价+前15分钟 | 含义 |
|--------------|------|
| 小幅低开(-1~-3%)+15分钟缩量企稳 | 正常获利了结 |
| 大幅低开(<-5%)+15分钟无承接 | 恐慌出逃 |
| 平开/高开+15分钟放量上攻 | 换手接力 |
| 竞价跌停拉回+15分钟翻红 | 资金抢筹 |

【Focus】
- 昨日特征（连续涨停/烂板/换手率/振幅）决定今日分析框架
- 竞价特征 + 15分钟量能变化构成分析输入
- 同板块标的（confirm_with）并列验证

【输出】
📊 大盘定性（20字）
📊 持仓重点分析（1-2只昨日特征最突出+今日竞价最异常的标的，每只80-100字）
📊 其他持仓（每只15字）← 动作+触发+证伪
📋 观察池（10字，有触发写条件，没有写空）
```

#### 10:30 30分钟确认（早盘方向确认）

```
【角色】30分钟数据。前15分钟的短暂波动已被消化，
现在可以判断今日主基调。

【Focus】
- 前15分钟的方向是否被30分钟数据验证？
- 出现了哪些关键信号？哪些在走弱？
- 有没有标的出现方向性变化？

【输出】
📊 早盘定性（30字）← 比09:45长一些，可以判断基调了
📊 个股分析（1-2只关键票，70-100字）
📊 其他持仓（每只15字）
📋 观察池（如果出现了新的介入范围内的，可以多说一点，最多60字）
```

#### 14:00 午盘（午后验证）

```
【角色】午后数据。验证上午方向是否延续。

【Focus】
- 下午是否拉回还是加速？
- 有没有出现"上午假象、下午反转"的情况？
- 持仓票是否触发风控条件？

【输出】
📊 午后判断（20字）
📊 个股分析（1-2只关键票，70-80字）
📊 持仓风控（仅触发风控的票，每只20字）
```

#### 14:52 尾盘（收盘决策）

```
【角色】尾盘数据。决定持仓过夜策略。

【Focus】
- 今日是否出现了条件单触发信号？
- 烂板票是否该减仓？
- 哪些票适合持有过夜？

【输出】
📊 今日总结（20字）
📊 个股回顾（每只持仓30-40字，回顾今日表现+明日展望）
📊 尾盘操作建议（如有触发条件）
```

## 6. 业界参考框架（评审补充）

> 补充日期：2026-06-11
> 来源：淘股吧竞价图形实战、盘口资金时钟体系、职业短线手复盘工作流

### 6.1 淘股吧"竞价图形实战"核心规则

- **竞价涨幅≥5%，振幅≤5%，回落时最低涨幅≥4%** → 符合抢筹条件
- **竞价成交量/昨日全天成交量**：高开3-5%需≥50%，高开7-9%需≥66%
- **直接开涨停（10%）建议回避**，5-9%高开反而更有性价比
- **9:20前可撤单，9:20后才是真实资金意图** → 必须采集9:20-9:25的价格轨迹，而非仅看最终撮合价

### 6.2 "盘口资金时钟"体系关键信号

- 集合竞价巨量买单压顶 + 高开3-5% + 未明显回落 → 资金抢筹
- 首笔成交即放量（换手率>8%）+ 15分钟内主力净流入 → 确认强势
- 阶梯式堆量（连续5分钟量能递增20%）→ 主力建仓痕迹
- 脉冲式放量（单分钟>日均量10%）→ 对倒嫌疑

### 6.3 职业短线手"复盘→次日预案"工作流

收盘后三轮工作：
1. 复盘自选股梯队（核心20只晋级/剔除）
2. 16:00 复盘当日涨停股和7%以上股
3. 17:00 复盘龙虎榜（资金性质、席位风格、锁仓/出局行为）

开盘前：根据前晚信息做**预设名单**，9:20-9:25看竞价验证。

**启示**：收盘复盘应输出"明日剧本"（强修复/弱震荡/强分歧的概率和条件），次日竞价分析才有对比基准，而非从零开始。

## 7. 数据层修改建议（评审补充）

### 7.1 `_auction_snapshot` 增加关键字段

当前6个字段不足以支撑"竞价阶段是否出货/抢筹"的判断，需补充：

| 新增字段 | 键名 | 示例 | 含义 |
|---------|------|------|------|
| 竞价阶段振幅 | `auction_amplitude` | 4.5 | 9:15-9:25最高涨幅%-最低涨幅% |
| 9:20-9:25最高涨幅 | `last5min_high_pct` | -1.2 | 不可撤单阶段最高涨幅% |
| 9:20-9:25最低涨幅 | `last5min_low_pct` | -5.7 | 不可撤单阶段最低涨幅% |
| 竞价量/昨日成交量 | `auction_vs_yesterday_volume` | 0.08 | >5%异常，>10%需警惕 |
| 未匹配买/卖单比 | `unmatched_buy_ratio` | 2.3 | 9:24:50未匹配买单÷卖单 |
| 竞价轨迹描述 | `auction_trend_920_925` | "pull_up_then_push" | 具体轨迹，非简单方向 |

> **为什么重要**：9:20前可撤单，存在主力"假单制造价格假象"行为。只看9:25最终价格无法识别"竞价从跌停拉到-2%再从-2%压到-5%"这种博弈过程，而该过程直接揭示真实资金意图。

### 7.2 `_yesterday_summary` 细化涨停/烂板相关字段

对于涨停/烂板持仓，次日竞价分析必须结合龙虎榜席位性质：

| 新增/细化字段 | 键名 | 示例 | 含义 |
|-------------|------|------|------|
| 封板质量 | `board_quality` | "weak" | strong/medium/weak/NA |
| 龙虎榜席位性质 | `dt_seat_type` | "机构+游资" | 机构/游资/量化/混合 |
| 买一行为 | `dt_top_buy_behavior` | "锁仓" | 锁仓/加仓/出局/做T |
| 是否纯游资主导 | `dt_is_pure_hot_money` | false | 纯游资→次日砸盘概率高 |
| 持仓成本 | `cost_basis.avg_cost` | 118.5 | 从 positions.yaml 注入 |
| 当前浮盈 | `cost_basis.unrealized_pct` | +8.2 | 浮盈%，负数为浮亏 |
| 成本保护线 | `cost_basis.cost_protection_line` | 122.0 | 浮盈回撤容忍阈值 |

> **为什么重要**：同样的-3%低开，浮盈15%和浮亏8%的操作完全不同。LLM必须知道持仓成本才能给出合理的"持有/减仓/止损"建议。

### 7.3 板块分析从"均涨幅"升级为"梯队对比"

将 `sector_avg_change` 扩展为板块梯队数据：

```yaml
sector_tier:
  tier1_code: "002409.SZ"    # 板块龙一
  tier1_auction_pct: +5.2    # 龙一竞价涨幅
  tier2_code: "688300.SH"    # 板块龙二
  tier2_auction_pct: +1.5    # 龙二竞价涨幅
  tier3_code: "600500.SH"    # 板块龙三
  tier3_auction_pct: -2.1    # 龙三竞价涨幅
  avg_change: +1.5           # 板块平均涨幅（保留）
```

> **为什么重要**：龙一高开+5%、龙二低开-2% → 你的持仓是板块唯一强者，可以留。龙一低开-3%、龙二也低开-4% → 板块性出货，操作要更果断。该功能已实现于 `_build_sector_tiers()`，数据在 `positions[].sector_tier`。

### 7.4 龙虎榜全市场总榜交叉校验

**数据源**：akshare `stock_lhb_detail_em()` — 东方财富龙虎榜全市场总榜
**采集时机**：15:20 收盘复盘 cron（与 `_build_yesterday_summary()` 同步）
**调用频率**：每日1次，1个API获取全部上榜股票

**为什么需要总榜而不是只查持仓**：
- 持仓股的竞争对手（同板块/同方向）可能上榜但持仓本身未上榜
- 观察池标的可能突然上榜（机构/游资介入），需要次日09:26提醒
- 连板票的**产业链上下游**可能因联动效应上榜，持仓股的主角地位可能变化
- 全市场净买入TOP榜直接揭示当日资金流向

**新增输出字段**（接入 context 的 `market_snapshot` 下）：

| 字段 | 键名 | 示例 | 含义 |
|------|------|------|------|
| 全市场龙虎榜 | `dragon_tiger_board` | list[dict] | 当天所有上榜股票精简摘要 |
| 持仓/观察池上榜标记 | `watch_dt_items` | list[str] | 持仓或观察池中上榜的标的及简要数据 |
| 全市场净买入TOP5 | `dt_nettop5` | list[dict] | 全市场净买入额前5的股票 |
| 同方向净买入总和 | `dt_sector_summary` | str | 持仓所属方向的龙虎榜资金汇总 |

**过滤逻辑**：
- 全市场总榜 → 过滤出 `代码` 属于 `持仓池∪观察池` 的行 → 标记 `watch_dt_items`
- 全市场总榜 → 按 `龙虎榜净买额` 排序取TOP5 → `dt_nettop5`
- 全市场总榜 → 按持仓所属 `theme_id` 汇总净买入 → `dt_sector_summary`

**数据结构**：

```python
# 注入 agent context 的 market_snapshot 下
"market_snapshot": {
    "dragon_tiger_board": [
        {"code": "002409", "name": "雅克科技", "net_buy": "+8.18亿",
         "reason": "日涨幅偏离值达7%", "seat_type": "外资+机构+量化"}
    ],
    "watch_dt_items": [     # 仅持仓+观察池上榜的
        "002409 雅克科技 +8.18亿 外资+机构+量化"
    ],
    "dt_nettop5": [         # 全市场净买入TOP5
        {"code": "002409", "name": "雅克科技", "net_buy": "+8.18亿"}
    ],
    "dt_sector_summary": {
        "ccL_resin_upstream": {"total_net": "+10.2亿", "stocks": ["002409"]}
    }
}
```

### 7.3 板块分析从"均涨幅"升级为"梯队对比"

将 `sector_avg_change` 扩展为板块梯队数据：

```yaml
sector_tier:
  tier1_code: "002409.SZ"    # 板块龙一
  tier1_auction_pct: +5.2    # 龙一竞价涨幅
  tier2_code: "688300.SH"    # 板块龙二
  tier2_auction_pct: +1.5    # 龙二竞价涨幅
  tier3_code: "600500.SH"    # 板块龙三
  tier3_auction_pct: -2.1    # 龙三竞价涨幅
  avg_change: +1.5           # 板块平均涨幅（保留）
```

> **为什么重要**：龙一高开+5%、龙二低开-2% → 你的持仓是板块唯一强者，可以留。龙一低开-3%、龙二也低开-4% → 板块性出货，操作要更果断。

## 8. Prompt 层修改建议（评审补充）

### 8.1 09:45 Prompt 增加"持仓类型分支框架"

当前所有持仓股用同一套分析框架，但实战中**不同类型的持仓，次日竞价逻辑完全不同**。Prompt 应根据 `_yesterday_summary` 自动选择分支：

#### 分支A：连板持仓（consecutive_limit_ups ≥ 2）

```
【连板竞价验证框架】
- 竞价高开≥5% 且 auction_vs_yesterday_volume ≥ 50% → 符合预期，持有等板
- 竞价高开<3% 或 auction_vs_yesterday_volume < 30% → 低于预期，开盘15分钟不翻红即减仓
- 竞价低开 → 直接触发止盈/止损评估
- 同梯队竞争标的出现更强竞价 → 你的持仓可能被卡位，需警惕
```

#### 分支B：烂板持仓（weak_board = true）

```
【烂板次日处理框架】
- 竞价低开>-2% 且 last5min_trend = pull_up → 有承接，观察30分钟
- 竞价低开<-3% 且 unmatched_buy_ratio < 1 → 无承接，开盘即减仓
- 竞价高开 → 超预期，但需前15分钟确认不是诱多（放量冲高回落=诱多）
- 封成比<0.1且龙虎榜买一出局 → 次日低开概率极高，竞价即减仓
```

#### 分支C：趋势持仓（均线多头，非涨停股）

```
【趋势均线验证框架】
- 竞价在MA5上方 + 前15分钟缩量 → 正常获利盘释放，持有
- 竞价跌破MA5 + 前15分钟放量 → 趋势可能破坏，减仓观察
- 竞价跌破MA10 + 同板块同步走弱 → 板块性问题，止损
```

#### 分支D：浮亏持仓（unrealized_pct < 0）

```
【风控优先框架】
- 浮亏<-5%且竞价继续低开 → 不抱幻想，开盘即评估止损
- 浮亏>-3%且竞价有承接（last5min_trend=pull_up）→ 给30分钟观察期
- 成本线就是心理线，不要让浮亏扩大为深套
```

### 8.2 收盘复盘增加"明日剧本"输出

收盘复盘 Prompt 应要求 LLM 输出次日三类情景，作为09:26的对比基准：

```json
{
  "tomorrow_scenarios": {
    "strong_repair": {
      "probability": "30%",
      "auction_signature": "全A高开>0.5%，竞价量放大，持仓股竞价符合预期",
      "action_if_match": "持仓不动，观察加仓机会"
    },
    "weak_consolidation": {
      "probability": "50%",
      "auction_signature": "全A平开±0.3%，竞价量正常，个股分化",
      "action_if_match": "做T为主，不新增净仓"
    },
    "strong_divergence": {
      "probability": "20%",
      "auction_signature": "全A低开>0.5%，竞价量萎缩或放量下杀",
      "action_if_match": "直接降仓，跌破risk_line执行风控"
    }
  }
}
```

09:26 Prompt 则应要求："根据昨日收盘复盘的'明日剧本'，判断当前竞价数据更符合哪个情景？如果与预判不符，说明哪里超预期/低于预期。"

### 8.3 09:45 Prompt 加入分时均价线和分钟级量能

```
【新增输入】
- first_15min.volume_by_5min: [12000, 8000, 6000]  # 每5分钟成交量
- first_15min.price_vs_vwap_at_0945: -0.8           # 当前价相对均价线偏差%
- first_15min.pattern: "放量下杀→缩量企稳"           # 分钟级量价结构

【分析要求】
- 区分"阶梯式堆量"（主力建仓）vs "脉冲式放量"（对倒诱多）
- 股价在均价线上方=多头控盘，下方=弱势
- 前15分钟缩量企稳=健康，放量下跌=危险
```

## 9. 优先级排序与实施建议

### 9.1 修改优先级

| 优先级 | 改动项 | 工作量 | 影响 |
|--------|--------|--------|------|
| **P0** | `_auction_snapshot` 增加 `auction_vs_yesterday_volume` 和竞价轨迹字段 | 中（API适配） | 直接决定竞价分析的准确性 |
| **P0** | Prompt 注入持仓成本/浮盈数据（从 `positions.yaml` 读取） | 小 | 同样的盘面，不同成本=不同操作 |
| **P1** | 09:45 Prompt 增加"持仓类型分支框架" | 中（Prompt重写） | 从"通用分析"升级为"因股施策" |
| **P1** | 收盘复盘增加"明日剧本"输出 | 中 | 让次日分析有对比基准 |
| **P2** | 龙虎榜席位性质 + 封成比细化 | 中（需新数据源） | 对涨停/烂板票次日预判很关键 |
| **P2** | 龙虎榜全市场总榜交叉校验 | 小（1个API） | 发现持仓/观察池未注意到的异动信号 |
| **P2** | 板块梯队对比（龙一/龙二/龙三竞价） | 中 | 区分"个股问题"还是"板块问题" |
| **P3** | 前15分钟分钟级量能 + 分时均价线 | 较大（需新数据采集） | 提升09:45分析的精准度 |

### 9.2 实施建议

**当前 v1.0 骨架是合格的**，建议按以下路径迭代：

1. **先落地 P0+P1**（工作量可控，影响最大）：
   - 补充竞价快照字段
   - 注入持仓成本
   - 重写 09:26/09:45 Prompt 加入分支框架和明日剧本验证

2. **跑3-5天实盘观察**，记录：
   - LLM 输出是否符合实际走势
   - 哪些"分支框架"判断准确，哪些误判
   - Token 成本是否超标

3. **再迭代 P2+P3**：
   - 根据实盘反馈，补充龙虎榜和板块梯队数据
   - 若09:45分析经常不准，再投入分钟级量能采集
