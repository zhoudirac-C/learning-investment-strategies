【14:00 午盘监控 — 节点专属指令】

【持仓池 vs 观察池 区分说明】
- 持仓池 = positions.yaml 中列出的股票，是你当前实际持有的仓位
- 观察池 = watchlist.yaml 中列出的股票，是你关注但尚未买入的标的
- 【严禁】将观察池标的当作持仓分析或给出持仓操作建议！
- 当前持仓状态已在上下文顶部标明，分析前务必确认

上午已经走完，现在进入午后。你需要做：
1. 对比上午预期和下午实际：上午的判断验证了吗？
2. 午后修复力度评估：强于/弱于/符合上午预期？
3. 是否出现尾盘杀风险？（指数持续走低、量能萎缩、跌停增加）
4. 持仓是否需要尾盘调整？（减仓/加仓/做T）
5. 今日机会扫描：有没有出现符合赔率要求的买入信号？

- 重点：假设验证 + 尾盘预案 + 机会扫描
- 必须包含：上午判断验证结果 + 午后走势评估 + 尾盘操作建议 + 今日机会扫描
- 字数：300字以内
- 格式：JSON

【⚠️ 强制要求：daily_state 输出】
分析完成后，必须在回复末尾输出以下代码块（不可省略！系统会自动解析此代码块记录观点连续性）：

```daily_state
{"market_stage":{"phase":"等修复","detail":"..."},"direction_priority":[{"direction":"...","intensity":"🔥🔥🔥"}],"position_stance":"空仓等待","intraday_narrative":[{"time":"14:00","summary":"一句话总结本节点观点"}]}
```

说明：
- `market_stage.phase`: 周期判断（等修复/强修复/弱修复/分歧/防御）
- `direction_priority`: 方向优先级数组，最多3个
- `position_stance`: 持仓态度（空仓等待/轻仓试探/重仓持有）
- `intraday_narrative`: 观点演进记录，time=节点时间，summary=一句话总结
