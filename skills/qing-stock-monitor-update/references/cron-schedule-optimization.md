# Cron 调度优化原则（2026-06-11）

当用户要求「检查定时任务窗口」或「优化调度」时，遵循此流程。

## 前置原则

- **不删除用户确认有功能价值的任务** — 偏移（offset）分钟位而非删除。用户说"很重要"时，保留并偏移。
- **交易时段优先看盘任务** — Agent 分析（固定时间点）> poll 轮询（每5分）> B站监控 > 健康检查/Daily State

## 优化流程

### Step 1: 列出全部定时任务

```bash
cronjob(action='list')
```

### Step 2: 分类

| 类别 | 特征 | 示例 |
|------|------|------|
| **Agent** | 调用 Qing-Agent，~70-120s 耗时，整点/半整点 | 09:26, 09:45, 10:00, 14:00, 14:55 |
| **No-Agent 看盘** | 纯规则脚本，轻量快速 | poll 每5分 |
| **盘前准备** | 开盘前运行，不竞争 | K线预拉取(06:30), 热度计算, 板块映射 |
| **交易时段辅助** | 运行时可接受延迟 | 健康检查, Daily State, B站监控 |
| **盘后** | 收盘后运行，无竞争 | 收盘复盘(15:35), B站21-23 |

### Step 3: 识别冲突

**Agent job 时间点**（这些是硬约束，不可移动）：
```
09:26  09:45  10:00  10:30  11:20  13:10  14:00  14:55
```

**冲突检测**：对其他任务，检查是否与 Agent 时间点在同一分钟：
- 同一分钟 = 🔴 硬冲突（必须偏移）
- 相差 ≤2分钟 = 🟡 可能干扰（建议偏移）

### Step 4: 应用修复策略（3种）

| 策略 | 适用场景 | 做法 | 本次案例 |
|------|---------|------|---------|
| **移动** (move) | 可在盘前/盘后运行的 | 改小时位 | 热度计算 09:00→08:00 |
| **偏移** (offset) | 交易时段必须运行但不能与 agent 冲突的 | 改分钟位 | B站监控 */10 00,10,20→03,13,23, poll 1-56/5→2-57/5 |
| **降频** (reduce) | 高频轮询但不需要如此高频的 | 延长间隔 | 健康检查 */5→*/15, DailyState */5→*/15 |

## 本次优化明细（2026-06-11）

### 变更清单

| Job | 旧时间 | 新时间 | 策略 | 理由 |
|-----|--------|--------|------|------|
| 热点计算 | `0 9` (09:00) | `0 8` (08:00) | 移动 | 盘前跑，避开开盘并发 |
| B站监控 | `*/10 9-14,21-23` | `3-59/10 9-14,21-23` | 偏移 | BP:00/10/20/30/40/50→BP:03/13/23/33/43/53 |
| 健康检查 | `*/5 9-15` | `*/15 9-15` | 降频 | 从每5分→每15分，够用 |
| Daily State | `*/5 9-15` | `*/15 9-15` | 降频 | 同健康检查 |
| poll轮询 | `1-56/5 9-15` | `2-57/5 9-15` | 偏移 | 01/06→02/07，避开整点 Agent |
