# pack 新增宏观事件日历（前瞻 5 个交易日）

## 差距事实

UP 在 10-11/10-12/10-13 连续三天的复盘中把宏观日历作为节奏锚点：

- 004-i / 011-k：「美国9月CPI 北京时间10月14日20:30公布，A股完整反馈落在10月15日；对科技估值要同步观察美债收益率实际反应，不能只看CPI同比数值」
- 001-m：布油 108/105 区间、10Y 美债 5.20-5.35% 与 30Y 分轨观察
- 001-n：摩根大通/富国/高盛/花旗财报看点排序

盲判 pack 的 `global_macro` 只有**当日快照**（隔夜已发生的数据），没有**未来 N 天将发生什么**——导致盲判无法做「数据公布前不加仓」「反馈落在次日」这类时点定价推理（UP 方法论中的关键一环）。

## 处置建议

1. **数据源调研**（先实测再选型，候选）：
   - 东财财经日历 API（datacenter `RPT_ECONOMIC_CALENDAR` 类接口，与现有估值 overlay 同域，凭证/反爬风险低）——首选验证
   - 金十/华尔街见闻日历抓取——反爬风险高，备选
   - 手工维护 yaml（CPI/FOMC/财报季日期高度规律，月度更新成本极低）——兜底且最稳
2. **落盘**：`infra/data/macro_calendar/YYYY-MM.json`（月度文件，事件=日期/时间/名称/重要性/前值/预期），cron 月初刷新 + 手工补丁。
3. **pack 注入**：`build_daily_pack` 增加 `macro_calendar_ahead` 块=未来 5 个交易日事件清单（回放安全：日历是预先公布的日程，无未来函数）。
4. **prompt 规则**（候选 v21 规则43，与规则25宏观三条件校验互补）：当 macro_calendar_ahead 含高重要性事件（CPI/FOMC/大厂财报）时，operation.basis 必须标注「数据前/数据后」时点定位，scenario 须给出事件前后分支。
5. **纪律对齐**：对应用户既有纪律「美数据=次日开盘定价输入→建仓放收盘前；数据前不加仓」，盲判 operation 在事件前一日应自动降风险偏好档。

## 风险

- 东财日历接口字段/覆盖度未实测，调研不通过则直接落手工 yaml 兜底（不阻塞）
- 事件重要性分级标准需定义（建议：影响利率预期的美国通胀/就业/联储 + 云厂商资本开支指引 = 高）
