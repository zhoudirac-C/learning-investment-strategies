# 早盘监控观察指南（Morning Cron Observation Guide）

## 场景描述

当 cron job 在 09:30（市场开盘初期）触发，且预运行脚本输出 `[qing-agent fallback — 输出原始监控上下文]`（脚本的 agent 分析层未生成结构化数据）时，使用本指南。

## 典型数据流

```
脚本失败输出: "[qing-agent fallback — 输出原始监控上下文]"
        ↓
降级路径激活: curl Tencent API 获取实时行情
        ↓
联表数据: positions.yaml + strategy_pack.yaml + watchlist.yaml + recent claims
        ↓
策略判断: 实时数据 vs YAML 配置中的 buy_setup/invalidation_setup/key_levels
        ↓
输出: 结构化早盘提醒（五段式）
```

## 开盘初期关键验证点（按优先级）

### 1. 指数关键点位验证
- 上证 4000（strategy_pack 中的减仓/风控阈值）
- 上证 4030/4120（趋势买点/强修复阈值）
- 科创50 与主板的背离（科技方向分歧信号）

### 2. 进攻方向方向性验证
- 燃气轮机方向（杰瑞/应流/万泽）：集体走弱 → 触发 invalidation
- LPU/推理芯片（世运/沪电/深南）：全线弱势 → 确认 UP 科技规避纪律
- 方法：从 watchlist.yaml 的 sector_groups 获取同方向标的，curl 批量查询涨跌幅

### 3. 防御/低位方向企稳验证
- 工程机械（徐工）：是否企稳不创新低
- 创新药（药明康德）：是否止跌逆势红盘
- 方法：对比防御方向涨跌幅 vs 大盘涨跌幅

### 4. 持仓风控线验证
- 读取 positions.yaml 中 shares > 0 的所有持仓
- 计算当前价 vs risk_zone（风控线）和 cost（成本）
- 若距风控线 <3%，标记为风控观察并写收回条件

## 板块联动交叉验证（核心方法）

当唯一持仓（或核心观察标的）出现下跌时，必须按以下步骤验证是否板块走弱：

```
第1步：从 watchlist.yaml 的 confirm_with 或 sector_groups 获取同方向标的代码列表
第2步：curl 批量查询这些标的
第3步：判断模式——

  模式A — 板块集体走弱（多数同向跌，领涨标的大跌>5%）：
    → 持仓动作偏防御，证伪字段引用板块联动信号
    → 不因单票跌幅小就认为持仓安全
  
  模式B — 板块分化（部分涨部分跌）：
    → 持仓按技术面正常判断
  
  模式C — 板块独跌（同方向其他票平稳或涨）：
    → 排查个股利空（未公告/突发风险）
    → 动作可偏减仓
```

## 典型案例：2026-06-10 开盘

**场景**：预运行脚本输出 `qing-agent fallback`，上证 3986.71(-0.58%)，唯一持仓万泽股份。

**数据获取**：
```bash
# 指数
curl -s 'https://qt.gtimg.cn/q=sh000001,sz399001,sz399006,sh000688' | iconv -f gbk -t utf-8 | awk -F'~' '{print $2, $4, $5, ($4-$5)/$5*100}'
# 持仓+同方向+观察池
curl -s 'https://qt.gtimg.cn/q=sz000534,sz002353,sh603308,sz000425,sh603259,sz000636' | iconv -f gbk -t utf-8 | awk -F'~' '{name=$2; print name, "现价="$4, "涨跌幅="($4-$5)/$5*100"%"}'
```

**交叉验证结果**：
- 杰瑞 -6.76%（领涨大跌，异常深度回调）
- 应流 -2.52%
- 万泽 -1.91%
→ 结论：燃气轮机方向集体走弱 → 触发 strategy_pack invalidation

**信号整合**：
1. 上证失守 4000（3986.71）→ 减仓警戒
2. 燃气轮机集体走弱 → 进攻方向受损
3. 万泽距风控线 30.5 仅 2.6% → 风控观察
4. 科创50 独红 +0.29% → 科技分歧，但 UP 纪律不碰
5. 风华高科 +4.31% → MLCC 周期上行确认，但已降级为 monitor_only

## 常见陷阱

### 1. 只关注持仓个股跌幅，忽略板块联动
**错误**：万泽仅 -1.91%，看起来不严重
**正确**：杰瑞 -6.76% + 应流 -2.52% → 板块集体走弱 → 万泽的风控风险远大于个股跌幅显示的程度

### 2. 开盘杀跌时忽略上证关键点位
**错误**：认为"刚开盘，跌 0.58% 不算什么"
**正确**：3986 < 4000 直接触发 strategy_pack 的"收盘跌破4000→减仓"警戒条件。虽然只是开盘跌破，但必须重点跟踪 30 分钟内能否收回

### 3. 科创50独红时忘记 UP 规避纪律
**错误**：科创50 +0.29% 且主板跌 → 科技有独立机会
**正确**：UP 6/4 明确"6月份开仓科技不是很好的行为"，科创50独红可能是科技板块内部最后的分化动量，不追

### 4. 预运行脚本失败时放弃板块验证
**错误**：脚本失败→只查持仓个股→忽略板块
**正确**：脚本失败更需手动执行板块交叉验证，因为 YAML 的自动 invalidation 触发机制依赖脚本运行
