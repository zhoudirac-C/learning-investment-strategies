# 买入信号检测设计缺口

> 对应 SKILL.md 陷阱 24。记录「永远在等，从不执行」的根因和设计方案。

## 用户需求（原文）

> 「我想的就是让大模型替我盯盘，比如他自己观察观察池里的票，已经缩量企稳了，然后告诉我今天这个点位可以买入了，这是最核心的。」
>
> 「我希望 Qing Agent 做到和 UP 同样的思维逻辑，分析之后，直接给我买入信号。」

## 现状断层

```
当前：cron 定时 → Agent 全量分析 → "等缩量企稳" → 用户自己盯
目标：cron 定时 → poll 检测条件 → Agent 单票确认 → "买，现价X，止损Y"
```

## 缺失的三个能力

### 1. 买入信号检测（poll 脚本侧）

poll 脚本当前只做价格区间检测（add_zone），不做量价配合判断。需要新增：

| 信号 | 检测方式 | 参考框架 |
|------|---------|---------|
| 缩量止跌 | 近3日成交量递减 + 收盘价不再创新低 | UP 买入纪律 |
| 放量阳线确认 | 当日量 > 5日均量 × 1.5 + 阳线 + 收盘 > 开盘 | 量价配合 |
| 均线支撑 | 收盘价在20日线上方 + 5日线上穿10日线 | entry-points-generation |
| 不追板 | 当日涨幅 < 7%（非涨停板） | 核心纪律 |

### 2. 单票深度研判（Agent 侧）

当 poll 检测到某票满足上述条件时，不应走全量 market 分析，而是触发单票分析模式：

```
poll 触发 → Agent /analyze/trigger?analysis_type=single_stock&code=600378
  → 只分析这一只票的：均线状态、量价关系、板块联动、大盘环境
  → 输出二值化结论
```

### 3. 二值化输出格式

Agent 输出必须收敛到两种格式之一：

```
🟢 买入信号
代码：600378 昊华科技
现价：52.30
介入区间：51.5-53.0
止损：49.80（-4.8%）
理由：20日线上方缩量止跌 + 今日放量阳线确认 + WF6涨价持续 + 大盘缩量修复
风险：大盘若放量跌破地量低点则失效

🔴 不买
代码：600500 中化国际
原因：今日涨停板（+10.02%），纪律不追板。等开板分歧回踩6.3-6.6区间再判断。
```

**禁止**：「等」「观察」「关注」「如果……可以……」等模糊词。

## 实现优先级

| 优先级 | 任务 | 难度 |
|--------|------|------|
| P0 | Agent 输出格式改为二值化（prompt 修改） | 低 |
| P0 | "可买"标签改为「📋 条件单待触发」 | 低 |
| P1 | poll 脚本增加量价配合检测 | 中 |
| P1 | poll → Agent 单票触发链路 | 中 |
| P2 | 全自动端到端（poll 检测 → Agent 确认 → 推送） | 高 |

## 与现有 cron 的关系

不需要新增 cron job。利用现有的高频率 poll job（`qing_stock_monitor_poll.py`，每 5 分钟）：
- 当前：检测 add_zone → 推送「价格进入介入区间」
- 增加：检测量价配合后 → 触发 Agent 单票分析 → 推送买入信号

Agent cron job 保持现有频率不变，但分析重点从「全量大盘+板块」转向「poll 触发的单票买入确认」。
