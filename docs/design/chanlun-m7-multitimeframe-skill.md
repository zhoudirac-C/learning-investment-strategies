## 一、定位与动机（为什么做）

### 1.1 实证动机（2026-08-28 三周期 spike，sh512400）

同一天（8/28 收盘）三周期各自跑 `RecursionEngine`，输出差异决定性：

| 周期 | 最新结构 | 信号 |
|---|---|---|
| 日线 | 最新笔 [7/20~8/11] **sure=False**，8 月无中枢无买卖点 | **哑火**——结构未定型，什么都不给 |
| 60m | 中枢 [1.712,1.851]（7/20~8/11）→ 上移 [1.860,1.960]（8/11~8/19） | 1类卖点 L2 @8/11（1.922 顶）+ **3类买点 L1 @8/19 价1.864** |
| 30m | 中枢 [1.753,1.820] → [1.860,1.960]（与 60m 同区间） | **1类买点 L1+L2 双级别共振 @8/19 价1.864** |

**结论**：日线一笔的内部，次级别已走完完整走势并给出明确买卖点。单周期引擎在"结构未定型"时段对操作者零输出——这正是 skill 必须用 60m/30m 的底层原因，也是 chan_engine 替换 skill 前必须补齐的能力。

### 1.2 为什么是"真次级别"而不是三份独立报告

三周期独立跑只能靠人肉对齐（本 spike 即如此）。缠论原文的区间套是**结构包含**关系：

- **区间套**（claim-20080306-001-a）：走势有级别整体结构才有区间套；买卖点精确定位靠区间套。
- **买卖点级别定理**（claim-20070309-001-r）：大级别买卖点必然是次级别以下某级别买卖点。
- **买点定律**（claim-20061205-001-a）：大级别二买 = 次级别一买。
- **级别递进**（claim-20080306-001-b）：高级别改变必先从低级别开始。

因此 M7 的核心是**日线笔 → 时间窗切片 → 次级别走势分解 → 区间套确认**的递归链，让"日线未确认笔（sure=False）"获得次级别的细粒度解读，而不是三张图各说各话。

### 1.3 与 skill 的关系

`skills/finance/chanlun-course/scripts/chan_analysis.py`（413 行）现状：

- **保留**：数据源经验（腾讯日线/新浪分钟/TDX 降级链、缓存 TTL、UA 坑）、CLI 接口（`--30m/--60m/--scale N/--fresh`）、输出惯例（防守线/反转确认位/仓位性质/失效条件）。
- **替换**：`merge_inclusion → find_fractals → find_bi → identify_zhongshu → detect_backtension → classify_buy_points` 简化算法管线 → 换成 `RecursionEngine`（claims 校准口径）+ 多级别对齐层。
- **替换理由**（2026-08-28 对照实证）：简化口径在窄震荡区产出"线状伪中枢"（512400 [1.849,1.851]，宽度 0.002，无操作意义）；新笔/旧笔口径未仲裁；无线段、无级别、无 is_sure。chan_engine 在以上四点全部有 ADR 仲裁与测试门。

## 二、目标与非目标

### 2.1 目标

1. **分钟数据层（M7-1）**：60m/30m 抓取（新浪 → TDX 降级链，复用 skill 踩坑经验）+ SQLite 多周期存储 + `load_bars(code, tf)` 适配。
2. **跨周期对齐层（M7-2）**：日线笔时间窗 → 次级别 bar 切片映射；`MultiTimeframeChart` 容器（日线五表 + 每笔的次级别图引用）。
3. **引擎理论补全（M7-3，v1.1 新增）**：补齐单周期引擎的理论缺口——走势类型状态机（盘整/趋势/三演化）、背驰前提校验（趋势背驰 vs 盘整背驰）、二买/二卖生成、recursion 列九段升级。详见 §十 Gap 清单 G1–G4/G6。
4. **区间套递归层（M7-4）**：日线已确认/未确认笔 → 次级别走势分解校验 → 次级别背驰/买卖点作为大级别笔的精确定位与确认信号；**大级别二买 = 次级别一买**的跨级别确认；小转大信号输出。
5. **Skill 接入层（M7-5）**：report adapter 把多周期结构翻译成 skill 输出惯例（防守线/反转确认位/目标位/失效条件/仓位性质，含级别归属三问自检）；**同级别分解视角**与**分类状态→预案**输出（L38/39，P3 笔记既定演进）；`chan_analysis.py` 改为薄壳 CLI，直接替换旧算法管线（仲裁 ⑥：不设 legacy）。
6. **线段口径升级（M7-6，v1.1 新增；v1.2 拍板全量重写）**：自建 L0 分组的"greedy-3bi + 极值扩展"口径**整体替换**为特征序列两情况 + 缺口处理（课 67/71，ADR-003 口径 A），消除 SEG-004/005 已登记偏差（仲裁 ②：不采用偏差点修补降级路径）。

### 2.2 非目标（本期不做）

- 周线及以上、1min/5min 周期（30m 已是最细）
- 实盘推送、盘中自动交易
- 策略回测（M6 职责；M7 的多周期信号后续可反哺 M6 特征层，反向不依赖）
- 全市场扫描/选股
- **均线系统/吻三分类（P2）不进引擎**：课程 P3 明确"学完本部分，均线系统退居辅助"——吻是均线近似口径，已被中枢/走势类型的结构化定义取代。仅在 skill 教学章节保留（P2 讲义档案）。

## 四、M7-1 分钟数据层设计

### 4.1 数据源降级链（复用 skill 实证经验）

```
60m/30m: 新浪 CN_MarketDataService.getKLineData(scale=60/30) → TDX(60min/30min) → stale 缓存
日线:    M6 既有链不动（腾讯缓存 + akshare/baostock）
```

skill 已实证的坑直接继承：腾讯分钟线不可用（mkline 301/fqkline param error）必须新浪；TDX 分钟线有盘中实时 bar 完整 datetime；新浪 datalen=260 窗口上限。

> M7-1 落地口径（2026-08-28 评审后同步）：链末级"stale 缓存"由 **minute_bars 库内既有快照**承载——双源皆挂时调用方复读库即可，数据层不另设缓存文件；stale-age 提示归 M7-5 报告层。详见 `docs/tasks/chanlun-m7-1-minute-data-layer.md`。

### 4.2 存储（chan_bars.db 扩表）

```sql
CREATE TABLE IF NOT EXISTS minute_bars (
    code       TEXT NOT NULL,              -- 带前缀 'sh512400'
    tf         INTEGER NOT NULL,           -- 60 / 30
    dt         TEXT NOT NULL,              -- 'YYYY-MM-DD HH:MM'
    open REAL, high REAL, low REAL, close REAL,
    volume REAL,
    complete INTEGER NOT NULL DEFAULT 1,   -- 盘中未完成 bar = 0
    source TEXT NOT NULL,                  -- 'sina' / 'tdx'
    updated_at TEXT,
    PRIMARY KEY (code, tf, dt)
);
```

- **窗口限制如实声明**：新浪单次 260 根 ≈ 60m 覆盖 2.6 个月 / 30m 覆盖 1.4 个月。分钟数据**不支撑长周期级别递归**，仅用于"近期结构"的次级别确认——这是能力边界，写进报告头。
- **增量语义**：分钟数据只做"滑动窗口快照"（每日盘中/收盘各刷一次），不做全量回填（历史分钟线免费源不可得，如实接受）。与日线库的长历史形成互补：日线管级别定性，分钟管近期次级别。

### 4.3 未收盘 bar 纪律

盘中最后一根分钟 bar 是**未完成 bar**：入库保留但打 `complete=0` 标记；`load_bars` 默认剔除，`include_partial=True` 才返回（供盘中观察）。防止"用未走完的 bar 确认分型"——与 is_sure 反未来函数纪律同源。

## 五、M7-2 跨周期对齐层设计

### 5.1 对齐口径（ADR 待仲裁项，暂定案）

**时间窗映射**：日线笔 bi（start_idx, end_idx）→ 取 `bars[start_idx].date 00:00 ~ bars[end_idx].date 15:00` 的 tf 切片。

- 暂定案理由：简单、无歧义、可测试。真·结构递归（次级别走势类型合成日线笔）留作 M7-4 验证后的演进方向，不一步到位。
- 边界 case：日线笔端点落在盘中（罕见，日线 bar 日期对齐收盘）；切片空窗（次级别数据窗口不足）→ 返回 `coverage=False` 并在确认结构中标注"次级别数据不足"，**禁止静默降级**。

### 5.2 MultiTimeframeChart 容器

```python
@dataclass
class SubLevelConfirmation:
    bi_ref: tuple[int, int]        # 日线笔 (start_idx, end_idx)
    tf: str                        # '60m' / '30m'
    zs_in_bi: list[ZhongShu]       # 笔内次级别中枢
    bsp_in_bi: list[BSPoint]       # 笔内次级别买卖点（精确定位）
    backchi: bool                  # 笔末端次级别背驰（确认信号）
    backchi_metric: dict           # 双口径证据: {area_proxy: …, macd_area: …}
    coverage: bool                 # 次级别数据是否覆盖整笔

@dataclass
class MultiTimeframeChart:
    daily: NormalizedChart
    sub: dict[str, NormalizedChart]            # {'60m': …, '30m': …}
    confirmations: list[SubLevelConfirmation]  # 日线笔 × 次级别
```

### 5.3 时间戳对齐纪律

- 分钟 dt 截断到 `HH:MM`，A 股时段表（9:30-11:30 / 13:00-15:00）校验，异常 dt 明确报错。
- 日线笔窗口与分钟切片的**重叠校验**：切片首尾 bar 必须落在窗口内，超出即断言失败（防数据错位）。

## 六、M7-3 引擎理论补全设计（v1.1 新增）

### 6.1 走势类型状态机（G1/G2）

课 17/18/20 定义 → 新增 `core/trend.py`：

- **盘整** = 完成走势只含 1 个中枢；**趋势** = ≥2 个**依次同向、互不重叠**（`[zd1,zg1]` 与 `[zd2,zg2]` 无交集）的中枢。
- **中枢三演化判定**（课 18/20）：
  - 延伸：新笔仍回到原中枢区间（`zd ≤ 笔端点 ≤ zg` 反复）→ 同一中枢延续；
  - 新生：同向新中枢产生且区间不重叠 → 趋势延伸；
  - 扩张：连续两个同级别中枢波动区间重叠 → 级别扩张（对应级别延续定理二，claim-20070105-001-a/b）。
- **输出**：`TrendState { walk_type: trend/consolidation/unknown, zs_count, zs_list, last_event: extension/new/expansion }`——这是仓位性质（反弹仓 vs 反转仓）的结构化根据，取代 adapter 层的启发式。

### 6.2 背驰前提校验（G3）："没有趋势没有背驰"（L15/24）

- 现状：`detect_backchi_bsp` 对任何三件套几何模式都出背驰买卖点，**不校验走势类型前提**。
- 补全：背驰输出增加 `backchi_type: trend_div / consolidation_div`——三件套所在走势含 ≥2 同向不重叠中枢 → 趋势背驰（标准一买/一卖）；仅 1 中枢 → 盘整背驰（skill 已有人工标注惯例，claim 依据"反弹幅度理论上限=中枢区间"）。**报告必须标注，防止把盘整背驰当反转信号**（skill 现行人工纪律引擎化）。

### 6.3 二买/二卖生成（G4）

- 现状：core 只产 bstype=1（背驰）与 3（回试不回中枢），**bstype=2 缺失**——三类买卖点完备性只实现 2/3。
- 补全（课 17 定义 + 安全性证明）：一买后**第一次次级别回调**（次级别 = 同向笔间反向笔代理，M7-4 起用真 60m 切片确认）低点不破一买低点 → 二买（`bstype=2, dir=up`）；一卖镜像。安全性由分解定理保证（一买后已走两段，必有第三段向上），非概率。
- 与 M7-4 衔接：日线二买候选 → 强制要求次级别一买确认（claim-20061205-001-a 买点定律），未确认则标 `sure=False`。

### 6.4 recursion 列九段升级（G6）

- 现状：九段升级只在 chanpy/czsc 适配器后处理（`_apply_nine_bi_upgrade_with_extension`，课 33，claim-20070302-001-b），**core/levels.py 无**——校准报告已登记 ZS-003 recursion 降级项。
- 补全：把中枢延伸 ≥9 笔（延伸后范围内 3 子中枢重合门控）→ level+1 的后处理移植进 core/levels.py，recursion 列 ZS-003 转 PASS。

### 6.5 验收

- 既有 202 测试零回归（当前 182 绿 + 15 czsc/Chan 环境依赖 error，**M7-3 开工前补齐环境**）；校准矩阵 chanpy 25 / czsc 25 / recursion 18 不回退且 ZS-003 recursion 修复。
- 新增 synthetic 用例：两中枢趋势 / 中枢扩张 / 二买构造 / 盘整背驰 vs 趋势背驰各 ≥2 例。

## 七、M7-4 区间套递归层设计

> **实证修正（2026-08-29，M7-4 落地时）**：§三"切片 → 次级别引擎分解"修正为
> **全序列引擎 + 窗口归属**——实测切片孤跑丢失进入段上下文（512400 笔 [7/20~8/11]
> 的 60m 切片 68 根 → zs 全空、无一卖），无法复现 §1.1；全序列 260 根跑引擎则
> 精确复现 spike 全部结构（60m 三买 @8/19 1.864、30m 一买 L1+L2 共振同点同价）。
> BiSlice 时间窗职责收窄为结构归属（zs span 相交即归入，bsp 按 idx 落窗）。
> 探针记录：`docs/tasks/chanlun-m7-4-nested.md`。

### 7.1 次级别确认四输出（对齐课文口径）

对日线每根笔（重点：**末端笔与 sure=False 笔**）：

1. **精确定位**（区间套，claim-20080306-001-a）：日线笔末端 → 次级别买卖点给出入场/离场的具体价位与时刻（8/19 15:00 @1.864 模式）。
2. **确认信号**（买点定律，claim-20061205-001-a）：日线二买候选 → 要求次级别一买确认；日线笔 sure=False → 次级别背驰/转折结构作为"笔可能终结"的早期信号。
3. **小转大输出**（课 43）：次级别背驰 + 大级别笔/段结构联动 → 显式标注 `small_to_large` 候选（次级别背驰绝大多数不制造大级别顶，须与大级别背驰同时满足才升级——防级别错配的镜像纪律）。
4. **级别归属校验**（级别三问自检，P2 答疑沉淀）：信号哪张图成立、防守线哪张图、目标位哪张图——三者必须同图；adapter 输出强制携带 `level` 标签，**60m 信号永不改变日线仓位性质**（级别错配硬防线）。

### 7.2 背驰口径衔接（G7，v1.3 改判：MACD 为主口径）

- **主口径 = MACD 柱面积**（EMA12/26/9，首值用首根 close 做种子，规则照搬 chan_analysis.py `calc_macd`）——与 UP 课程 P2/P4 口径及 skill 现行纪律一致；**背驰判定按 MACD 面积下结论**（UP 2026-08-28 改判，推翻 v1.2 仲裁 ④）。
- 对照口径 = 校准门 Σ|Δc|（`core/backchi.py` 面积代理），并行输出作结构对照证据（`backchi_metric` 双字段）。
- 两口径结论同向 → 置信标注一致；冲突 → **按 MACD 主口径下结论**，Σ|Δc| 证据并列展示。
- 实施要点：`calc_macd` 移植进 `src/chan_engine/core/`（纯函数，零依赖）；种子规则与预热行为写入 docstring 并加单测锚定（同一输入数值逐位复现）；M7-3 落地时 `detect_backchi_bsp` 的面积函数切换为 MACD 面积，Σ|Δc| 路径保留并加对照输出——校准门 synthetic 用例的 expect 断言**保持 Σ|Δc| 不动**（BC-002 等几何校准锚不被污染），MACD 口径作为策略层新增能力单独加用例，两口径在测试层隔离。

**改口径影响面实测（2026-08-28，零回归预验证）**——切换前的实证背书，开工即引用，无需重测：

| 层 | 影响 | 实测证据 |
|---|---|---|
| 校准资产（26 用例 + 5 金标 yaml） | **零改动** | expect 只断言结构结论（fx/bi/zs/bsp 表），面积数值在注释/meta 不进断言（ADR-008：面积断言 M1 不参与 diff） |
| core/backchi.py（`detect_backchi_bsp`/`_segment_internal_backchi`） | **唯一实际改动点** | 两函数用 `_segment_area`（Σ\|Δc\|）比较决定 bsp 输出——切换即换此处面积函数 |
| BC-001/002 背驰金标 | **结论同向，PASS 保持** | BC-002 实测：A2 vs C2 Σ=10.0>5.2 / MACD=3.93>1.88 同向背驰；a1 vs c1 Σ=2.6>1.8 / MACD=0.37>0.02 同向背驰 |
| engine/harness/czsc 列/增量会话 | 不受影响 | 只消费 bsp 表结果，不关心面积算法；增量一致性（M3-5 硬门）与口径无关 |
| skill chan_analysis.py | **反而统一** | skill 的 `detect_backtension` 本来就是 MACD 面积——引擎切 MACD 后两端口径一致，M7-5 接入少一处对齐 |

两个待办记录（不阻塞，M7-3 开工第一项）：①BC-001 仅验证了 hist 可计算、完整 A/C 比较须开工即跑；②种子规则必须与 skill 口径逐位一致（首根 close 种子），否则 synthetic 短序列数值漂移。

### 7.3 校准与验收锚

- **Golden**：512400 2026-08 实证（本设计 §1.1）固化为 golden 用例——日线笔 [7/20~8/11] → 60m 切片须复现中枢 [1.712,1.851] + 1类卖点 L2 @8/11；[8/11~8/19 窗口] → 60m 三买 @8/19 1.864。次级别数据窗口滚动后此 golden 会失效（分钟数据不可回填），处理方式同 ADR-005：固化**当时切片快照**入 spec/golden。
- **Synthetic 用例族**：构造"日线 N 笔 + 次级别预设结构"的双层合成数据，验证对齐切片边界、coverage=False 传播、未收盘 bar 剔除、二买=次级别一买确认链路。

### 8.1 CLI 兼容契约（不破坏现有用法）

```

```

### 8.2 输出翻译（skill 输出惯例 → adapter 职责）

| skill 惯例 | 数据来源（multi_tf + M7-3 状态机） |
|---|---|
| 防守线 | 日线最近底背驰低点 / 60m 最近次级别一买低点（级别标注归属图） |
| 反转确认位 | 日线前高 + 60m 突破回踩结构（L18 定理三"突破回踩确认"严格化） |
| 仓位性质（反弹仓/反转仓） | **仅日线**定性质——依据 M7-3 `TrendState`（走势类型 + 中枢位置），次级别只定时机 |
| 失效条件 | 破防守线（注明哪张图的线）；破更大级别前低 → 反弹终结 |
| 入场点 | 60m/30m 次级别买卖点价位（区间套精确输出） |
| 背驰类型 | `backchi_type` 强制标注（趋势背驰/盘整背驰，M7-3 G3） |

### 8.3 同级别分解视角与分类状态（G8/G9，L38/39 + P3 笔记既定演进）

P3 讲义明确："用户 skill 映射'60min 定入场时机'本质=同级别分解视角；P3 后可升级为显式'中枢标记→分类状态→预案'流程"。M7-5 落地为 adapter 两种输出模式：

- **同级别分解模式**（`--decomp`）：选定级别，只输出当前走势类型的**当前中枢** + 上一段/当前段，机械化"只做上涨+盘整段、回避下跌段"视角。
- **分类状态→预案**：当下输出结构化状态机（课 17"理论不预测，只提供分类框架"）：
  ```
  { 中枢位置: 中枢内/上方/下方, 状态: 延伸/新生候选/破坏确认,
    预案: 破坏成立→持有到新高/回抽破 ZG→退回中枢内处理… }
  ```
  每个状态绑定 L18 定理三破坏判定与三买/三卖几何，输出直接可操作。

### 8.4 切换纪律（v1.2 修订，仲裁 ⑥）

**不保留旧算法、不并行观察**：`chan_analysis.py` 算法管线直接替换为 multi_tf，无 `--legacy` 开关。旧简化口径的对照价值由本文档 §1.1/§1.3 实证记录与校准门资产承载；切换后新口径结论以盘面验证，差异直接在报告中显式列出（不再有旧输出可对照，须在切换后首两周人工加密复核频次）。

## 九、M7-6 线段口径升级设计（ADR 前置，可独立排期）

### 9.1 现状与缺口（G5）

自建 L0 分组（`core/segments.py`）用"greedy-3bi + 创新极值吸收"口径，与课 67/71 的**特征序列两情况 + 缺口处理**口径在 SEG-004/005 上存在已登记偏差（校准报告：L0 段拆得更细，与 chanpy EigenFX 降级同源）。局限自述（levels.py 头注释）：更长段的内部多中枢构造未泛化（当前段=最小 3 笔段）。

### 9.2 升级内容

1. 特征序列构造（含包含处理，只对同一特征序列成立——课 71，ADR-003 仲裁口径 A）。
2. 线段终结两情况判定（课 67）：特征序列顶/底分型 + 缺口两种情形分别处理。
3. 段内多中枢泛化（解除"最小 3 笔段"限制）→ 九段升级与中枢延伸判定的地基更稳。

### 9.3 前置与风险（v1.2 修订，仲裁 ②③）

- **须先立 ADR-012**（线段终结口径：特征序列完整实现的实现细节与边界 case）——这是全引擎复杂度最高的单项，波及 recursion 全部下游（zs/bsp）。
- **拍板：全量重写**——`core/segments.py` greedy-3bi 口径整体替换为特征序列口径，不保留旧路径、不采用偏差点修补降级。
- 排期：**严格串行**，置于 M7-5 之后（M7-1→2→3→4→5→6 依序执行，每次一步）；skill 接入（M7-5）先以现有 L0 口径交付，线段升级在 M7-6 全量重写后全量校准矩阵复验。

## 十三、M7-6/M7-7 终态结论（2026-08-29，防重复验证专节）

> **本节存在的目的**：线段口径问题已最终解决，双轨制为终态架构。
> 任何人（含 AI 代理）若考虑"把递归层内部单元也切到特征序列段"或"修复 M7-7 失败"，
> **先读本节，勿重复立项、勿重复验证、勿重复实验**。

### 13.1 最终架构：双轨制（非过渡态）

| 层 | 口径 | 消费方 | 模块 |
|---|---|---|---|
| 对外 seg 表（报告/CLI） | 特征序列严格口径（课 67/71/78 两情况+缺口+古怪延续） | report/CLI/decomp/五表 | `core/segments_fx.py` |
| 递归层内部走势单元 | greedy-3bi 相位分组（课 35/84 f1(a0) 递归构造物，ADR-009 正名） | zs/bsp/trend/backchi | `core/segments.py` |

两者回答的是**不同的问题**：特征序列段回答"这段走势什么时候结束"，greedy 段回答"这段走势内部怎么拆成中枢+连接腿"。**互补关系，非替代关系。**

### 13.2 M7-7 B 演进失败实证（为什么不能统一）

尝试把递归层内部单元也切到特征序列段（M7-7 B-2 路线），**真数据 golden 16 例失败**。

**根因（鉴别冲突，不可调和）**：真数据长 fx 段含多个盘整相位（如 512400 60m 的
[1.712,1.851]→[1.804,1.953]→[1.86,1.96]），相位边界锚定的是 greedy 分组规则。
存在两组互相矛盾的锚：
- BC-002 要求"段首重叠三笔 bi0-2 不发射"（三件套进入段角色）
- 512400 60m 要求"同形的推动三笔 bi10-12 发射"（三件套离开段角色）

区分二者的唯一信息是相位在三件套中的角色，而相位边界 = greedy 规则本身。
**任何纯段内局部规则都无法同时满足两组锚。**合成语料太短（≤12 笔、单相位）未暴露此问题。
