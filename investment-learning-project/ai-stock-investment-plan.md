# AI 炒股投资项目方案：基于四大核心模块的自动化投资分析系统

> **版本**：v2.0（2026-08-07，第二稿）
> **设计依据**：以原《投资学习项目框架》（已归档 `docs/archived/investment-learning-framework-v3.0/`）的**核心模块**为蓝本——该框架定义了一套经过思考验证的投资方法论（双路径、假设清单、信号跟踪、事前验尸、仓位规则、复盘校准），但它靠**人手工执行**。本项目的目标是：**把这套方法论的每个核心模块自动化成一个 AI 子系统**，机器按方法论跑流程、人只做最终决策。
> **免责声明**：系统一切产出仅供研究参考，**不构成任何投资建议**；不接入真实交易接口，不自动下单。

---

## 一、设计思想：方法论不变，执行者换人

原框架的四个核心模块与要解决的自动化问题：

| 原框架核心模块 | 手工时的做法 | 自动化后要回答的问题 |
|---|---|---|
| **核心原则：双路径**（A 基本面 / B 情绪趋势，禁止混用） | 人交易前自己选路径 | 机器如何给每个标的、每笔建议自动判定路径并防止混用？ |
| **模块一：产业逻辑拆解**（产业链分层、信息分级、假设清单） | 人读财报读研报，手写假设 | 机器如何自动拆解产业链、给信息分级、生成带数值置信度的假设？ |
| **模块二：信号跟踪与情绪判断**（A 基本面信号、B 情绪四指标、事前验尸） | 人每周盯 3–5 个信号 | 机器如何 7×24 盯信号、算情绪指标、自动做事前验尸？ |
| **模块三：落地策略与复盘**（路径匹配检查、仓位规则、交易日志、复盘、错误分类、校准） | 人写计划、记日志、月复 | 机器如何自动生成交易计划、强制仓位纪律、自动复盘与校准？ |

**一条主线贯穿**：原框架是"人 + 检查清单"，本系统是"AI 引擎 + 同一张检查清单"。方法论里的每条规则都变成机器的硬约束或校验节点。

## 二、总体架构：四大引擎 + 一个闭环

```
                        ┌─────────────────────────────────────┐
                        │  调度层：盘前 / 盘中7时点 / 收盘      │
                        └───────────────┬─────────────────────┘
                                        ▼
┌──────────┐   ┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ 双路径引擎 │→ │ ① 产业逻辑引擎     │→ │ ② 信号与情绪引擎   │→ │ ③ 执行与复盘引擎   │
│ (路径分流) │   │ (路径A研究自动化)  │   │ (跟踪+验尸自动化)  │   │ (计划+纪律+校准)   │
└──────────┘   └──────────────────┘   └──────────────────┘   └────────┬─────────┘
       │ 每个标的/建议             │ 假设清单                │ 信号触发        │ 建议报告
       │ 先定路径                 │ (数值置信度)             │ +验尸结果       │ +交易日志
       ▼                        ▼                        ▼              ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ 知识底座：claims观点卡(Neo4j+Qdrant) · 推理模式库 · 方法论库 · 案例库(基准率) │
│ 数据底座：东财→新浪→缓存降级链 · K线SQLite缓存 · akshare财报 · 市场情绪      │
└──────────────────────────────────────────────────────────────────────────┘
```

关键事实：四大引擎所需的底层能力在本仓库**均已存在并每日跑通**——Qing-Agent 的 9 节点 LangGraph 工作流（`src/qing_investment/agent/`）里已经有知识检索、市场分析、个股分析、**魔鬼代言人（即自动化事前验尸）**、引用校验、复核节点；监控规则引擎（`src/qing_investment/monitor/`）已经在做信号触发与去重。本项目是把它们**按四大模块重组为统一系统**，只新建编排层与各模块缺失的薄功能。

## 三、双路径引擎：每笔建议先定路径

原框架铁律："同一标的必须事先选定路径 A 或路径 B，不能中途切换理由。"自动化设计：

- **路径判定**：每个进入观察池的标的带 `path` 字段（A/B），写入 `config/stock_monitor/watchlist.yaml`；AI 生成建议时必须声明路径，报告模板按路径分栏。
- **路径 A 建议**：只能引用基本面证据（订单、价格、产能、财报、产业链验证）；失效条件必须对应假设证伪。
- **路径 B 建议**：只能引用情绪/趋势证据（成交额占比、换手率、舆论、估值分位）；失效条件必须是趋势破坏（止损价）。
- **混用检测（自动校验节点）**：复用 Qing-Agent 的 reviewer 节点加一条校验规则——若路径 A 建议里出现"情绪还在所以持有"类表述，或路径 B 建议里出现"基本面好所以长持"，判违规、退回重写。这对应原框架复盘表里的"路径纪律"一栏，从人工自查变成机器强制。

## 四、引擎①：产业逻辑引擎（模块一自动化）

**目标**：输入一个产业主题或标的，自动产出产业链拆解 + 结构化假设清单。

### 4.1 产业链拆解
- 复用 `framework/reasoning-patterns.yaml` 的 128 条推理链（上游涨价周期五步、BOM 传导、受益标的筛选等）作为 AI 的拆解脚手架；`docs/标的深度研究/` 的存量报告作为输出范例；
- 输出：上中下游分层、各环节价值分配/壁垒/格局、核心事件的"直接受益/间接受益/情绪映射/受损"四类标的映射。

### 4.2 信息分级（自动标注）
- 按原框架三级标准给每条输入信息自动打级：一级（公告/财报/交易所）、二级（研报/协会）、三级（社媒/传闻）；
- 硬约束（原框架规则不变）：**任何假设至少 1 条一级 + 1 条二级信息支撑**，否则不进入假设清单。数据源降级链（东财→新浪→缓存→报错）保证一级信息的诚实性：没数据就报"数据缺失"，禁止 AI 编造。

### 4.3 假设清单（自动生成，对接 claim 卡）
- 输出格式沿用原框架升级后的字段：**假设内容 / 判断依据 / 验证信号 / 信息等级 / 数值置信度(%) / 基准率 / 兑现时间窗 / 证伪后处理**；
- 置信度不是拍脑袋：AI 必须先在 `knowledge/cases/` 案例库检索历史类似案例（基准率），再给出数值；
- 直接写成 `knowledge/claims/` 的 claim 卡格式（statement/evidence/confidence/status/supersedes 天然同构），进入 Neo4j 观点演化图——**假设从此可检索、可追溯、可证伪**，这是手工框架做不到而仓库已有基础设施直接支持的一点。

## 五、引擎②：信号与情绪引擎（模块二自动化）

**目标**：假设清单里的每条验证信号变成机器盯的指标；路径 B 的四指标自动计算；事前验尸自动执行。

### 5.1 路径 A：基本面信号跟踪
- 把假设清单的验证信号（招标公告、价格库存、业绩预告、政策事件、产业链互证）映射到现有采集通道：监控规则引擎（`monitor/rules/`）盯价格/区间类信号，财报 cron（`fetch_financial_reports_cron.py`）盯业绩信号，事件管线（`qing-event-pipeline`）盯公告/政策类信号；
- 信号触发 → 自动更新对应 claim 的状态与置信度（支持→上调、反对→下调）；**置信度跌破 40% 自动判假设失效**，按"证伪后处理"字段执行并通知——这就是原框架"纠偏判断流程"的自动版。

### 5.2 路径 B：情绪四指标（自动计算）
- 板块成交额占比、龙头股换手率、舆论密度、相对估值分位，全部可由现有数据源计算（东财行情 + 板块数据 + 情绪采集 `market_sentiment`）；
- 判定"升温/过热/退潮/冰点"时调用 `methodology/market-cycle.md` 与 `framework/market-cycle-framework.md` 的状态定义，避免 AI 自由发挥；量能真假用 `framework/volume-quality-assessment.md` 的三步法交叉验证。

### 5.3 事前验尸（自动化 Devil's Advocate）
- Qing-Agent 已有 devils_advocate 节点，把原框架的 pre-mortem 流程固化为它的输出契约：对每笔建议**必须输出"假设 6 个月后失败的 3 个具体死因"**，且每个死因回推一个"现在可观察的先行指标"并入 5.1 的跟踪表；
- 原框架的 5 个反证问题（是否已 price-in、是否只听利好、空仓还会买吗等）作为该节点的固定检查清单注入 prompt。

## 六、引擎③：执行与复盘引擎（模块三自动化）

**目标**：交易计划自动生成、仓位纪律机器强制、日志与复盘全自动、校准按季自动跑。

### 6.1 交易前路径匹配检查（自动门禁）
- 原框架的五问表变成建议报告的强制字段：买入理由 / 持有周期 / 证伪信号 / 退出条件 / 最大亏损，缺一不出报告；
- "答案介于两条路径之间 → 不做"——reviewer 节点判不定路径时直接输出"回避"。

### 6.2 仓位规则引擎（纪律硬编码）
- 原框架公式不变，机器强制换算：**仓位% = 单笔风险上限% ÷ 止损幅度%**，再套三层上限（个股 ≤10%、单主题 ≤20%、路径 B 合计 ≤30%）取最小值，实际风险重算确认 ≤2%；
- 每条建议在报告里必须同时出现**仓位/止损/单笔风险三个数值**，缺一被校验节点打回；
- 组合熔断：月回撤 ≥10% 自动触发"强制减半"建议——这条从人的自觉变成系统规则（持仓数据来自 `positions.yaml`，本地私有、不进 git）。

### 6.3 交易日志与复盘（自动记录、过程/结果分离）
- 日志：每笔建议落盘即留档（标的/路径/三数值/对应假设/市场周期位置/数据时间戳），无需人记；
- 复盘：收盘后自动跑（现有 daily-review 通道），按原框架原则**过程评分与结果评分分离**——过程分评"当时信息下流程是否合格"，防止用结果反推决策质量（resulting 偏误）；
- 错误自动分类六型（逻辑/数据/执行/心理/路径/**运气**），"过程合格但亏损"自动归"运气"，防止 AI 因一次坏运气乱改方法论。

### 6.4 季度校准（自动统计）
- 原框架的校准机制直接落在 claim 数据上：按季度统计所有已到时间窗的假设——"AI 说 70% 的事实际兑现几成"，按置信度分桶输出命中率偏差表；
- 偏差超 10 个百分点 → 自动给下季度 AI 输出的置信度打 9 折（prompt 层注入校准系数）。这是手工框架最难坚持的一条，机器执行毫无成本。

## 七、每日闭环：四大引擎如何转起来

| 时段 | 动作 | 涉及引擎 |
|---|---|---|
| 盘前 06:30 | 预拉 K 线/财报；生成《今日观察清单》（各标的的触发/失效条件，纯配置渲染不经 LLM） | 双路径 + 引擎② |
| 盘中 7 时点（9:26–15:05） | 信号引擎扫描 → 触发即走：路径判定 → 检索对应假设/claim → AI 分析（含事前验尸）→ 仓位换算 → 《盘中建议报告》 | 全部 |
| 收盘 15:30 | 复盘当日信号与建议 → 更新 claim 状态/置信度 → 《每日投资建议报告》→ 观点跨日连续 | 引擎②③ |
| 每季度首日 | 校准统计 → 输出命中率偏差表 → 调整置信度校准系数 | 引擎③ |

**降级原则**（贯穿所有引擎）：AI 不可达 → 规则引擎照常出纯规则报告并标注"无 AI 推断"；数据源全挂 → 明确报错，禁止编造；幻觉校验不过 → 该段输出作废。**系统的底线行为与原框架红线一致：宁可没有建议，不给错的建议。**

## 八、输出契约（沿用原框架纪律，一条不改）

- 每条建议五要素：标的+方向 / 触发条件 / 失效条件 / 依据与证据分级（证据 vs 推断）/ 数据时间戳；
- 失效条件缺失 → 显式标注"未配置失效条件"，严禁编造；
- 报告头：数据时间、生成时间、分析引擎、路径分栏；报告尾：固定免责声明；
- 无无条件买卖指令（AGENTS.md 红线）。

## 十、实施路线（按引擎划分里程碑）

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M1 双路径引擎 | watchlist 加 `path` 字段；报告按路径分栏；混用校验进 reviewer | 构造混用案例能被拦截 |
| M2 执行与复盘引擎③ | 仓位三数值强制校验 + 建议落盘留档 + 收盘自动复盘 | 缺数值的建议被打回；完整交易日自动产出两份报告 |
| M3 信号与情绪引擎② | 信号→claim 置信度自动更新；路径 B 四指标自动计算；pre-mortem 契约进 devils_advocate | 信号触发能改 claim 状态；验尸输出含 3 死因+先行指标 |
| M4 产业逻辑引擎① | 假设清单自动生成并转写 claim 卡 | 给定主题能产出合规假设清单并入库可查 |
| M5 校准与回归 | 季度校准统计；`evals/` 回归对齐 | 输出首期命中率偏差表 |

顺序理由：先纪律（路径+仓位，防风险），再信号（出价值），后研究（提上限），校准最后（需要数据积累）。

## 十一、边界与红线

- 只调用、不修改 `src/qing_investment/`、`scripts/`、`config/stock_monitor/` 的现有实现；
- 不接交易接口、不自动下单；`positions.yaml` 等私有数据不进 git、不进 prompt 外发；
- 不承诺收益；所有产出保留"非投资建议"声明；
- 原框架的四条铁律（路径不混用、止损无条件、仓位有上限、数据要诚实）在系统中是硬编码约束，不是建议。
