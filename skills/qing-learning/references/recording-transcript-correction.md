# 录音转文字文档纠错与规范化流程

## 适用场景

用户提供录音/视频转文字的原始文档（如 Whisper 输出、讯飞转写、飞书妙记等），要求：
1. 按项目 raw 格式规范化
2. 修正录音转文字残留的错别字/口误
3. 走完整 qing-learning 流程（claims → wiki → framework）

## 与 OCR 图片转文字的区别

| 维度 | OCR 图片转文字 | 录音转文字 |
|------|---------------|-----------|
| 错误类型 | 字形识别错误、排版混乱 | 同音字、口语化表达、语气词 |
| 修正难度 | 中（需识别字形） | 高（需理解上下文+领域知识） |
| 特有错误 | 截断、重叠、乱码 | 重复句、口头禅、断句错误 |
| 处理工具 | RapidOCR / Tesseract | 纯 LLM 上下文理解 |

### 2. 口语化与口头禅

- "好吧"、"好吧好吧"、"是不是这个道理"、"就就就" → 保留或删除，不影响核心内容
- "我操"、"他妈的" → 根据上下文判断是否为强调，通常删除或弱化
- "各位"、"跟各位讲一下" → 博主对观众的称呼，保留或简化

### 3. 重复与断句错误

录音转文字常见把一句话拆成多段，或重复记录：

```
原文转写：
"中国长城这个东西，有时我不知道对这两个东西重视一下，
一个arpc，一个软件。我们特别是软件这一块，我们真得重视一下
6月1号到6月4号的台北大会，台北电脑展，台北电脑展，
6月2号到6月5号，有一系列的整个arpc会出来"

修正后：
"中国长城这个东西，有很多资金看好，人太多太一致了，
加上整体市场环境不好，所以导致它走得不顺畅。
但这个东西，你如果真要炒AIPC炒CPU，一定是绕不开的。"
```

### 4. 数字与单位错误

- "1200块钱" → 可能是"1200亿"或"1200元"，需根据上下文（市值/股价）判断
- "36%，40%" → 确认是百分比还是具体数值
- "800万" → 确认是"800万元"还是"800万台币/美元"

## 纠错流程

### Step 1: 初读全文，标记明显错误

快速浏览全文，标记以下类型：
- [ ] 明显同音字（根据投资领域知识判断）
- [ ] 公司/产品名称疑似错误
- [ ] 数字/单位可疑
- [ ] 重复段落
- [ ] 断句混乱

### Step 2: 上下文验证

对每个疑似错误，用上下文验证：

```
疑似错误："中继续创"
上下文："我们在上PCB那门课的时候，讲中继续创算到的是800多块钱"
→ 验证：①"PCB课"是博主课程 ②"800多块钱"是估值 ③光模块龙头中际旭创曾被估值
→ 结论："中继续创" = "中际旭创"
```

### Step 3: 领域知识核对

对不确定的术语，用以下方式验证：

1. **搜索项目已有 raw/claims/wiki** 中是否出现过类似表述：
   ```bash
   grep -r "疑似术语" sources/raw/财经/ knowledge/
   ```
2. **B站动态索引交叉验证**（关键技巧）：`sources/original/bilibili/index.md` 包含所有 UP 动态的标题和时间戳。当某个录音中提到某只股票在某天涨停时，检查 index 中当天是否有 UP 关于该股票的动态：
   - 案例：录音中说\"新环科技\"6/4 20cm涨停 → index 中 6/4 13:27 有\"星环科技拉直线的原因\" → 确认\"新环\"=\"{星环科技\"（688031）
   - 此方法对充电视频转录纠错特别有效——UP 在视频中讨论的标的通常当天有相关动态
3. **web 搜索核实**：对无法在本地知识库确认的股票名，用 web 搜索验证代码和全称
4. **腾讯财经 API 快速验证**：`curl -s 'https://qt.gtimg.cn/q=szXXXXXX' | iconv -f gbk -t utf-8 | awk -F'~' '{print $2}'`

### Step 4: 结构化整理

纠错完成后，按 raw 格式规范化。

## 常见陷阱与注意事项

### 陷阱1：二鬼 不等于 20日均线（高危）

UP 使用的「二轨」是自创的七轨布林线系统的第二轨（MID + 1×DEV），不是传统技术分析中的 20 日均线。上下文若提到「打到二轨」「二轨接一波」，指七轨布林线的强势股回调买点。误判为 20 日线会导致操作价位错误。参考 methodology/technical-analysis.md。

### 陷阱2：充电视频股票名优先用 B站动态索引交叉验证

UP 充电视频（录音/录像）中讨论的标的，通常在发布当天或次日有相关 B站动态。检查 sources/original/bilibili/index.md 按日期搜索动态标题——案例：录音中说「新环科技 6/4 20cm涨停」→ index 中 6/4 13:27 有「星环科技拉直线的原因」→ 确认「新环」= 星环科技（688031）。此方法比 web 搜索更快更准。

### 陷阱3：研报系列是 UP 动态图片股票推荐的正源

UP 在早盘/动态中发的带图片的机构推荐股票，已统一整理到 sources/raw/财经/研报：*.md 系列。不需要从原始图片 OCR 重新提取——研报文档就是加工后的成品。

### 一般注意事项

1. 不要过度纠错：口语化表达不影响核心内容时保留
2. 不确定时标注：[疑似：XXX] 或 [原文：XXX]
3. 保留原文引用：claims 的 evidence_quote 必须用修正后的准确原文
4. 时间戳处理：录音转文字的时间戳通常删除
5. AI总结不可靠：转写文档开头的AI总结通常不准确

## 与 qing-learning 流程的衔接

录音转文字文档走完纠错和 raw 格式化后，后续流程与普通 raw 完全一致。

**特殊注意**：录音视频的 claims 中，`source_type` 应标记为 `video`，`source_path` 指向整理后的 raw 文件。
