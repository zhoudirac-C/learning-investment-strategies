# 个股深度分析 — 竞价+盘前数据层 + Prompt 差异化设计文档

> 版本: 2026-06-11 v1.0
> 触发: 用户要求看盘定时任务对持仓个股做竞价组合+分时形态级别分析
> 目标: 每个时间节点的 LLM 输出，从"风控巡检+简短备注"升级为"持仓重点股深度分析+大盘/观察池精简"

---

## 1. 数据采集层

### 1.1 昨日特征摘要 (_yesterday_summary)

**数据源优先级**：
1. `15:20 收盘复盘 cron` 写入的结构化 `config/stock_monitor/daily_review_summary.json`（最完整）
2. `config/stock_monitor/state.json` 的 `last_quote_snapshot`（收盘行情快照，无分时分析字段）
3. K 线缓存 SQLite 的第 N 日数据 + 腾讯财经 API 兜底（最不完整，仅 OHLC）

**设计原则**：收盘复盘 cron 调用 Qing-Agent 分析后，由 `stock_monitor.py` 从复盘输出和行情快照中自动提取并写入 summary 文件。次日的 poll / agent cron 直接读取 summary，不再重新采集。若 summary 不存在（如复盘 cron 失败），fallback 到 state.json + API。

**字段清单**（18 个，分 4 类）：

#### A. 基础行情（7 项，所有来源都可提供）

| 字段 | 键名 | 示例 | 来源 |

| 昨收 | `close` | 134.81 | 所有来源 |
| 今开 | `open` | 126.22 | 所有来源 |
| 最高 | `high` | 134.81 | 所有来源 |
| 最低 | `low` | 124.00 | 所有来源 |
| 涨跌幅 | `change_pct` | 10.00 | 所有来源 |
| 成交量 | `volume` | 576461 | 所有来源 |
| 成交额 | `amount` | 75.05亿 | state.json + API |

#### B. 板/封板特征（4 项，仅 summary 可完整提供）

| 字段 | 键名 | 示例 | 含义 |

| 是否涨停 | `is_limit_up` | true | 收盘是否为涨停 |
| 连续涨停天数 | `consecutive_limit_ups` | 2 | 含今天的累计连续板数 |
| 烂板标记 | `weak_board` | true | 盘中是否开板后回封 |
| 开板次数 | `board_open_count` | 3 | 当天开板次数 |

#### D. 分时形态/资金面（5 项，仅 summary 可提供）

| 字段 | 键名 | 示例 | 含义 |
|------|------|------|------|

| 龙虎榜净买入 | `dragon_tiger_net` | "+1.2亿" | 龙虎榜买入-卖出 |
| 距介入区间 | `entry_zone_distance` | "above" | above/in/below |
| 介入区间 | `entry_zone_range` | "118-122" | 配置的 entry_zone 区间 |

### 1.2 竞价快照 (_auction_snapshot)

**采集时间**：09:25:05（集合竞价结果生成的瞬间）
**数据源**：腾讯财经 API (竞价阶段可用) 或 东方财富 竞价 API

| 字段 | 键名 | 示例 | 含义 |
|------|------|------|------|
| 竞价价格 | `auction_price` | 130.50 | 集合竞价撮合价格 |
| 竞价涨跌幅 | `auction_change_pct` | -3.2 | 相较昨收的涨跌% |
| 竞价成交量 | `auction_volume` | 21000 | 竞价阶段成交量(手) |
| 竞价量占比 | `auction_volume_ratio` | 0.35 | 竞价量/近5日竞价量均值 |
| 竞价末5分钟趋势 | `last5min_trend` | "pull_up" | last 5 min 价格方向(pull_up/stabilize/push_down) |
| 竞价买卖盘差 | `auction_order_delta` | "+300万" | 买盘-卖盘金额差 |

### 1.3 数据流

```
15:20 收盘复盘 cron (LLM)
    │  输出：复盘分析文本 + 结构化复盘数据
    ▼
stock_monitor._build_yesterday_summary()
    │  从 state.json 的 last_quote_snapshot 提取基础行情
    │  从 daily_state.json 提取市场阶段、方向判断
    │  从策略包提取 entry_zone 状态
    ▼
config/stock_monitor/daily_review_summary.json  ← 持久化

次日 06:30: K线预拉取 cron
    │  补充 MA5/MA10 等均线计算
    ▼
次日 09:26 竞价记录 cron
    │  读取 summary + 拉竞价数据
    ▼
JSON 上下文 → LLM 分析
```

## 2. Prompt 差异化

### 2.1 篇幅分配

**之前**（总计 ~450 字）：

```
盘面/大盘: ~100字 (22%)
持仓池: ~200字 (44%)
观察池: ~100字 (22%)
脚注: ~50字 (11%)
```

**改成**（总计 ~600 字）：

```
【盘面】: ~50字 (8%)   ← 大幅精简
【重点分析】: ~300字 (50%) ← 新增，个股深度
【其他持仓】: ~60字 (10%)  ← 精简
【观察池】: ~40字 (7%)    ← 精简
【脚注】: ~50字 (8%)
缓冲：~100字 (17%)
```

### 2.2 各时间节点 Prompt 特异化

#### 09:26 竞价后（竞价数据）

```
【角色】你现在看到的是集合竞价数据（09:25 撮合结果）。
前15分钟的量能和价格运动尚未出现。

【Focus】
- 竞价价格相对于昨收的位置（高开/低开）
- 竞价成交量是否异常放大
- 竞价最后5分钟的价格方向（拉升/稳定/打压）
- 持仓股中哪些竞价异常最突出

【输出】
📊 大盘竞价定性（15字）
📊 持仓重点分析（1-2只竞价最异常的标的，每只60-80字，
   说清竞价特征 + 开盘后验证条件）
📋 观察池信号（15字）

【禁止】不要给"持有/减仓"结论，此刻还没开始交易。
```

#### 09:45 开盘15分钟（竞价+前15分钟验证）

```
【角色】你现在看到的是竞价+开盘前15分钟数据。
可以用前面定好的框架：竞价特征 + 前15分钟是否验证。

【框架】（重点个股自动套用）
| 竞价+前15分钟 | 含义 |
|--------------|------|
| 小幅低开(-1~-3%)+15分钟缩量企稳 | 正常获利了结 |
| 大幅低开(<-5%)+15分钟无承接 | 恐慌出逃 |
| 平开/高开+15分钟放量上攻 | 换手接力 |
| 竞价跌停拉回+15分钟翻红 | 资金抢筹 |

【Focus】
- 昨日特征（连续涨停/烂板/换手率/振幅）决定今日分析框架
- 竞价特征 + 15分钟量能变化构成分析输入
- 同板块标的（confirm_with）并列验证

【输出】
📊 大盘定性（20字）
📊 持仓重点分析（1-2只昨日特征最突出+今日竞价最异常的标的，每只80-100字）
📊 其他持仓（每只15字）← 动作+触发+证伪
📋 观察池（10字，有触发写条件，没有写空）
```

#### 10:30 30分钟确认（早盘方向确认）

```
【角色】30分钟数据。前15分钟的短暂波动已被消化，
现在可以判断今日主基调。

【Focus】
- 前15分钟的方向是否被30分钟数据验证？
- 出现了哪些关键信号？哪些在走弱？
- 有没有标的出现方向性变化？

【输出】
📊 早盘定性（30字）← 比09:45长一些，可以判断基调了
📊 个股分析（1-2只关键票，70-100字）
📊 其他持仓（每只15字）
📋 观察池（如果出现了新的介入范围内的，可以多说一点，最多60字）
```

#### 14:00 午盘（午后验证）

```
【角色】午后数据。验证上午方向是否延续。

【Focus】
- 下午是否拉回还是加速？
- 有没有出现"上午假象、下午反转"的情况？
- 持仓票是否触发风控条件？

【输出】
📊 午后判断（20字）
📊 个股分析（1-2只关键票，70-80字）
📊 持仓风控（仅触发风控的票，每只20字）
```

#### 14:52 尾盘（收盘决策）

```
【角色】尾盘数据。决定持仓过夜策略。

【Focus】
- 今日是否出现了条件单触发信号？
- 烂板票是否该减仓？
- 哪些票适合持有过夜？

【输出】
📊 今日总结（20字）
📊 个股回顾（每只持仓30-40字，回顾今日表现+明日展望）
📊 尾盘操作建议（如有触发条件）
```

## 4. 风险

| 风险 | 对策 |
|------|------|
| summary 文件被复盘 cron 遗漏 | Phase 1.2 fallback 机制，从 state.json 摘要 |
| 竞价 API 不稳定 | 用腾讯财经 API 缓存 + 重试，失败时输出"竞价数据未获取" |
| 每个时间节点分析太详细导致 token 成本超标 | 观察几天 token 用量，必要时减少"其他持仓"到每只10字 |
| LLM 给出过于确定性的建议 | 所有分析必须附带条件（如"若X则Y"，"在Y成立前不做操作"） |
