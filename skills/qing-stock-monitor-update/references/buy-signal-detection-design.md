## 快速导航

### 为什么需要这个设计

用户需求：「大模型替我盯盘，观察池里的票缩量企稳了，告诉我今天这个点位可以买入了。」

当前系统断层：
```
cron 定时 → Agent 全量分析 → "等缩量企稳" → 用户自己盯
```

目标：
```
cron 轮询 → poll 检测条件 → Agent 单票确认 → "买，现价X，止损Y"
```

### 核心架构：两级决策

```
poll 脚本(5分钟, no-agent)
  → 规则检测（价格区间 + 缩量止跌 + 放量阳线 + 均线支撑 + 不追板）
  → 命中 → Agent 单票确认
  → 输出二值化：🟢买入 / 🔴不买
```

### 四个检测条件

| 条件 | 算法 | 来源 |
|------|------|------|
| 价格在介入区间 | 当前价 ∈ [zone_low, zone_high] | 已有 |
| 缩量止跌 | 近3日量递减 + 最低价不创新低 | 新增 |
| 放量阳线确认 | 当日量 > 5日均量×1.5 + 阳线 | 新增 |
| 均线支撑 | 收盘 > MA20 + MA5上穿MA10 | 新增 |
| 不追板 | 涨幅 < 7% | 新增（核心纪律） |

### 实施阶段

| Phase | 内容 | 时间 |
|-------|------|------|
| 1 | Agent 输出改二值化 + 标签修正 | 1-2h |
| 2 | poll 增加买入信号检测引擎 | 3-4h |
| 3 | poll → Agent 单票分析链路 | 2-3h |
| 4 | 全自动闭环 | 2-3h |

### 相关陷阱

- 陷阱 14：条件驱动轮询未部署
- 陷阱 24："可买"标签误导 + Agent 永远在等
