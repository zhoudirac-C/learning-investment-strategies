# 持仓方向与 UP 近期内容核对手册

## 触发条件

用户说以下任意表述时触发本流程：
- "核对我的持仓方向，UP 是否提到"
- "UP 最近有没有提到我的持仓"
- "我的持仓方向 UP 怎么看"
- "看看 UP 最近有没有说我持仓的方向"
- 任何包含"持仓"+"UP/博主"+"提到/说/怎么看"的表述

## 与"持仓更新"子任务的区别

| 维度 | 持仓更新（Position Update） | 持仓方向核对（Direction Alignment） |
|------|---------------------------|-----------------------------------|
| 核心目标 | 盈亏计算 + 技术面分析 + Claims 关联 | UP 近期是否提及 + UP 态度是什么 |
| 数据重点 | 实时行情、K线、成本线 | UP 近期内容（视频/动态/复盘/早盘） |
| 输出重点 | 操作建议（持有/减仓/止损） | 方向一致性评估（✅一致/⚠️需确认/❌无观点） |
| 触发词 | "更新持仓""分析持仓" | "UP 是否提到""核对方向" |

## 执行流程

### Step 1：读取用户持仓

读取 `config/stock_monitor/positions.yaml`，提取所有 `shares > 0` 的标的，按方向分组：
- 燃气轮机：万泽股份、杰瑞股份
- 昇腾链：航天电器、意华股份
- 超级电容：艾华集团、江海股份
- ...

### Step 2：扫描 UP 近期内容

扫描 `sources/raw/财经/` 中最近 **2-3 天**的所有 UP 内容：
- 视频（`视频：26-XX-XX：`）
- 复盘专栏（`复盘：26-XX-XX：`）
- 早盘（`早盘：26-XX-XX：`）
- 动态（`动态：26-XX-XX：`）

**⚠️ 必须检查所有文件类型**，不能只读复盘或只读视频。UP 对同一方向的态度可能在不同媒介中不一致。

**⚠️ 用户指定时间窗口时必须严格遵守**：当用户明确说"只看 X 月 X 日的""不要看后面的""只看 6-4 的"时，**必须严格限制扫描范围到用户指定的日期**，不得自动扩展读取后续日期的内容。后续日期的内容（即使存在）与用户当前分析无关，引入会导致方向判断矛盾（如 6-4 看多 vs 6-5 看空）。
- 反面案例：用户说"只看 6-4 的"，但 agent 同时读了 6-5 早盘（"AI上游材料最确定"）和 6-4 视频（"燃气轮机类比锂电池"），导致两个方向都被评为高优先级，掩盖了 6-4 当天燃气轮机的真实最高优先级。
- 正确做法：扫描 `sources/raw/财经/` 时，用 `grep -E "26-06-04"` 或 `ls | grep "26-06-04"` 严格过滤，只读取文件名匹配用户指定日期的文件。对未指定日期的文件，即使更新、即使内容相关，也**不读取**。
- 若用户指定的日期在 repo 中无内容，如实告知"本地无 X 月 X 日内容"，不自动用其他日期替代。

### Step 3：逐只提取 UP 提及情况

对每只持仓标的，在 UP 近期内容中搜索：
```bash
grep -rn "标的名称\|股票代码" sources/raw/财经/ --include="*.md" | grep -E "26-XX-(XX|XX|XX)"
```

记录：
- 是否被提及（✅/❌）
- 提及来源（视频/复盘/早盘/动态）
- UP 原话（直接引用）
- 语言强度（见下方评级标准）

### Step 4：语言强度评级

按 UP 对方向的定调语言，给每个方向评级：

| 评级 | 语言特征 | 示例 |
|------|---------|------|
| 🔥🔥🔥 最高 | "类比锂电池""可以格局""确定性很高""机构都要买""最看好" | "类比上一轮牛市的锂电池，可以格局" |
| 🔥🔥 高 | "最确定方向""重心放""核心标的""明确看好" | "AI上游材料端最确定" |
| 🔥 中 | "赔率升高""逢低关注""慢慢看""不着急" | "接近估值底部，赔率升高" |
| ⚠️ 低/规避 | "短期告一段落""差不多了""回调""不追" | "短期涨太多要回调" |
| ❌ 未提及 | 无 | — |

**交叉比较规则**：若多个 source 对同一方向评级不一致，取语言强度最高的作为该方向的真实定级。

### Step 5：输出核对结果

按以下结构输出：

```
## 持仓方向 vs UP 近期内容核对

### 你的持仓
| 方向 | 标的 | 持仓 |

### UP 近期提及情况
| 你的标的 | UP 是否提到 | 来源 | UP 原话/态度 | 语言强度 |

### 核心结论
1. [方向]：UP [明确看好/中性观察/未提及/短期规避]，原话"..."
2. ...

### 风险点
| 风险 | 说明 |

### 一句话总结
> [方向一致性总体评估，如"方向与 UP 高度一致，但短期节奏需警惕"]
```

## 常见陷阱

1. **只读一种媒介**：只读复盘不看视频，可能漏掉 UP 对某方向的详细分析（视频通常比复盘更详细）。
2. **忽略评论回复**：UP 在动态下的评论回复可能包含与主动态相反的关键条件（如"4033清仓科技"）。
3. **混淆方向与个股**：UP 可能看好"燃气轮机"方向但未点名"万泽股份"，需区分方向认可和个股确认。
4. **忽略时间差**：repo 中最新内容可能滞后于实际 UP 发布（监控管道延迟），需检查文件修改时间。
5. **过度解读未提及**：UP 未提及某标的 ≠ 不看好，可能只是近期没有新观点。
6. **用户指定时间窗口时必须严格遵守**：当用户明确说"只看 X 月 X 日的""不要看后面的""只看 6-4 的"时，**必须严格限制扫描范围到用户指定的日期**，不得自动扩展读取后续日期的内容。后续日期的内容（即使存在）与用户当前分析无关，引入会导致方向判断矛盾（如 6-4 看多 vs 6-5 看空）。
   - 反面案例：用户说"只看 6-4 的"，但 agent 同时读了 6-5 早盘（"AI上游材料最确定"）和 6-4 视频（"燃气轮机类比锂电池"），导致两个方向都被评为高优先级，掩盖了 6-4 当天燃气轮机的真实最高优先级。
   - 正确做法：扫描 `sources/raw/财经/` 时，用 `grep -E "26-06-04"` 或 `ls | grep "26-06-04"` 严格过滤，只读取文件名匹配用户指定日期的文件。对未指定日期的文件，即使更新、即使内容相关，也**不读取**。
   - 若用户指定的日期在 repo 中无内容，如实告知"本地无 X 月 X 日内容"，不自动用其他日期替代。

## 数据完整性检查

执行核对前，先检查 repo 中是否有足够新的内容：
```bash
ls -lt sources/raw/财经/ | head -10
```

若最新文件日期距今天超过 2 天，提示用户：
> "本地最新 UP 内容为 X 月 X 日，可能遗漏近期更新。建议先运行 bilibili 监控同步。"

## 与 claims 的衔接

核对完成后，若用户需要进一步分析，可衔接至：
- **持仓更新**：加入盈亏计算和技术面分析
- **观察池更新**：若 UP 提到了用户未持仓的新方向
- **claims 关联**：在 `knowledge/claims/` 中搜索该方向的长期 claims
